# SDBL-грамматика tree-sitter-hbk: четыре пробела в разборе реальных запросов

**Статус:** закрыто (2026-07-23). Два коммита в ветке `dev` форка
`~/mcp/tree-sitter-bsl` (origin: uasy/tree-sitter-bsl) — `2f6ffc1`
(разыменование после `ВЫРАЗИТЬ`) и `62bea42` (кортеж в `В`, `УНИЧТОЖИТЬ` в
пакете, вложенные соединения). PR в апстрим (mussolene/tree-sitter-bsl,
текст ниже) отправлен. До приёма PR фикс потребляется через локально
пересобранный wheel (см. «Локальная сборка и замер» ниже) — актуально,
пока PR не смёржен или пока зависимость проекта не переключена на форк с
фиксом.

**Происхождение:** найдено при реализации резолвера полей текстов запросов
(`docs/contributors/onec-hbk-bsl-query-field-resolver-proposal.md`) —
дамп реальных SDBL-деревьев на синтетике вскрыл ERROR-узел; масштаб на
реальной конфигурации (ЗУП 3.1.37.54) и остальные три пробела нашлись при
последующем акцептанс-прогоне.

## Проблемы

Все четыре — валидный для платформы 1С синтаксис, который штатная
грамматика (`tree-sitter-hbk` 0.1.10, `sdbl_language()`) не разбирала:

1. **Обращение к полю результата `ВЫРАЗИТЬ`:**

   ```
   ВЫБРАТЬ
       ВЫРАЗИТЬ(Т.Поле КАК Справочник.Организации).ГоловнаяОрганизация
   ИЗ ...
   ```

   `.` после закрывающей скобки `cast_expression` давал `ERROR`-узел, хвост
   цепочки ошибочно принимался за `field_alias`.

2. **Кортеж слева от `В`:** `(Организация, ФизЛицо) В (ВЫБРАТЬ ...)` —
   `membership_expression` принимала только одиночное выражение слева, в
   т.ч. внутри параметров виртуальных таблиц.

3. **`УНИЧТОЖИТЬ` внутри пакета запросов:** `ВЫБРАТЬ ... ; УНИЧТОЖИТЬ ВТ` —
   `query_package` допускал между `;` только `query`.

4. **Вложенные соединения с отложенными `ПО`:**
   `А ЛЕВОЕ СОЕДИНЕНИЕ Б ЛЕВОЕ СОЕДИНЕНИЕ В ПО у1 ПО у2` — соединение,
   правый операнд которого сам с соединением, а условия `ПО` идут в конце.

## Масштаб

Замер на реальной конфигурации (ЗУП 3.1.37.54, один реквизит
`ГоловнаяОрганизация` как маркер): 1353 из 3749 вхождений токена в текстах
запросов (36%) находились в блоках с ошибками SDBL-парсинга. Паттерн
`ВЫРАЗИТЬ(...).Поле` — самый частый источник (`ВЫРАЗИТЬ(X КАК
ПланВидовРасчета.Начисления).Реквизит` и подобные — типовой код БСП), но
не единственный: минимизация остатка после первого фикса вскрыла ещё три
причины. Пробел блокирует не только резолвер полей запросов, но и любые
диагностики, работающие по SDBL-дереву (`sdbl_has_errors`).

## Реализация

Все четыре — аддитивные изменения формы дерева (существующие узлы не
меняются, старые деревья не ломаются):

- `cast_field_access`: `cast_expression` + `repeat1('.' field: identifier)`
  в `query_expression` — поддерживает цепочки (`ВЫРАЗИТЬ(...).Поле.Поле2`).
- `expression_tuple` (от 2 элементов) как альтернатива `query_expression`
  слева у `membership_expression`; одноэлементная скобка остаётся
  `parenthesized_expression`, конфликта нет.
- `query_package`: элемент теперь `query | destroy_statement`.
- `join_clause`: допускает вложенный `join_clause` перед своим
  `ON_KEYWORD`; условия связываются изнутри наружу, плоские цепочки
  сохраняют прежнюю форму.

Corpus форка: SDBL 52/52 (+6 кейсов), BSL 63/63; артефакты
`grammars/sdbl/src` перегенерированы; записи в
`spec/archive/IMPLEMENTATION_ARCHIVE.md`.

Акцептанс-прогон (139 подготовленных падавших блоков ЗУП): полностью
чистых блоков 16 → **111 (80%)**; ERROR/MISSING-узлы 1002 → 245. Остаток —
в основном подстановки-шаблоны `#Имя` (динамические тексты, осознанно вне
грамматики), плюс не разобранная по отдельности мелочь.

### Сторона onec-hbk-bsl: резолвер запросов

Параллельно в `analysis/query_field_resolver.py` (проект onec-hbk-bsl)
добавлены механизмы, не зависящие от грамматики, и один — прямо на неё
опирающийся:

- `prepare_query_text` — разэкранирование `""` (артефакт выгрузки текста
  запроса из BSL-строкового литерала) и вычистка секций построителя
  `{...}` пробелами (секции не влияют на идентичность метаданных;
  скобки в строковых литералах и геометрия строк сохраняются).
- `resolve_query_text_uses` — сплит-fallback для частично неразбираемых
  текстов: пакет режется по `;` верхнего уровня, нераспарсившиеся части
  дополнительно по `ОБЪЕДИНИТЬ [ВСЕ]`; типы временных таблиц протягиваются
  между разобранными частями в порядке документа.
- Разбор `cast_field_access` — узел, добавленный этим фиксом, теперь
  читается резолвером: базовая идентичность берётся из `cast_type`,
  дальше обычный дереференс по цепочке (с `ambiguous`/протяжкой в поля
  ВТ). До этой правки грамматика уже парсила `ВЫРАЗИТЬ(...).Поле`, но
  резолвер узел игнорировал.

Это сделало эффект грамматических фиксов измеримым отдельно от fallback:
fallback уже вытягивал резолвящиеся части падавших блоков через границы
`;`/`ОБЪЕДИНИТЬ`, грамматика добавляет то, что fallback принципиально не
может достать — конструкции внутри одной неразрывной части пакета.

## Локальная сборка и замер (2026-07-23)

До приёма PR фикс собран и установлен локально, заменяя штатный
`tree-sitter-hbk` 0.1.10 в текущем окружении.

Как собрано: `pip wheel .` в форке даёт `tree_sitter_bsl-0.1.7-*.whl`
(родное имя пакета форка — `tree-sitter-bsl`, а не `tree-sitter-hbk`, хотя
ABI и экспортируемые функции идентичны — `tree-sitter-hbk` издаётся из
того же кода под другим именем). Колесо распаковано, каталог пакета и
`*.dist-info` переименованы `tree_sitter_bsl` → `tree_sitter_hbk` (тот же
скомпилированный `_binding.abi3.so`, без пересборки C), запаковано обратно
и установлено (`pip install --user --break-system-packages
--force-reinstall --no-deps`) поверх системного пакета. Откат —
`pip install --user --break-system-packages --force-reinstall
tree-sitter-hbk==0.1.10`. Это временная мера для локальной разработки, не
способ распространения.

Проверка: полный набор тестов onec-hbk-bsl — 1580 passed (без учёта
сбоев окружения, не связанных с грамматикой).

## Вне рамок

- `#Имя`-подстановки (шаблонные динамические тексты запросов) — осознанно
  вне грамматики.
- Остаток из ~28 acceptance-блоков помимо `#Имя` не разобран по
  отдельности — не проверено, есть ли там ещё системные причины.
