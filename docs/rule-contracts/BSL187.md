# BSL187 Contract

## Rule Identity

- Code: BSL187
- BSLLS compatible name: FieldsFromJoinsWithoutIsNull
- Public name/i18n key: BSL187 / FieldsFromJoinsWithoutIsNull
- Default message/i18n key: RULE_MESSAGES_RU["BSL187"]
- Description/i18n key: RULE_METADATA["BSL187"].description
- Severity: ERROR
- Parameters/defaults: no user parameters
- Rule status: contracted

## Standard And Product Decision

- Standard or product policy: fields from nullable sides of outer joins must be protected by `ЕСТЬNULL()`/`ISNULL()` or by an explicit `ЕСТЬ НЕ NULL` / `IS NOT NULL` filter when the query intentionally eliminates NULL rows.
- Why this diagnostic exists: values from left, right, and full joins may be `NULL`; using them directly in selected fields, predicates, or other join conditions can produce unexpected results.
- Non-goals: proving metadata nullability, rewriting joins, reporting inner joins, or diagnosing syntactically broken SDBL fragments.
- Keep/drop decision: keep, with BSLLS-compatible outer-join semantics.

## Semantic Oracle

- Checked language fact: an alias from the nullable side of an outer join is used without local NULL protection.
- Must diagnose when: a left-join joined alias, right-join base alias, or either side of a full join is referenced in selected fields, WHERE conditions, or another join condition without `ЕСТЬNULL()`/`ISNULL()` or an effective not-null predicate.
- Must not diagnose when: the field is inside `ЕСТЬNULL()`/`ISNULL()`, the nullable alias is globally filtered by `ЕСТЬ НЕ NULL` / `IS NOT NULL` in WHERE, the join is inner-only, or no reliable outer-join facts can be extracted from the SDBL CST.
- Diagnostic anchor token/range: BSLLS anchors the primary diagnostic on the `joinPart` / SDBL `join_clause`; related information points at unsafe field uses.
- Quick-fix target, if any: wrap the field with `ЕСТЬNULL()` or replace the outer join with an inner join when the not-null filter is intentional.

## CST Or Domain Fact Model

- Parser/tree source: `DocumentSnapshot.query_text_blocks` with tree-sitter SDBL CST.
- CST/domain object types: `select_section`, `join_clause`, nullable join aliases, `field_list`, `where_clause`, `dotted_identifier`, `null_check_expression`.
- Extracted attributes: join kind, nullable alias, unsafe dotted identifier, join clause range, containing select-section identity.
- Parse-error behavior: do not fail the whole query block solely because `sdbl_has_errors` is true; report only if tree-sitter still exposes complete nullable `join_clause` facts. Broken fragments with no reliable join facts stay silent.
- Textual/regex behavior, only if genuinely textual: none for valid SDBL paths.

## Examples

### Invalid Examples

1. `ЛЕВОЕ СОЕДИНЕНИЕ ... КАК Левое` and selected field `Левое.Поле`.
2. `ПРАВОЕ СОЕДИНЕНИЕ ...` and selected field from the base alias.
3. `ПОЛНОЕ СОЕДИНЕНИЕ ...` and selected fields from either side.

### Valid Negative Twins

1. `ЕСТЬNULL(Левое.Поле, 0)` in selected fields.
2. `ГДЕ Левое.Ссылка ЕСТЬ НЕ NULL` before using `Левое` fields.
3. `ВНУТРЕННЕЕ СОЕДИНЕНИЕ` with direct field access.

### Edge Examples

- Comments: comments inside query text do not affect alias facts.
- Strings: only recognized query text blocks are parsed as SDBL.
- Preprocessor: BSL preprocessor does not affect SDBL facts after query extraction.
- Multiline: embedded query string lines map through `QueryTextBlockInfo.original_lsp_position`.
- Nested constructs: nested select sections are separate nullable-alias scopes.
- BSL/SDBL variants, if relevant: SDBL CST is required; invalid SDBL is skipped.

## Implementation Decision

- Change target: `sdbl_cst.NullableJoinFieldUse`, nullable join fact extraction, and `query_metadata_rules._run_bsl187_on_sdbl_tree`.
- Delta category fixed by this change: main-anchor mismatch, missed unsafe join-condition facts, `not_operator` null-check handling, and over-strict parse-error block skipping.
- Why not another layer: SDBL nullable alias and join range are structural query facts, not raw-text facts.
- Rollback signal: protected fields start reporting, invalid SDBL reports BSL187, or BSL187 no longer emits one issue per unsafe outer join.
