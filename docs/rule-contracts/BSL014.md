# BSL014 Contract

## Rule Identity

- Code: BSL014
- BSLLS compatible name: LineLength
- Public name/i18n key: BSL014 / LineLength
- Default message/i18n key: get_rule("BSL014").message
- Description/i18n key: RULE_METADATA["BSL014"].description
- Severity: INFORMATION
- Parameters/defaults: max_line_length
- Rule status: contracted

## Standard And Product Decision

- Standard or product policy: Source lines should stay within the configured readable line length.
- Why this diagnostic exists: It improves readability and review ergonomics.
- Non-goals: Lines at or below the configured limit and embedded query content lines.
- Keep/drop decision: keep

## Semantic Oracle

- Checked language fact: A readable physical source row exceeds `max_line_length`
  after excluding trailing spaces and tabs.
- Must diagnose when: The significant row end is greater than the configured threshold.
- Must not diagnose when: The significant row end is at or below the threshold or the row is embedded query content.
- Diagnostic anchor token/range: the full overlong row range from column 0 to significant row end.
- Quick-fix target, if any: manual line wrap.

## CST Or Domain Fact Model

- Parser/tree source: `DocumentSnapshot.line_too_long_facts`.
- CST/domain object types: source line, significant row end, embedded query content row.
- Extracted attributes: line index, significant row end, query-content membership, configured maximum.
- Parse-error behavior: line-length rule can run without valid CST.
- Textual/regex behavior, only if genuinely textual: this is a textual formatting rule.

## Examples

### Invalid Examples

1. A BSL assignment line longer than `max_line_length`.
2. A method call line longer than `max_line_length`.
3. A comment or code line that is not covered by a multiline string/query exception and exceeds the limit.
4. A long single-line string literal source line.
5. A long ordinary multiline string continuation row starting with `|`.

### Valid Negative Twins

1. A line exactly at `max_line_length`.
2. A line shorter than `max_line_length`.
3. A query text line starting with `|`.
4. A line whose only excess characters are trailing spaces or tabs.

### Edge Examples

- Comments: comments are checked unless excluded by a specific exception.
- Strings: long string lines are measured as visible source lines.
- Preprocessor: checked as text.
- Multiline: each physical row is checked independently; ordinary multiline string
  continuation rows are still readable BSL source rows.
- Nested constructs: not relevant.
- BSL/SDBL variants, if relevant: embedded query content rows are excluded from
  BSL014 and left to query/formatting rules.

- Coordinate normalization: one-based diagnostic lines and zero-based LSP characters.

- Known BSLLS defects: BSLLS `LineLength` does not distinguish query content

  whitespace in some comment ranges.
- Unknown categories: none

## Performance Contract

- Traversal/fact source: cached `line_too_long_facts(max_line_length)`.
- Expected complexity: O(lines), plus cached query-content detection only when
  query rows exist.
- Shared-pass reuse: uses cached significant row lengths and cached query line indices.
- Before/after measurement, if changed: local external corpus onec CLI BSL014
  went from 77.24s / 13043 diagnostics to 72.76s / 13338 diagnostics; direct
  fact extraction produced 13680 facts in 6.33s before suppression/filtering.

## Implementation Decision

- Change target: `DocumentSnapshot.reported_line_lengths`,
  `DocumentSnapshot.line_too_long_facts`, BSL014 contract, and synthetic coverage.
- Delta category fixed by this change: semantic-mismatch / BSLLS-only ordinary
  multiline string continuation rows hidden by the previous `skip all |` policy.
- Why not another layer: BSL014 is a textual readability rule; CST token-end
  compatibility would copy BSLLS whitespace/query defects without improving the
  user-facing diagnostic.
- Rollback signal: configured threshold is ignored, ordinary multiline string
  continuation rows do not report, embedded query rows report as BSL014, or
  contract validation fails.
