# BSL276 WrongUseFunctionProceedWithCall Contract

## Rule Identity

- Code: BSL276

- Severity: ERROR
- Parameters/defaults: none.
- Rule status: parity-classified

## Standard And Product Decision

- Standard or product policy: `ПродолжитьВызов()` / `ProceedWithCall()` is valid only in extension methods with `&Вместо` / `&Instead` / `&Around`.
- Why this diagnostic exists: using the function elsewhere is a runtime/extension contract error.
- Non-goals: methods with the required annotation, unrelated calls, comments, strings.
- Keep/drop decision: keep as a BSLLS-compatible extension correctness diagnostic.

## Semantic Oracle

- Checked language fact: a global method call to `ПродолжитьВызов` / `ProceedWithCall` appears in a method that lacks the required around annotation.
- Must diagnose when: call exists inside a procedure/function without the annotation.
- Must not diagnose when: containing method has `&Вместо`, `&Instead`, or `&Around`.
- Diagnostic anchor token/range: full call expression.
- Quick-fix target, if any: move the call into an annotated extension method or remove it.

## CST Or Domain Fact Model

- Parser/tree source: tree-sitter BSL CST runtime call context plus procedure model.
- CST/domain object types: `method_call`, procedure/function declarations, annotation lines.
- Extracted attributes: call name/range, containing procedure span, annotation presence.
- Parse-error behavior: no CST/call facts means no BSL276 diagnostic.
- Textual/regex behavior, only if genuinely textual: annotation check is bounded to lines above procedure start.

## Examples

### Invalid Examples

1. `ПродолжитьВызов();` in an ordinary procedure.
2. `ProceedWithCall();` without annotation.
3. `Если Условие Тогда ПродолжитьВызов(); КонецЕсли;` without annotation.

### Valid Negative Twins

1. Method annotated `&Вместо` calls `ПродолжитьВызов()`.
2. Method annotated `&Instead` calls `ProceedWithCall()`.
3. `"ПродолжитьВызов()"` inside a string.

### Edge Examples

- Comments: ignored by CST.
- Strings: ignored by CST.
- Preprocessor: no separate semantic target.
- Multiline: call range comes from runtime call facts.
- Nested constructs: nested calls are checked by containing method span.
- BSL/SDBL variants, if relevant: SDBL is not relevant.
