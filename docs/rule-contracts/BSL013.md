# BSL013 Contract

## Rule Identity

- Code: BSL013
- BSLLS compatible name: CommentedCode
- Public name/i18n key: BSL013 / CommentedCode
- Default message/i18n key: get_rule("BSL013").message
- Description/i18n key: RULE_METADATA["BSL013"].description
- Severity: WARNING
- Parameters/defaults: none
- Rule status: contracted

## Standard And Product Decision

- Standard or product policy: Dead code should be deleted instead of kept as commented source.
- Why this diagnostic exists: It prevents stale code fragments from hiding real behavior and misleading maintainers.
- Non-goals: Normal prose comments, examples explicitly marked as examples, and query comments that are not BSL code.
- Keep/drop decision: keep

## Semantic Oracle

- Checked language fact: A full-line comment group contains disabled BSL/query source text.
- Must diagnose when: CST `line_comment` nodes form a full-line comment group that, after removing leading `//`, parses as BSL with no `BSL001` parse errors and no CST error root. Adjacent commented annotations/directives are included when the uncommented group parses as code.
- Must not diagnose when: The comment is prose, marked as an example, a markdown-style heading, an incomplete expression fragment, or only mentions BSL words but the uncommented text does not parse as BSL.
- Diagnostic anchor token/range: the full-line comment group range.
- Quick-fix target, if any: delete the commented code manually.

## CST Or Domain Fact Model

- Parser/tree source: `DocumentSnapshot.commented_code_facts`.
- CST/domain object types: `line_comment` CST nodes, grouped adjacent full-line comments, and BSL parse result of uncommented comment text.
- Extracted attributes: group start/end node ranges, uncommented text, example marker state, query-continuation state, and whether the uncommented group parses without `BSL001`.
- Parse-error behavior: comment groups are considered commented code only when their uncommented text parses without `BSL001` and without CST root errors.
- Textual/regex behavior, only if genuinely textual: regex is retained only for non-tree-sitter fallback snapshots and query-continuation legacy behavior; tree-sitter snapshots use CST comment nodes plus BSL parse success as the primary source.

## Examples

### Invalid Examples

1. A block of `// Если ... Тогда` code lines.
2. A comment group containing a method call with BSL syntax.
3. A full-line comment group containing a complete disabled BSL statement.
4. A commented BSL annotation adjacent to a commented method body.
5. A commented BSL preprocessor block.

### Valid Negative Twins

1. A prose comment explaining business behavior.
2. A comment explicitly marked as an example.
3. A comment that mentions keywords without executable structure.
4. A markdown-style heading such as `// # Heading`.
5. A prose comment containing an embedded expression-like phrase that does not parse as a BSL statement/group.
6. A single commented expression continuation that cannot parse without surrounding live code.
7. Inline trailing comments after live code.

### Edge Examples

- Comments: comments are the target.
- Strings: string contents inside active code are not comment groups.
- Preprocessor: commented BSL preprocessor directives are code-shaped fragments; markdown-style headings are not.
- Multiline: adjacent comment lines are grouped.
- Nested constructs: code-like nested comment groups are reported as one group.
- BSL/SDBL variants, if relevant: query-looking comment lines can be classified as commented code.

## Performance Contract

- Traversal/fact source: cached `line_comment` CST node grouping in `commented_code_facts`, with line fallback only when tree-sitter is unavailable.
- Expected complexity: O(comment nodes) plus one small BSL parse per adjacent full-line comment group and per inline candidate.
- Shared-pass reuse: none.
- Before/after measurement, if changed: private corpus `--select BSL013 --jobs 1` measured real 83.46s after CST parse-based alignment.

## Implementation Decision

- Change target: BSL013 comment source and fragment classifier: primary tree-sitter path now reads full-line `line_comment` groups and classifies uncommented groups by strict successful BSL parse, instead of broadening token regexes.
- Delta category fixed by this change: BSLLS-only/pre-existing directive and fragment categories are re-evaluated through CST comment nodes; exact batch counts are recorded after implementation.
- Why not another layer: the snapshot already owns the parsed CST and project parser, so BSL013 can reuse that fact layer without a separate tokenizer artifact.
- Rollback signal: prose comments with BSL-looking words report as BSL013, markdown-style prose headings such as `// # Heading` report as BSL013, or clear commented code fragments stop reporting.
