## Описание диагностики

Клиентские общие модули содержат клиентскую бизнес-логику (функциональность, определенную только для клиента)
 и имеют признаки:

* Клиент (управляемое приложение)
* Клиент (обычное приложение)

Исключение составляют случаи, когда клиентские процедуры и функции должны быть доступны только в режиме управляемого
приложения (только в режиме обычного приложения или только в режиме внешнего соединения).
В таких случаях, допустима иная комбинация двух этих признаков.

Клиентские общие модули именуются с постфиксом "Клиент" (англ. "Client" ). Кроме случая - когда стоит флаг Глобальный.

## Description

Client common modules contain client business logic (functionality specific to the client only) and have the following features:

* Client (Managed application)
* Client (Ordinary application)

In cases where client methods should be available only in managed application mode (or only in regular application mode or only in external connection mode), a different combination of these two features is allowed.

Client common modules are named with the "Client" postfix ( "Клиент" in Rus). Except when the Global flag is on.

## Examples

FilesClient, CommonClient, StandardSubsystemsClient

## Standard And Product Decision

- Standard or product policy: client common modules should be named so their client-side execution context is visible from the module name.
- Why this diagnostic exists: common-module availability is encoded in metadata; names without a client marker obscure where the module is intended to run.
- Non-goals: global client common modules covered by BSL166, client-server modules covered by BSL163, non-client modules, missing/unreadable XML, and other naming predicates.
- Keep/drop decision: keep as a BSLLS-compatible common-module naming diagnostic.

## Semantic Oracle

- Checked language fact: a non-global common module is client-only and its metadata name does not contain a client marker.
- Must diagnose when: sibling common-module XML exists, execution-context predicates classify the module as client, `Global` is false, and the module name does not contain `Клиент` or `Client`.
- Must not diagnose when: XML is missing/unreadable, the module is not client-only, the module is global, or the name already contains an accepted client marker.
- Diagnostic anchor token/range: the first non-empty/non-BOM line of the module file.
- Quick-fix target, if any: rename the common module to include an accepted client marker.
