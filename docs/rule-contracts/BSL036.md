# BSL036 Contract

## Rule Identity

- Code: BSL036
- BSLLS compatible name: IfConditionComplexity
- Public name/i18n key: BSL036 / IfConditionComplexity
- Default message/i18n key: get_rule("BSL036").message
- Description/i18n key: RULE_METADATA["BSL036"].description
- Severity: WARNING
- Parameters/defaults: max_bool_ops
- Rule status: contracted

## Standard And Product Decision

- Standard or product policy: Complex `Если` / `If` conditions should be extracted to named variables or methods.
- Why this diagnostic exists: It improves readability by flagging condition expressions with too many boolean operands.
- Non-goals: Conditions at or below the configured boolean-operand threshold and boolean-looking text in comments/strings.
- Keep/drop decision: keep

## Semantic Oracle

- Checked language fact: An `Если` / `If` or `ИначеЕсли` / `ElsIf` condition has more boolean operands than `max_bool_ops`.
- Must diagnose when: The condition expression before `Тогда` / `Then` exceeds the configured boolean operand limit.
- Must not diagnose when: The condition is at or below the threshold or the tokens are only comments/strings.
- Diagnostic anchor token/range: the condition expression range after the condition keyword and before `Тогда` / `Then`.
- Quick-fix target, if any: extract condition to a variable or helper manually.

## CST Or Domain Fact Model

- Parser/tree source: `DocumentSnapshot.complex_condition_facts`.
- CST/domain object types: condition head line, multiline condition chunk, boolean operator tokens.
- Extracted attributes: start line, start character after keyword, end line, end character before `Тогда` / `Then`, boolean operator count.
- Parse-error behavior: textual condition chunk scan runs on source lines; `BSL001` owns syntax errors.
- Textual/regex behavior, only if genuinely textual: condition chunk detection is lexical because the rule measures readable expression text.

## Examples

### Invalid Examples

1. `Если` condition with more operands than `max_bool_ops`.
2. Multiline `Если` condition exceeding the threshold before `Тогда`.
3. `ИначеЕсли` condition exceeding the threshold.

### Valid Negative Twins

1. A simple condition below the threshold.
2. A condition exactly at the threshold.
3. Boolean words appearing only in comments or strings.

### Edge Examples

- Comments: ignored during condition measurement.
- Strings: masked during condition measurement.
- Preprocessor: not a separate target.

- Nested constructs: each condition head is measured separately.
