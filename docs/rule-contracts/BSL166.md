## Описание диагностики

Для глобальных модулей добавляется постфикс "Глобальный" (англ. "Global"),
в этом случае постфикс "Клиент" добавлять не следует.

## Примеры

НеПравильно:
РаботаСФайламиГлобальныйКлиент, InfobaseUpdateGlobalClient

Правильно:
РаботаСФайламиГлобальный, InfobaseUpdateGlobal

## Standard And Product Decision

- Standard or product policy: global client common modules should be named so their global client-side visibility is explicit.
- Why this diagnostic exists: global client modules combine broad visibility with client execution; names without a client marker hide an important context property.
- Non-goals: non-global client modules covered by BSL162, non-client global modules covered by BSL165, missing/unreadable XML, and other naming predicates.
- Keep/drop decision: keep as a BSLLS-compatible common-module naming diagnostic.

## Semantic Oracle

- Checked language fact: a common module is global and client-only, and its metadata name does not contain a client marker.
- Must diagnose when: sibling common-module XML exists, `Global` is true, execution-context predicates classify the module as client, and the module name does not contain `Клиент` or `Client`.
- Must not diagnose when: XML is missing/unreadable, the module is not global, the module is not client-only, or the name already contains an accepted client marker.
- Diagnostic anchor token/range: the first non-empty/non-BOM line of the module file.
- Quick-fix target, if any: rename the common module to include an accepted client marker.
