# BSL020 NestedStatements Contract

## Rule Identity

- Code: BSL020
- BSLLS compatible name: NestedStatements
- Public name/i18n key: BSL020 / NestedStatements
- Default message/i18n key: RULE_MESSAGES_RU["BSL020"]
- Description/i18n key: RULE_METADATA["BSL020"].description
- Severity: WARNING
- Parameters/defaults: `maxAllowedLevel` / `max-nesting-depth`, default `4`.
- Rule status: verified

## Standard And Product Decision

- Standard or product policy: deeply nested control-flow makes module code hard to read, refactor, and maintain.
- Why this diagnostic exists: nested `Если`, loops, and `Попытка` blocks are a common source of spaghetti code and hidden branch complexity.
- Non-goals: method size, cyclomatic complexity, cognitive complexity, query nesting, expression nesting, and syntax-error ownership.
- Keep/drop decision: keep as a BSLLS-compatible brain-overload diagnostic.

## Semantic Oracle

- Checked language fact: a parsed BSL control-flow statement is nested deeper than the configured maximum control-flow level.
- Must diagnose when: a supported control statement enters level `maxAllowedLevel + 1` or deeper in a clean CST.
- Must not diagnose when: nesting is at or below the configured limit, nesting occurs only in expressions/query text/comments/strings, the tree is invalid enough that BSL001 owns the syntax problem, or another complexity rule owns the issue.
- Diagnostic anchor token/range: the start keyword token/range of the deepest over-limit control statement in a continuous nesting chain.
- Quick-fix target, if any: extract nested code to a separate method, use guard clauses, or flatten conditions.

## CST Or Domain Fact Model

- Parser/tree source: tree-sitter BSL CST for clean documents; legacy line fallback remains only for invalid/non-CST paths.
- CST/domain object types: `if_statement`, `while_statement`, `for_statement`, `for_each_statement`, and `try_statement`.
- Extracted attributes: control node type, start token range, current control-stack depth, configured maximum, and clean-tree status.
- Parse-error behavior: clean CST uses structural facts; invalid trees skip CST BSL020 and may fall back to line-domain scan, while BSL001 owns syntax errors.
- Textual/regex behavior, only if genuinely textual: fallback line scanning is legacy invalid-tree support; valid CST paths must not use it.

## Examples

### Invalid Examples

1. Five nested `Если` statements with the default limit `4`.
2. `Если -> Если -> Попытка -> Если` with configured limit `3`.
3. Nested loop/control chain whose deepest control statement exceeds the configured threshold.

### Valid Negative Twins

1. Four nested control statements with the default limit `4`.
2. A single shallow `Если` inside a method.
3. Several sibling control blocks that do not exceed the configured stack depth.

### Edge Examples

- Comments: commented keywords do not create CST control nodes.
- Strings: string literals containing keywords do not create CST control nodes.
- Preprocessor: not a separate semantic target for this rule.
- Multiline: multiline conditions count by their containing control statement node.
- Nested constructs: nested `Попытка` contributes to depth like `Если` and loops.
- BSL/SDBL variants, if relevant: SDBL query nesting is not a target.

## Implementation Decision

- Change target: BSL020 contract and audit state; no implementation change.
- Delta category fixed by this change: none; existing CST implementation already matches BSLLS exactly on the verified batch.
