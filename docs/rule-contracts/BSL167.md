## Standard And Product Decision

- Standard or product policy: server-call common modules should be named so server-call behavior is visible from the module name.
- Why this diagnostic exists: server-call modules are a specific cross-context API surface; names without a server-call marker hide how the module is intended to be invoked.
- Non-goals: ordinary server modules, client/client-server/global naming, missing/unreadable XML, and other common-module metadata diagnostics.
- Keep/drop decision: keep as a BSLLS-compatible common-module naming diagnostic.

## Semantic Oracle

- Checked language fact: a common module is classified as server-call and its metadata name does not contain a server-call marker.
- Must diagnose when: sibling common-module XML exists, execution-context predicates classify the module as server-call, and the module name does not contain `ВызовСервера` or `ServerCall`.
- Must not diagnose when: XML is missing/unreadable, the module is not server-call, or the name already contains an accepted server-call marker.
- Diagnostic anchor token/range: the first non-empty/non-BOM line of the module file.
- Quick-fix target, if any: rename the common module to include an accepted server-call marker.

## CST Or Domain Fact Model

- Parser/tree source: XML metadata for common-module flags/name; BSL text is used for the diagnostic anchor.
- CST/domain object types: common-module XML snapshot and first non-empty module line.
- Extracted attributes: module name, execution-context flags, computed server-call predicate, and anchor line range.
- Parse-error behavior: BSL parse errors do not affect this XML-driven naming rule.
- Textual/regex behavior, only if genuinely textual: XML tags and module-name token matching are textual metadata conventions.

## Examples

### Invalid Examples

1. Server-call common module named `ОбменДанными`.
2. Server-call common module named `ServerUtilities`.
3. Server-call common module whose name lacks `ВызовСервера` or `ServerCall`.

### Valid Negative Twins

1. Server-call common module named `ОбменДаннымиВызовСервера`.
2. Server-call common module named `ServerCallUtilities`.
3. Non-server-call common module without a server-call marker.

- Comments: comments may be the diagnostic anchor when they are the first real module line.
- Strings: BSL strings do not affect XML naming.
- Preprocessor: not a separate semantic target for this rule.
- Multiline: XML formatting may be multiline; tag extraction is fixed-tag based.
- Nested constructs: BSL procedures/functions do not affect this rule.
- BSL/SDBL variants, if relevant: SDBL is not relevant.
