## Standard And Product Decision

- Standard or product policy: one blank line is enough to separate code blocks; longer blank runs add noise.
- Why this diagnostic exists: two or more consecutive empty lines unnecessarily stretch modules and methods.
- Non-goals: reporting a single blank separator, whitespace inside strings/comments/query text, or formatting unrelated to physical blank lines.
- Keep/drop decision: keep as a cheap physical-line formatting diagnostic with BSLLS-compatible default.

## Semantic Oracle

- Checked language fact: a physical source file contains a run of more than one empty or whitespace-only line.
- Must diagnose when: a blank-line run length exceeds `allowedEmptyLinesCount=1`, including trailing blank runs at file end.
- Must not diagnose when: there is only one blank line between nonblank lines or no blank line.
- Diagnostic anchor token/range: from the first excessive blank line run start to the line after the run, matching current BSLLS range normalization.
- Quick-fix target, if any: collapse the run to one blank line.
