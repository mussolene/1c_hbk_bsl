## Standard And Product Decision

- Standard or product policy: `ЗаписьЖурналаРегистрации` / `WriteLogEvent` should include event, error level, metadata/object when needed, and useful detailed error text in exception handlers.
- Why this diagnostic exists: weak event-log records make production incidents hard to diagnose.
- Non-goals: non-error log records outside exception handling, valid detailed comments, variables containing non-constant comment expressions, and calls in comments/strings.
- Keep/drop decision: keep as a BSLLS-compatible logging quality diagnostic.

## Semantic Oracle

- Checked language fact: an event-log call is missing required parameters or has an insufficient direct error comment expression.
- Must diagnose when: required event/level/comment parameters are omitted, error level is wrong, or direct comment expression is constant/simple/brief.
- Must not diagnose when: the comment is detailed error info, raises the exception, or is a non-constant variable expression as BSLLS does not deeply reject it.
- Diagnostic anchor token/range: full log-event call.
- Quick-fix target, if any: pass correct event, error level, metadata/object, and detailed error text.

## CST Or Domain Fact Model

- Parser/tree source: tree-sitter BSL CST and runtime global-call facts.
- CST/domain object types: `try_statement`, exception block roots, `method_call`, `arguments`, assignments.
- Extracted attributes: call name/range, argument positions, exception-block membership, log level expression, comment expression, and simple variable assignment shape.
- Parse-error behavior: no CST means no BSL262 diagnostics.
- Textual/regex behavior, only if genuinely textual: none for valid paths.

## Examples

### Invalid Examples

1. `ЗаписьЖурналаРегистрации("E")` with missing required arguments.
2. Error-level call with omitted comment argument.
3. Direct `КраткоеПредставлениеОшибки(Ошибка)` comment in an exception block.

### Valid Negative Twins

1. Comment uses `ПодробноеПредставлениеОшибки(ИнформацияОбОшибке())`.
2. Comment variable is assigned a non-constant formatted expression before the log call.
3. Exception block re-raises the error.

### Edge Examples

- Comments: ignored by CST.
- Strings: ignored by CST.
- Preprocessor: no separate semantic target.
- Multiline: call range may span multiple lines.
- Nested constructs: exception-block calls are checked by CST containment.
- BSL/SDBL variants, if relevant: SDBL is not relevant.
