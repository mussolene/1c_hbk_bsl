## Описание диагностики

Указание нескольких директив компиляции методу или переменной модуля является ошибкой само по себе. Кроме того, указание нескольких различных директив приводит к неопределенностям: будет ли скомпилирован коде? а если будет, то в каком контексте?

## Примеры

Неправильно

```bsl
&НаСервере
&НаКлиенте
Перем МояПеременная;

&НаСервере
&НаКлиенте
Процедура МояПроцедура()

КонецПроцедуры
```

</div>

<div class="doc-lang doc-lang-en" markdown="1">

## Description

It is an error to specify multiple compilation directives to a module method or variable. In addition, specifying several different directives leads to ambiguities: will the code compile? And if so, in what context?

## Examples

Incorrect:

```bsl
&AtServer
&AtClient
Var MyVariable;

&AtServer
&AtClient
Procedure MyProcedure()

EndProcedure
```

## Standard And Product Decision

- Standard or product policy: one method or module variable declaration must not have several compiler directives.
- Why this diagnostic exists: multiple directives on a declaration make execution context ambiguous or invalid.
- Non-goals: needless single directives, valid single client/server directives, and directives not attached to a method or module variable.
- Keep/drop decision: keep as a BSLLS-compatible compiler-directive correctness diagnostic.

## Semantic Oracle

- Checked language fact: a method declaration or module variable declaration has more than one compiler directive attached to it.
- Must diagnose when: two or more adjacent compiler directives are associated with the same procedure/function or module variable declaration.
- Must not diagnose when: only one directive is attached, directives are attached to separate declarations, or directive-like text appears in comments/strings.
- Diagnostic anchor token/range: method name range for method directives; module variable declaration range for variable directives.
- Quick-fix target, if any: remove all but the intended compiler directive.

## CST Or Domain Fact Model

- Parser/tree source: tree-sitter BSL CST and existing procedure/module variable directive facts.

- Parse-error behavior: missing declaration facts means no structural BSL248 diagnostics.

## Examples

### Invalid Examples

1. `&НаКлиенте` then `&НаСервере` before one procedure.
2. `&AtClient` then `&AtServer` before one function.
3. Two directives before a module `Перем` declaration.

### Valid Negative Twins

1. A single `&НаКлиенте` before a procedure.
2. Two procedures each with one directive.
3. `// &НаСервере` comment before a client procedure.

### Edge Examples

- Comments: commented directive text is ignored.
- Strings: directive text in strings is ignored.
- Preprocessor: no separate semantic target.
- Multiline: method signatures may be multiline; directive count is attached to the declaration.
- Nested constructs: methods/module variables are top-level declarations.
