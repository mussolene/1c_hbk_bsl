## Описание диагностики

Существуют громоздкие методы (процедуры и функции), с которыми невозможно эффективно работать именно из-за их огромного размера.
Большой метод зачастую возникает, когда разработчик добавляет в метод новый функционал. "Зачем мне выносить проверку параметров в отдельный метод, если я могу написать ее тут?", "Для чего необходимо выделять метод поиска максимального элемента в массиве, оставим его тут. Так код яснее", - и прочие заблуждения.

Есть два правила рефакторинга большого метода:

- Если при написании метода хочется добавить комментарий в код, необходимо выделить этот функционал в отдельный метод
- Если метод занимает более 50-100 строк кода, следует определить задачи и подзадачи, которые он выполняет, и попробовать вынести подзадачи в отдельный метод

## Description

There are cumbersome methods (procedures and functions) which mskes it impossible to work effectively precisely because of their huge size.
A large method often arises when a developer adds new functionality to a method. “Why should I put the parameter check in a separate method, if I can write it here?”, “Why do I need to create a separate method for the search of maximum element in the array, let’s leave it here. So the code is clearer”, and other misconceptions.

There are two rules for refactoring a large method:

- If when writing a method you want to add a comment to the code, you must put this functionality in a separate method
- If the method takes more than 50-100 lines of code, you should determine the tasks and subtasks that it performs and try to put the subtasks in a separate method

## Examples

### Invalid Examples

1. A procedure with 201 executable body lines under the default `maxMethodSize=200`.
2. A function with 51 executable body lines when `maxMethodSize=50`.
3. A long method whose body is extended by ordinary statements rather than comments.

### Valid Negative Twins

1. A procedure with 200 executable body lines under the default limit.
2. A method with many trailing comments but an executable body below the configured limit.
3. A short method that is complex; complexity belongs to BSL011/BSL019 instead.

### Edge Examples

- Comments: ignored for first/last effective body line selection.
- Strings: counted as source lines only when they are inside the effective method body span.
- Preprocessor: ordinary body lines contribute when inside the effective span.
- Multiline: multiline statements count by physical body lines.
- Nested constructs: included in the owning method body length.
- BSL/SDBL variants, if relevant: query text is not a separate target.
