# BSL244 ServerCallsInFormEvents Contract

## Rule Identity

- Code: BSL244
- BSLLS compatible name: ServerCallsInFormEvents
- Public name/i18n key: ServerCallsInFormEvents / BSL244
- Default message/i18n key: RULE_MESSAGES_RU["BSL244"]
- Description/i18n key: RULE_METADATA["BSL244"].description
- Severity: ERROR
- Parameters/defaults: none
- Rule status: parity-classified

## Standard And Product Decision

- Standard or product policy: form events `ПриАктивизацииСтроки` / `OnActivateRow` and `НачалоВыбора` / `OnStartChoice` must not call context-dependent server methods.
- Why this diagnostic exists: these form events can run very often or in latency-sensitive UI flows; server round trips from them can make forms slow or unstable.
- Non-goals: do not diagnose every form event, server-side form procedures, ordinary helper calls, calls to `&НаСервереБезКонтекста` / `&AtServerNoContext`, common-module calls, or dynamic calls that are not direct global method calls.
- Keep/drop decision: keep as a BSLLS-compatible form performance/correctness diagnostic.

## Semantic Oracle

- Checked language fact: a direct global method call inside a forbidden form event targets a local form method compiled with `&НаСервере` / `&AtServer`.
- Must diagnose when: the current file is a form module, the containing procedure/function name ends with `ПриАктивизацииСтроки`, `OnActivateRow`, `НачалоВыбора`, or `OnStartChoice`, and a direct call in its body targets a local method with exactly the context-dependent server compiler directive.
- Must not diagnose when: the event is another `При*` / `On*` event, the target method is `&НаСервереБезКонтекста` / `&AtServerNoContext`, the target method is client/both/none-context, the call is a qualified common-module call, or the file is not a form module.
- Diagnostic anchor token/range: direct called method name range in the forbidden event body.
- Quick-fix target, if any: move the call out of the event, use a non-context server method if safe, cache required data, or redesign the form interaction.

## CST Or Domain Fact Model

- Parser/tree source: current form module BSL procedure/function model and cleaned BSL lines.
- CST/domain object types: `ProcInfo` for containing event methods and target methods, compiler directive lines immediately preceding target procedures, direct same-line global method call tokens.
- Extracted attributes: current path module type, event method name suffix, containing method execution context, target method name, target server directive kind, call range, and cleaned-line text.
- Parse-error behavior: missing parsed procedure facts means no structural BSL244 diagnostics.
- Textual/regex behavior, only if genuinely textual: current implementation uses the existing cleaned-line direct call scanner for same-line global method calls; this is a bounded compatibility bridge until a shared CST call fact is used by the metadata/runtime pool.

## Examples

### Invalid Examples

1. `&НаКлиенте Процедура ТоварыПриАктивизацииСтроки()` directly calls `Заполнить()` where `Заполнить` is `&НаСервере`.
2. `&AtClient Procedure ItemsOnActivateRow()` directly calls `Fill()` where `Fill` is `&AtServer`.
3. `&НаКлиенте Процедура ПолеНачалоВыбора()` directly calls a local form method compiled with `&НаСервере`.

### Valid Negative Twins

1. `ПриОткрытии` calls a server helper.
2. `ПриАктивизацииСтроки` calls a helper compiled with `&НаСервереБезКонтекста`.
3. A non-forbidden server-side form event method calls a server helper.
4. A non-form module contains a method with a forbidden suffix.

### Edge Examples

- Comments: cleaned comments must not produce direct call facts.
- Strings: string literals must not produce direct call facts.
- Preprocessor: no special handling beyond visible cleaned lines.
- Multiline: only same-line direct call syntax is currently in scope.
- Nested constructs: calls inside conditionals/loops inside the forbidden event are checked the same way.
- BSL/SDBL variants, if relevant: SDBL is not relevant.

## Implementation Decision

- Change target: BSL244 branch in `query_metadata_rules.py`, public rule severity/docs, and synthetic coverage.
- Delta category fixed by this change: semantic mismatch from checking all `При*` / `On*` events and treating `&НаСервереБезКонтекста` as forbidden server calls.
- Why not another layer: existing runtime pool already has current form module procedures and cleaned lines; no metadata crawl or new parser is required.
- Rollback signal: `ПриОткрытии` server helper calls report, `НаСервереБезКонтекста` target calls report, forbidden event `ПриАктивизацииСтроки` no longer reports, or private parity worsens without a classified reason.
