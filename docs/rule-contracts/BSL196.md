# BSL196 GlobalContextMethodCollision8312 Contract

## Rule Identity

- Code: BSL196
- BSLLS compatible name: GlobalContextMethodCollision8312
- Rule status: implemented

## Standard And Product Decision

- Standard or product policy: Platform 8.3.12 introduced global context bit methods; configuration methods with the same names must be renamed or removed to avoid unpredictable resolution.
- Non-goals: Do not diagnose calls to platform methods; only declarations in the configuration module are checked.

## Semantic Oracle

- Checked language fact: A procedure or function declaration name equals one of the 8.3.12 global bit-method names.
- Must diagnose when: a method declaration is named `ПроверитьБит`, `ПроверитьПоБитовойМаске`, `УстановитьБит`, `ПобитовоеИ`, `ПобитовоеИли`, `ПобитовоеНе`, `ПобитовоеИНе`, `ПобитовоеИсключительноеИли`, `ПобитовыйСдвигВлево`, `ПобитовыйСдвигВправо`, or the documented English equivalents.
- Must not diagnose when: the name appears only as a call, string, comment, or longer identifier.
- Diagnostic anchor token/range: The colliding method declaration name.

## CST Or Domain Fact Model

- CST/domain object types: module method model / procedure declaration symbol.
- Extracted attributes: method name, declaration start line, method-name span.
- Parse-error behavior: Do not report if the module model cannot prove a method declaration.
- Shared semantic object: Declared module method symbol.

## Examples

### Invalid Examples

1. `Процедура ПроверитьБит()`.
2. `Function BitwiseShiftRight()`.
3. `Функция ПобитовоеИли()`.

### Valid Negative Twins

1. `ПроверитьБит(Значение);` as a call.
2. `Процедура ПроверитьБитДополнительно()`.
3. `// Процедура ПроверитьБит()`.
