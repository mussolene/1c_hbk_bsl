## Standard And Product Decision

- Standard or product policy: find-by-string/code/number helpers should be avoided in performance-sensitive metadata lookups.
- Why this diagnostic exists: string lookups can be slow and fragile compared with references or indexed fields.
- Non-goals: dynamic/non-literal arguments outside BSLLS scope, comments, strings, and unrelated methods.
- Keep/drop decision: keep as a BSLLS-compatible performance diagnostic.

## Semantic Oracle

- Checked language fact: a `method_call` uses `НайтиПоНаименованию`, `НайтиПоКоду`, `НайтиПоНомеру` or English equivalents with BSLLS-compatible simple arguments.
- Must diagnose when: such a call uses no argument, a string argument, or a numeric argument.
- Must not diagnose when: argument is a variable/expression beyond BSLLS scope or text appears outside code.
- Diagnostic anchor token/range: full method call where available.
- Quick-fix target, if any: replace with indexed lookup/reference-based logic.

2. `Справочники.Товары.НайтиПоНаименованию("A")`.
