## Standard And Product Decision

- Standard or product policy: unstructured `Перейти` / `Goto` control flow should not be used in BSL code.
- Why this diagnostic exists: jumps make control flow harder to read, maintain, and reason about compared with structured `Если`, `Пока`, `Для`, `Продолжить`, or `Прервать`.
- Non-goals: method calls whose name is `Перейти`/`Goto`, labels by themselves, comments, strings, query text, formatter casing, and syntax-error ownership.
- Keep/drop decision: keep as a BSLLS-compatible standard/badpractice diagnostic.

## Semantic Oracle

- Checked language fact: executable BSL code contains a parsed `goto_statement`.
- Must diagnose when: a clean CST contains a `goto_statement` formed by `Перейти` or `Goto` and its target label.
- Must not diagnose when: `Перейти`/`Goto` appears as an object method name, identifier text, comment, string literal, label declaration, or malformed syntax owned by BSL001.
- Diagnostic anchor token/range: the whole goto statement range from the `Перейти`/`Goto` keyword through the target label, excluding trailing semicolon/comment.
- Quick-fix target, if any: replace the jump with structured control flow.

## CST Or Domain Fact Model

- Parser/tree source: tree-sitter BSL CST.
- CST/domain object types: `goto_statement`, target label child node, semicolon/comment child nodes for range trimming.
- Extracted attributes: statement start/end point, target node range, keyword text, and clean tree state.
- Parse-error behavior: invalid/missing CST produces no BSL027 facts; BSL001 owns syntax errors.
- Textual/regex behavior, only if genuinely textual: none for valid CST paths.

## Examples

### Invalid Examples

1. `Перейти ~Метка;`
2. `Goto ~Loop;`
3. `Если Условие Тогда Перейти ~Метка; КонецЕсли;`

### Valid Negative Twins

1. `ПотокЗаписи.Перейти(Позиция);`
2. `// Перейти ~Метка;`
3. `~Метка: Значение = 1;`

### Edge Examples

- Comments: commented goto text is ignored.
- Strings: string literals containing `Перейти`/`Goto` are ignored.
- Preprocessor: not a separate semantic target for this rule.
- Multiline: statement range should include the parsed target label and not trailing comments.
- Nested constructs: nesting does not change the rule; goto remains forbidden wherever parsed.
- BSL/SDBL variants, if relevant: SDBL is not relevant.
