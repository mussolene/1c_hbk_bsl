## Standard And Product Decision

- Standard or product policy: query `ПОДОБНО` / `LIKE` right operand must follow the standard form; BSLLS permits a query parameter or a multiline/string literal pattern and reports other expression shapes.
- Why this diagnostic exists: non-parameter, non-literal LIKE operands are hard to reason about, can be wrong at runtime, and deviate from the BSLLS standard check.
- Non-goals: do not diagnose mere LIKE usage without operand-shape defect; BSL269 owns the performance/style warning.
- Keep/drop decision: keep as a BSLLS-compatible query correctness diagnostic.

## Semantic Oracle

- Checked language fact: an SDBL `like_expression` whose right `query_expression` is not a parameter and not a string literal.
- Must diagnose when: right operand is an identifier/field, number, undefined, function call, binary expression, or another non-allowed expression shape.
- Must not diagnose when: right operand is a query parameter such as `&Pattern`, or a query string literal/multiline string literal.
- Diagnostic anchor token/range: full SDBL `like_expression` range mapped to the BSL query-string coordinates, matching BSLLS parent predicate range as closely as possible.
- Quick-fix target, if any: move the pattern into a query parameter or literal pattern accepted by the standard.

## CST Or Domain Fact Model

- Parser/tree source: unescaped SDBL tree-sitter CST from query text blocks.
- CST/domain object types: `QueryTextBlockInfo`, SDBL `like_expression`, child `query_expression` nodes, `parameter`, `string`, and expression-shape descendants.
- Extracted attributes: like-expression start/end row and byte columns, right operand expression kind, and mapped BSL line/character range.
- Parse-error behavior: skip malformed query fragments that do not produce a complete `like_expression` with right operand.
- Textual/regex behavior, only if genuinely textual: legacy regex fallback may remain only for environments without query block/SDBL facts; valid CST paths must be structural.

## Examples

### Invalid Examples

1. `ГДЕ Т.Код ПОДОБНО ДругаяКолонка`.
2. `ГДЕ Т.Код ПОДОБНО Неопределено`.
3. `WHERE T.Code LIKE BuildPattern(&Pattern)`.

### Valid Negative Twins

1. `ГДЕ Т.Код ПОДОБНО &Шаблон`.
2. `ГДЕ Т.Код ПОДОБНО "ABC%"`.
3. `WHERE T.Code LIKE &Pattern`.

### Edge Examples

- Comments: LIKE-like words in comments are not SDBL expressions.
- Strings: `LIKE` inside a query string literal is not an operator.
- Preprocessor: BSL preprocessor is irrelevant after query text extraction.
- Multiline: a LIKE predicate may span query lines; range maps back to BSL lines.
- Nested constructs: LIKE inside nested query expressions is diagnosed the same way.
- BSL/SDBL variants, if relevant: Russian `ПОДОБНО` and English `LIKE` are equivalent.
