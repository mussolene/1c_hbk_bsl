# BSL229 OrdinaryAppSupport Contract

## Rule Identity

- Code: BSL229
- BSLLS compatible name: OrdinaryAppSupport
- Rule status: implemented

## Standard And Product Decision

- Standard or product policy: Configurations should preserve ordinary-application compatibility flags unless there is an explicit product decision not to.
- Non-goals: Do not report in arbitrary modules; BSLLS scopes this diagnostic to the session module and configuration metadata.

## Semantic Oracle

- Checked language fact: Configuration metadata flags conflict with ordinary application support requirements.
- Must diagnose when: `UseManagedFormInOrdinaryApplication` is false.
- Must diagnose when: `UseOrdinaryFormInManagedApplication` is true.
- Must not diagnose when: both flags are configured as recommended.
- Must not diagnose when: the current module is not `Ext/SessionModule.bsl`.
- Diagnostic anchor token/range: The session module selection range, reported as line 1 by the local XML pool.

## CST Or Domain Fact Model

- CST/domain object types: local `Configuration.xml`, session module path, module symbol range.
- Extracted attributes: configuration root, boolean flag values, session-module path, diagnostic message.
- Parse-error behavior: The rule does not depend on BSL CST beyond module symbol/range availability.
- Shared semantic object: Configuration ordinary-application compatibility state.

## Examples

### Invalid Examples

1. `<UseManagedFormInOrdinaryApplication>false</UseManagedFormInOrdinaryApplication>`.
2. `<UseOrdinaryFormInManagedApplication>true</UseOrdinaryFormInManagedApplication>`.
3. Both invalid flags in one configuration produce two diagnostics.

### Valid Negative Twins

1. `<UseManagedFormInOrdinaryApplication>true</UseManagedFormInOrdinaryApplication>` and `<UseOrdinaryFormInManagedApplication>false</UseOrdinaryFormInManagedApplication>`.
2. The same XML next to a non-session module.
3. Configuration extensions without these base-configuration flags.
