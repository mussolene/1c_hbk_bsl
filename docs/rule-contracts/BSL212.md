## Описание диагностики

При вызове функций не следует пропускать обязательные параметры. В противном случае в параметр будет передано значение `Неопределено`, на которое функция может быть не рассчитана.
Если же значение `Неопределено` является допустимым, то нужно
- или его передавать в функцию явно
- или сделать этот параметр необязательным со значением по умолчанию `Неопределено`.
## Примеры

Например, для вызова процедуры

```bsl
Процедура ПоменятьЦветПоляФормы(Форма, ИмяПоля, Цвет)
```

неправильно:

```bsl
ПоменятьЦветПоляФормы(,"РезультатПроверки", ЦветаСтиля.ПоясняющийОшибкуТекст); // пропущен первый параметр Форма
ПоменятьЦветПоляФормы(,,); // пропущены все обязательные параметры
```

правильно:

```bsl
ПоменятьЦветПоляФормы(ЭтотОбъект, "РезультатПроверки", Цвет); // указаны все обязательные параметры
```

## Description

Required parameters must not be omitted when calling methods, otherwise the value `Undefined` will be passed to the parameter, which the method often cannot process.
If the value `Undefined` is valid, then you need to
- explicitly pass a value
- or make the parameter optional with a default value of `Undefined`.
## Examples

For example

```bsl
Procedure ChangeFormFieldColor(Form, FiledName, Color)
```

Incorrect:

```bsl
ChangeFormFieldColor(,"Result", StyleColors.ArthursShirtColor); // missing first parameter Form
ChangeFormFieldColor(,,); // missing all required parameters
```

Correct:

```bsl
ChangeFormFieldColor(ThisObject, "Result", Color); // all required parameters are specified
```

## Standard And Product Decision

- Standard or product policy: calls to known methods must supply every required positional parameter.
- Why this diagnostic exists: a call with a missing required parameter is a runtime correctness error.
- Non-goals: do not validate unknown dynamic calls, qualified object calls resolved only at runtime, common-module API arity, constructor overloads, or type-specific platform methods in the local method-contract pass.
- Keep/drop decision: keep as a BSLLS-compatible correctness diagnostic for resolved local method calls.

## Semantic Oracle

- Checked language fact: a direct local method call omits at least one non-optional parameter from the resolved local procedure/function signature.
- Must diagnose when: the callee is a local procedure/function, a required parameter position is absent, or an omitted required position appears before later supplied arguments.
- Must not diagnose when: all required positions are supplied, the omitted positions are optional parameters, the call is qualified with an object/module prefix, or the callee is not a known local method.
- Diagnostic anchor token/range: full local method call range from callee identifier through the matching closing parenthesis, excluding the statement semicolon.
- Quick-fix target, if any: add the missing required argument or make the parameter optional intentionally.

## CST Or Domain Fact Model

- Parser/tree source: `DocumentSnapshot.procedures`, `DocumentSnapshot.calls`, and source text argument extraction for the matched local call.
- CST/domain object types: `ProcInfo` local procedure/function facts, semantic `Call` records from `method_call` CST nodes, and parsed call argument positions.
- Extracted attributes: callee name, caller line/character, local signature parameter names, optional parameter set, per-position argument presence, and full call range.
- Parse-error behavior: only parsed local procedures and calls are checked; BSL001 owns syntax errors and malformed calls without a matching closing parenthesis are skipped.
- Textual/regex behavior, only if genuinely textual: source text is used only to recover empty argument positions and the matching closing parenthesis for an already parsed CST call.

## Examples

### Invalid Examples

1. `Обработать();` when `Обработать(Параметр)` requires one parameter.
2. `Обработать(Первый, , Третий);` when the second parameter is required.
3. `Обработать(, "Имя", Значение);` when the first parameter is required and later arguments are supplied.

### Valid Negative Twins

1. `Обработать(Значение);` when only one required parameter exists.
2. `Обработать(Первый);` when later parameters have default values.
3. `Модуль.Обработать();` even if a same-named local method exists; qualified calls are not resolved as local calls.

### Edge Examples

- Comments: comments do not create CST call facts.
- Strings: string literals inside supplied arguments do not suppress the call diagnostic.
- Preprocessor: visible parsed calls are checked; inactive branch semantics are not owned by this rule.
- Multiline: multiline calls are checked only when argument presence and matching call range are recoverable from source text.
- Nested constructs: calls inside conditions, loops, and nested expressions are checked the same way.
- BSL/SDBL variants, if relevant: query text is not a BSL method-call target for this rule.
