## Standard And Product Decision

- Standard or product policy: unary plus immediately following string concatenation is ambiguous and can cause runtime errors.
- Why this diagnostic exists: `Строка + +Значение` is usually a typo where the second plus should not be unary.
- Non-goals: numeric unary plus not following another plus, binary addition, comments, and strings.
- Keep/drop decision: keep as a BSLLS-compatible suspicious expression diagnostic.

## Semantic Oracle

- Checked language fact: a `unary_expression` with operator `+` is preceded by another non-space `+` and its operand is not a numeric literal expression.
- Must diagnose when: a unary plus token appears in a concatenation/addition context like `Текст + +Значение`.
- Must not diagnose when: the unary plus is not preceded by plus, the operand is numeric, or the text appears in comments/strings.
- Diagnostic anchor token/range: the unary `+` operator token.
- Quick-fix target, if any: remove the unary plus or add explicit intended operator/parentheses.

## Examples

### Invalid Examples

1. `Текст = "A" + +Значение;`.
2. `Сообщение = Часть1 + +Часть2;`.
3. `Результат = ПолучитьСтроку() + +Параметр;`.

### Valid Negative Twins

1. `Число = +1;`.
2. `Сумма = A + +1;`.
3. `"A + +B"` inside a string.
