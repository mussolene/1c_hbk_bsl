## Standard And Product Decision

- Standard or product policy: public API methods should have a method description comment.
- Why this diagnostic exists: exported methods in the public interface region form a module contract and need reader-facing documentation.
- Non-goals: validating parameter descriptions, return descriptions, method size, export placement, or non-public service methods.
- Keep/drop decision: keep as a BSLLS-compatible documentation diagnostic.

## Semantic Oracle

- Checked language fact: an exported procedure or function is located under the root public API region and has no adjacent method documentation comment.
- Must diagnose when: an `Экспорт`/`Export` procedure or function is inside root region `ПрограммныйИнтерфейс` or `Public` and `build_method_doc_comment(..., skip_blank_lines=True)` finds no usable method documentation block.
- Must not diagnose when: the method is not exported, the method is outside the public API root region, the adjacent block is a valid method documentation comment, or the syntax tree is invalid.
- Diagnostic anchor token/range: the method name token.
- Quick-fix target, if any: insert a method documentation block above the method declaration.

## CST Or Domain Fact Model

- Parser/tree source: tree-sitter BSL CST converted into `ProcInfo`, plus current line-domain root-region tracking and shared `MethodDocComment`.
- CST/domain object types: `procedure_definition`, `function_definition`, `ProcInfo`, root `#Область`/`#Region` lines, and `MethodDocComment`.
- Extracted attributes: method name/range, export flag, method start line, root region name, adjacent documentation block presence, and compiler directive/blank-line skipping.
- Parse-error behavior: structural method-contract checks skip invalid method facts; BSL001 owns syntax errors.
- Textual/regex behavior, only if genuinely textual: root-region tracking currently reads region directives from lines; method documentation presence uses the shared structured comment layer.

## Examples

### Invalid Examples

1. `#Область ПрограммныйИнтерфейс` containing `Процедура Команда() Экспорт` without preceding comment.
2. `#Region Public` containing `Procedure Command() Export` without preceding comment.
3. Exported public API function with only compiler directives above it and no method description.

### Valid Negative Twins

1. Exported method in `ПрограммныйИнтерфейс` with a preceding `// Описание метода.` block.
2. Non-export method in `ПрограммныйИнтерфейс`.
3. Exported method outside `ПрограммныйИнтерфейс`/`Public`.

### Edge Examples

- Comments: adjacent method documentation comments suppress BSL233; non-method structural comments do not; `См.`/`See` lines inside a structured documentation block do not invalidate the whole block.
- Strings: string literals are not relevant.
- Preprocessor: compiler directives between documentation and method are skipped.
- Multiline: multiline signatures are still anchored on the method name.
- Nested constructs: nested regions use the root region for public API membership.
- BSL/SDBL variants, if relevant: SDBL is not relevant.

## Related-Rule Cluster

- Shared semantic object: public method declarations and adjacent documentation comments.
- Rules that may report on the same object/range: BSL003 checks non-export methods in API regions, BSL015/BSL031 check parameter counts, BSL062 checks unused parameters, BSL192/BSL193/BSL194/BSL215 check method/parameter documentation and contracts, and BSL240 checks parameter rewrites.
- Intended duplicate policy: keep BSL233 separate; it reports a missing method-level documentation block, while BSL215 reports incomplete parameter documentation only after a method documentation block exists.
- Cluster fixture or probe: `tests/test_diagnostics_method_contracts.py::TestBsl233PublicMethodsDescription`.

## Implementation Decision

- Change target: shared structured method documentation parser, BSL233 synthetic coverage, contract, and audit state.
- Delta category fixed by this change: onec-only semantic false positives caused by ignoring an entire documentation block when any line starts with `См.`/`See`.
- Why not another layer: the defect is in the existing `MethodDocComment` block classifier used by BSL233 and BSL215; region tracking and method discovery were not the source of the parity delta.
- Rollback signal: documented public methods with reference lines report BSL233, undocumented exported public methods stop reporting, non-public methods report, or BSL215 documentation parsing regresses.
