- Rule status: implemented

## Standard And Product Decision

- Standard or product policy: query text should use `ОБЪЕДИНИТЬ ВСЕ` / `UNION ALL` instead of plain `ОБЪЕДИНИТЬ` / `UNION` unless duplicate elimination is intentionally required.
- Why this diagnostic exists: plain union can add unnecessary duplicate elimination and degrade query performance.
- Non-goals: string constants that are query separators, dynamic incomplete query fragments, comments, and already explicit `UNION ALL`.
- Keep/drop decision: keep as a BSLLS-compatible query performance diagnostic.

## Semantic Oracle

- Checked language fact: a complete extracted SDBL query block contains `ОБЪЕДИНИТЬ` / `UNION` not followed by `ВСЕ` / `ALL`.
- Must diagnose when: a parseable query block has a plain union keyword in query text.
- Must not diagnose when: the keyword appears in ordinary BSL strings, generated separator fragments outside extracted query blocks, comments, non-query text, or already says `ОБЪЕДИНИТЬ ВСЕ` / `UNION ALL`.
- Diagnostic anchor token/range: the union keyword token range in the original BSL query string line.
- Quick-fix target, if any: replace with `ОБЪЕДИНИТЬ ВСЕ` / `UNION ALL` after confirming duplicate elimination is not required.

## CST Or Domain Fact Model

- Parser/tree source: extracted query text blocks from `DocumentSnapshot` and SDBL parse status.
- CST/domain object types: `QueryTextBlockInfo`, `QueryTextLineInfo`, SDBL parse status, and original query line mapping.
- Extracted attributes: content-line head text, UTF-8 byte offsets for the union keyword, and original LSP range.
- Parse-error behavior: SDBL parse errors do not suppress BSL258 once the source has been extracted as a query block; BSLLS also reports plain union keywords in partially dynamic query blocks.
- Textual/regex behavior, only if genuinely textual: keyword match is textual inside already-extracted parseable query blocks.

## Examples

### Invalid Examples

1. A complete query with `ОБЪЕДИНИТЬ` between two `ВЫБРАТЬ` sections.
2. A complete query with English `UNION` between two `SELECT` sections.
3. A multiline query string where the plain union keyword appears on its own line.

### Valid Negative Twins

1. `ОБЪЕДИНИТЬ ВСЕ` / `UNION ALL`.
2. `Разделитель = " ОБЪЕДИНИТЬ ";`.
3. A dynamic fragment string that contains only a union separator without a complete query.

### Edge Examples

- Comments: comments outside query blocks are ignored.
- Strings: only extracted query string blocks are checked.
- Preprocessor: no separate semantic target.
- Multiline: original ranges are mapped from query block rows to BSL lines.
- Nested constructs: nested query blocks are handled if the extractor returns a complete parseable block.
- BSL/SDBL variants, if relevant: Russian and English union keywords are supported.

## Implementation Decision

- Change target: `UnionAllRule` in `diagnostic_runtime/rules.py`, synthetic separator negative, contract, and audit state.
- Delta category fixed by this change: semantic mismatch from diagnosing ordinary string query separators outside extracted query blocks as query unions.
- Why not another layer: query block extraction already owns the query/non-query boundary and range mapping; adding a separate tokenizer would duplicate it.
- Rollback signal: plain union in a complete query no longer reports, `UNION ALL` reports, or string separator fragments report.
