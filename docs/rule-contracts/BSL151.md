## Standard And Product Decision

- Standard or product policy: `НачатьТранзакцию` / `BeginTransaction` must be outside the `Попытка-Исключение` block and immediately before `Попытка`.
- Why this diagnostic exists: transaction start placement affects exception-safe commit/rollback handling and is part of the 1C transaction usage standard.
- Non-goals: checking commit/rollback pairing, transaction nesting, or arbitrary transaction lifetime analysis.
- Keep/drop decision: keep as a BSLLS-compatible transaction-safety diagnostic.

## Semantic Oracle

- Checked language fact: a global `НачатьТранзакцию()` / `BeginTransaction()` call statement is not immediately followed by a `try_statement`.
- Must diagnose when: any executable statement other than `Попытка` follows `НачатьТранзакцию`, or the call is the last pending statement in the analyzed statement stream.
- Must not diagnose when: the next executable statement is `Попытка` / `Try`, or the call is not a global begin-transaction call statement.
- Diagnostic anchor token/range: the full begin-transaction call statement.
- Quick-fix target, if any: move `НачатьТранзакцию` immediately before `Попытка` and keep it outside the try/catch block.
