## Standard And Product Decision

- Standard or product policy: queries should avoid `ПОЛНОЕ ВНЕШНЕЕ СОЕДИНЕНИЕ` / `FULL OUTER JOIN`, especially for PostgreSQL-backed installations.
- Why this diagnostic exists: full outer joins are often expensive and can usually be rewritten into clearer, cheaper query structures.
- Non-goals: diagnosing left, right, or inner joins; proving an equivalent rewrite; checking runtime DBMS.
- Keep/drop decision: keep as a BSLLS-compatible query standard diagnostic.

## Semantic Oracle

- Checked language fact: an embedded query contains a full outer join operator.
- Must diagnose when: query text contains `ПОЛНОЕ СОЕДИНЕНИЕ`, `ПОЛНОЕ ВНЕШНЕЕ СОЕДИНЕНИЕ`, `FULL JOIN`, or `FULL OUTER JOIN` in a recognized query text block.
- Must not diagnose when: the query uses only left, right, or inner joins, or the words occur outside recognized query text.
- Diagnostic anchor token/range: the full-join operator phrase only, matching BSLLS `fullJoin()` range.
- Quick-fix target, if any: rewrite the query without full outer join.

## CST Or Domain Fact Model

- Parser/tree source: `DocumentSnapshot.query_text_blocks` and extracted query content lines.
- CST/domain object types: embedded query text line facts; BSLLS source object is SDBL `JoinPartContext.fullJoin()`.
- Extracted attributes: original BSL line number, query content base column, matched full-join phrase start/end.
- Parse-error behavior: textual phrase matching still reports in recognizable query text blocks, matching the rule's lexical standard target.
- Textual/regex behavior, only if genuinely textual: yes. The diagnostic range is exactly the full-join phrase; using the query text line extractor avoids scanning arbitrary BSL strings/comments.

## Examples

### Invalid Examples

1. `ПОЛНОЕ СОЕДИНЕНИЕ Таблица КАК Alias`.
2. `ПОЛНОЕ ВНЕШНЕЕ СОЕДИНЕНИЕ Таблица КАК Alias`.
3. `FULL OUTER JOIN Table AS Alias`.

### Valid Negative Twins

1. `ЛЕВОЕ СОЕДИНЕНИЕ Таблица КАК Alias`.
2. `ПРАВОЕ СОЕДИНЕНИЕ Таблица КАК Alias`.
3. `ВНУТРЕННЕЕ СОЕДИНЕНИЕ Таблица КАК Alias`.

### Edge Examples

- Comments: comments outside recognized query text do not matter.
- Strings: only query text blocks are inspected.
- Preprocessor: preprocessor does not affect extracted query text.
- Multiline: each query content line is mapped back to original BSL coordinates.
- Nested constructs: nested full joins still match the full-join phrase.
- BSL/SDBL variants, if relevant: Russian and English SDBL spellings are supported.
