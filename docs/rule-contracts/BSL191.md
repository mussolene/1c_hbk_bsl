## Описание диагностики

Следует избегать использования конструкции ПОЛНОЕ ВНЕШНЕЕ СОЕДИНЕНИЕ в запросах, особенно когда в качестве СУБД используется PostgreSQL. В тех случаях, когда это возможно, необходимо переписать запрос без использования ПОЛНОЕ ВНЕШНЕЕ СОЕДИНЕНИЕ.
## Примеры

Запрос из примера ниже приведет к повышенной нагрузке при использовании PostgreSQL.
```bsl
Процедура Тест1()

    Запрос = Новый Запрос;
    Запрос.Текст = "ВЫБРАТЬ
                   |    Товары.Номенклатура КАК Номенклатура,
                   |    ЕСТЬNULL(ПланПродаж.Сумма, 0) КАК СуммаПлан,
                   |    ЕСТЬNULL(ФактическиеПродажи.Сумма, 0) КАК СуммаФакт
                   |ИЗ
                   |    Товары КАК Товары
                   |        ЛЕВОЕ СОЕДИНЕНИЕ ПланПродаж КАК ПланПродаж
                   |            ПОЛНОЕ ВНЕШНЕЕ СОЕДИНЕНИЕ ФактическиеПродажи КАК ФактическиеПродажи // Диагностика должна сработать здесь
                   |            ПО ПланПродаж.Номенклатура = ФактическиеПродажи.Номенклатура
                   |        ПО Товары.Номенклатура = ПланПродаж.Номенклатура";

КонецПроцедуры
```

## Description

You should not use FULL OUTER JOIN in queries, especially in PostgreSQL database. It is better to rewrite query without FULL OUTER JOIN.
## Examples

Query below will lead to high load on PostgreSQL database.
```bsl
Procedure Test1()

    Query = New Query;
    Query.Text = "SELECT
                   |    Goods.Product AS Product,
                   |    ISNULL(SalesPlan.Sum, 0) AS PlanSum,
                   |    ISNULL(SalesActual.Sum, 0) AS ActualSum
                   |FROM
                   |    Goods AS Goods
                   |        LEFT JOIN SalesPlan AS SalesPlan
                   |            FULL OUTER JOIN SalesActual AS SalesActual // Should trigger here
                   |            ON SalesPlan.Product = SalesActual.Product
                   |        ON Goods.Product = SalesPlan.Product";

EndProcedure
```

## Standard And Product Decision

- Standard or product policy: queries should avoid `ПОЛНОЕ ВНЕШНЕЕ СОЕДИНЕНИЕ` / `FULL OUTER JOIN`, especially for PostgreSQL-backed installations.
- Why this diagnostic exists: full outer joins are often expensive and can usually be rewritten into clearer, cheaper query structures.
- Non-goals: diagnosing left, right, or inner joins; proving an equivalent rewrite; checking runtime DBMS.
- Keep/drop decision: keep as a BSLLS-compatible query standard diagnostic.

## Semantic Oracle

- Checked language fact: an embedded query contains a full outer join operator.
- Must diagnose when: query text contains `ПОЛНОЕ СОЕДИНЕНИЕ`, `ПОЛНОЕ ВНЕШНЕЕ СОЕДИНЕНИЕ`, `FULL JOIN`, or `FULL OUTER JOIN` in a recognized query text block.
- Must not diagnose when: the query uses only left, right, or inner joins, or the words occur outside recognized query text.
- Diagnostic anchor token/range: the full-join operator phrase only, matching BSLLS `fullJoin()` range.
- Quick-fix target, if any: rewrite the query without full outer join.

- Parser/tree source: `DocumentSnapshot.query_text_blocks` and extracted query content lines.
