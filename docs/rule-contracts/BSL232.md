## Description

The absence of module sources in the configuration is not recommended.
In the case of a closed, password-protected module, the quality of the code decreases, it is impossible to review the code, and versioning of changes is not carried out.

## Standard And Product Decision

- Standard or product policy: protected/password-closed modules reduce reviewability, versioning quality, and maintainability.
- Why this diagnostic exists: the project should surface protected module owners even when the protected source is not available for normal code diagnostics.
- Non-goals: reporting protected flags on ordinary modules directly, parsing unavailable source code, or judging why the module is protected.
- Keep/drop decision: keep as a BSLLS-compatible project-locatable session-module diagnostic.

## Semantic Oracle

- Checked language fact: configuration metadata contains one or more module owners whose module is marked protected (`Protected` or `IsProtected` true).
- Must diagnose when: BSL232 is run on `Ext/SessionModule.bsl` and the configuration contains protected module metadata.
- Must not diagnose when: the file is not the session module, configuration metadata is absent, or no protected module metadata exists.
- Diagnostic anchor token/range: the first line/module selection range of the session module.
- Quick-fix target, if any: remove module protection or provide reviewable source.

## CST Or Domain Fact Model

- Parser/tree source: configuration XML metadata plus session module text.
- CST/domain object types: protected module refs cache, session module path classification, first-line range.
- Extracted attributes: protected module XML refs and session module first-line length.
- Parse-error behavior: BSL parse errors are not relevant; the rule is metadata-driven.
- Textual/regex behavior, only if genuinely textual: XML protected flags are matched with the shared metadata helper.

## Examples

### Invalid Examples

1. `CommonModules/Имя.xml` contains `<Protected>true</Protected>` and SessionModule exists.
2. `CommonModules/Имя.xml` contains `<IsProtected>true</IsProtected>` and SessionModule exists.
3. Multiple protected module owners produce multiple diagnostics on the session module range.

### Valid Negative Twins

1. No metadata XML has a protected flag.
2. The checked file is a common module rather than `Ext/SessionModule.bsl`.
3. The workspace has no configuration root.
