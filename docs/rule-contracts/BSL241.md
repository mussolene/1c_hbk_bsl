## Описание диагностики

Для подчиненных объектов метаданных, таких как реквизиты, измерения, ресурсы, табличные части (и их реквизиты) не рекомендуется использовать имена, совпадающие с именами объектов-владельцев, т.к. это может приводить к ошибкам в запросах.

## Примеры

Неправильное именование

```
Справочник.Контрагенты.ТабличнаяЧасть.Контрагенты
РегистрСведений.ПодчиненныеДокументы.Измерение.ПодчиненныеДокументы
Документ.Тара.ТабличнаяЧасть.Тара.Реквизит.Тара
```

## Description

For child metadata objects, such as attributes, dimensions, resources, tabular sections (and their attributes), it is not recommended to use names that match the names of the owner objects, since this can lead to errors in queries.

## Examples

Incorrect names

```
Catalog.Contractors.TabularSection.Contractors
InformationRegister.SubordinateDocuments.Dimension.SubordinateDocuments
Document.Container.TabularSection.Container. Attribute.Container
```

## Standard And Product Decision

- Standard or product policy: child metadata object names should not duplicate the name of their owner because such names make query references ambiguous and can lead to query mistakes.
- Why this diagnostic exists: duplicate owner/child names reduce metadata readability and can produce confusing query paths such as `Catalog.Object.Object` or `Document.Object.Table.Table`.
- Non-goals: do not check BSL local variables, query aliases, form controls, synonyms, comments, or arbitrary substrings; only exact case-insensitive technical-name equality is in scope.
- Keep/drop decision: keep as a BSLLS-compatible metadata naming/design diagnostic.

## Semantic Oracle

- Checked language fact: a parsed object storage child name exactly equals its owning metadata object name, or a tabular-section attribute name exactly equals its tabular-section name.
- Must diagnose when: an object-level storage child such as an attribute, dimension, resource, accounting flag, or tabular section has the same technical name as the metadata object; or a tabular-section attribute has the same technical name as the tabular section.
- Must not diagnose when: names only partially match, only synonyms match, form-only attributes/commands match, enum values match, the current file has no metadata object context, or the metadata XML cannot be parsed.
- Diagnostic anchor token/range: metadata owner range at line 1, character 0 through visible first-line length with minimum 1, matching the shared metadata owner-module anchor policy.
- Quick-fix target, if any: rename the child metadata object so it does not duplicate the owner name.

## CST Or Domain Fact Model

- Parser/tree source: Designer/EDT metadata XML parsed through cached `crawl_config`.
- CST/domain object types: `MetaObject` and `MetaMember` from `metadata_parser.py`, current module path context, current object XML path.
- Extracted attributes: current metadata object name, member kind, member dotted name, terminal member names, parent metadata kind, and first module line for owner diagnostic range.
- Parse-error behavior: unreadable or missing XML produces no BSL241 diagnostics.
- Textual/regex behavior, only if genuinely textual: none; matching is exact case-insensitive string comparison on parsed metadata names.

## Examples

### Invalid Examples

1. Catalog `Товары` with attribute `Товары`.
2. Information register `Состояния` with dimension `Состояния`.
3. Document `Заказ` with tabular section `Строки` and tabular-section attribute `Строки`.
4. Document `Заказ` with tabular section `Заказ`.

### Valid Negative Twins

1. Catalog `Товары` with attribute `Товар`.
2. Document `Заказ` with tabular section `Строки` and attribute `Номенклатура`.
3. A form attribute named like the metadata object.
4. A standalone `.bsl` file outside a configuration metadata folder.

### Edge Examples

- Comments: BSL comments do not matter.
- Strings: BSL strings do not matter.
- Preprocessor: preprocessor directives do not matter.
- Multiline: XML formatting and multiline BSL constructs do not matter.
- Nested constructs: tabular-section attribute comparison uses the tabular-section name, not the metadata object name.
- BSL/SDBL variants, if relevant: SDBL is not directly parsed, but the rule exists because duplicate metadata paths can confuse query text.
