# BSL250 TempFilesDir Contract

## Rule Identity

- Code: BSL250
- BSLLS compatible name: TempFilesDir

- Default message/i18n key: RULE_MESSAGES_RU["BSL250"]
- Description/i18n key: RULE_METADATA["BSL250"].description
- Severity: WARNING
- Parameters/defaults: none.
- Rule status: verified

## Standard And Product Decision

- Standard or product policy: application code should use platform-controlled temporary file names instead of constructing paths from the temporary-files directory manually.
- Why this diagnostic exists: files created from manually composed temporary paths can remain unmanaged and accumulate in the filesystem.
- Non-goals: diagnosing `ПолучитьИмяВременногоФайла()` / `GetTempFileName()`, proving whether a temporary path is later deleted, or checking arbitrary path concatenation.
- Keep/drop decision: keep as a BSLLS-compatible standard/bad-practice diagnostic.

## Semantic Oracle

- Checked language fact: a global function call to `КаталогВременныхФайлов()` / `TempFilesDir()`.
- Must diagnose when: executable BSL code contains the global call token followed by an opening parenthesis.
- Must not diagnose when: the same text appears in comments, strings, or as a member call on an object.
- Diagnostic anchor token/range: the function name token.
- Quick-fix target, if any: replace the path construction with `ПолучитьИмяВременногоФайла()` / `GetTempFileName()` and create a directory from that path when needed.

## CST Or Domain Fact Model

- Parser/tree source: masked executable source lines.
- CST/domain object types: call-name token facts after string/comment masking.
- Extracted attributes: function name, line, start character, end character, and member-call guard.
- Parse-error behavior: malformed syntax is not a separate target; BSL001 owns syntax errors.
- Textual/regex behavior, only if genuinely textual: a bounded call-name regex is acceptable because the diagnostic is a simple global built-in function call convention.

### Edge Examples

- Comments: ignored after masking.
- Strings: ignored after masking.
- Preprocessor: not a separate semantic target.

- Nested constructs: nested expressions are irrelevant; the call token itself is the fact.
- BSL/SDBL variants, if relevant: query text is outside this rule.
