## Описание диагностики

Многократное использование одинаковых строковых литералов в одном модуле или методе является плохим тоном, т.к.
- оно может приводить к сложностям при дальнейшем сопровождении, когда необходимо изменить значение и высока вероятность пропустить одно из повторений
- оно может быть следствием "копипасты", т.е. разработчик забыл изменить, после копирования похожего блока кода.

### Особенности реализации диагностики

- Диагностика с настройками по умолчанию не учитывает регистр символов литерала, т.о. считаются одинаковыми строки `АААА` и `АааА`.
- Нельзя указать минимальное значение анализируемого литерала меньше, чем значение по умолчанию. Это обусловлено тем, что часто используются служебные литералы, которые будут сильно фонить. Например: пустая строка "", числа-селекторы "1", "0" и т.д.
- Нельзя уменьшить допустимое количество повторов использования меньше 1, т.к. это не имеет практического смысла.

## Description

It is bad form to use the same string literals multiple times in the same module or method:
- it can lead to problems with further maintenance, if necessary, change the value - there is a high probability of missing one of the repetitions
- it can be a consequence of "copy-paste" - the developer may have forgotten to change the code after copying a similar block of code.

### Features of the implementation of diagnostic

- Diagnostics with default settings does not respect the case of literal characters - the strings ` AAAA ` and ` AaaA ` are considered the same.
- You cannot specify a minimum parsed literal value less than the default. Short service literals are often used, which will generate unnecessary comments. For example: empty string "", selector numbers "1", "0", etc.
- You cannot reduce the allowed number of repetitions to less than 1, because it makes no practical sense.

## Examples

Bad code

```bsl
Procedure Test(Param)
    Result = "Value";
    If Param = "One" Then
        Result = Result + One("Value");
    Else
        Result = Result + Two("Value");
    EndIf;
EndProcedure
```

Сorrected:

```bsl
Procedure Test(Param)
    Result = "Value";
    If Param = "One" Then
        Result = Result + One(Result);
    Else
        Result = Result + Two(Result);
    EndIf;
EndProcedure
```

Bad code

```bsl
Procedure Test2(Param)
    Result = "Value";
    If Param = "One" Then
        Result = Result + One("Value");
    Else
        Result = Result + Two("Value");
    EndIf;
EndProcedure

Procedure Test3(Param)
    If Param = "Five" Then
        Result = Result + Five("Value");
    EndIf;
EndProcedure
```

Сorrected

```bsl
Procedure Test2(Param)
    Result = "Value";
    If Param = "One" Then
        Result = Result + One(StringValue());
    Else
        Result = Result + Two(StringValue());
    EndIf;
EndProcedure

Procedure Test3(Param)
    If Param = "Five" Then
        Result = Result + Five(StringValue());
    EndIf;
EndProcedure

Function StringValue()
   Return "Value";
EndFunction
```

## Standard And Product Decision

- Standard or product policy: repeated non-trivial string literals inside one method/scope should be extracted or reused to reduce copy-paste maintenance risk.
- Why this diagnostic exists: changing duplicated literal values is error-prone, and repeated literals often indicate missing constants or duplicated code.
- Non-goals: short service literals below the minimum length, string text in comments, pseudo-literals formed across adjacent syntax, cross-method duplicates when `analyzeFile=false`, and syntax-error ownership.
- Keep/drop decision: keep as a BSLLS-compatible badpractice/readability diagnostic.

## Semantic Oracle

- Checked language fact: the same string literal value appears more than the allowed number of copies inside the configured duplicate-analysis scope.
- Must diagnose when: a normalized string literal appears at least `min_duplicate_uses` times in one method/module scope and its quoted length is at least `minTextLength`.
- Must not diagnose when: the literal appears fewer times than the threshold, belongs to different method scopes with default `analyzeFile=false`, is too short, occurs only in comments, or is a syntactic artifact rather than a real literal.
- Diagnostic anchor token/range: the first duplicate string literal token including quotes.
- Quick-fix target, if any: extract the literal to a variable/constant/function and reuse it.

## CST Or Domain Fact Model

- Parser/tree source: document snapshot, procedure model scopes, and comment-stripped source lines.
- CST/domain object types: procedure/function scope model, module-level scope, string literal regex over code-without-comments.
- Extracted attributes: scope line indices, literal raw value, case-folded key when case-insensitive, first occurrence line/column, duplicate count, and minimum duplicate threshold.
- Parse-error behavior: BSL035 is not a parser recovery rule; malformed syntax should be owned by BSL001.
- Textual/regex behavior, only if genuinely textual: string-literal extraction is textual over code-without-comments because the rule compares literal text content and existing snapshot already masks comments/strings consistently.

## Examples

### Invalid Examples

1. Three uses of `"Значение"` inside one procedure with default threshold.
2. Three case-varied uses of `"Раздел"` / `"раздел"` when `caseSensitive=false`.
3. Three escaped-quote literals such as `"Код ""240"" места"` inside one scope.

### Valid Negative Twins

1. Two uses of the same literal with threshold `3`.
2. The same literal once in each of three different methods when `analyzeFile=false`.
3. Short literals below the minimum quoted length.

### Edge Examples

- Comments: string-looking text in comments is ignored.
- Strings: escaped quotes belong to the same literal value.
- Preprocessor: not a separate semantic target for this rule.
- Multiline: current contract is single-line literal comparison; multiline literal parity must be classified before expanding behavior.
- Nested constructs: nested blocks do not create separate scopes; method/module scope controls grouping.
- BSL/SDBL variants, if relevant: query text is still BSL string text; query semantics are not inspected by this rule.
