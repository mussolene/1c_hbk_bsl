- Rule status: verified

## Standard And Product Decision

- Standard or product policy: BSL keywords, preprocessor instructions, and compile directives should use canonical spelling.
- Why this diagnostic exists: mixed or non-canonical keyword spelling makes code style unstable and diverges from the 1C standard spelling table.
- Non-goals: identifiers, strings, comments, generated syntax-error recovery text, and semantic validation of the surrounding construct.
- Keep/drop decision: keep as a BSLLS-compatible standard/style diagnostic.

## Semantic Oracle

- Checked language fact: BSL source text contains a recognized keyword/preprocessor keyword/directive spelling that differs from the canonical spelling table.
- Must diagnose when: a recognized keyword word is present in executable or preprocessor text and its exact spelling is not one of the accepted canonical spellings.
- Must not diagnose when: the word appears only in a comment or string, or the line is intentionally suppressed by the BSL036 condition-line overlap policy.
- Diagnostic anchor token/range: the non-canonical keyword word.
- Quick-fix target, if any: replace the word with the canonical spelling from the RU/EN table.

## CST Or Domain Fact Model

- Parser/tree source: line text with strings and comments masked, plus existing document lines.
- CST/domain object types: textual keyword facts; this rule is genuinely spelling-oriented rather than semantic-node-oriented.
- Extracted attributes: source line index, masked code text, keyword word, word start/end character, and accepted spelling set.
- Parse-error behavior: valid lexical keyword spelling facts can still be emitted; BSL001 owns syntax-error structure.
- Textual/regex behavior, only if genuinely textual: a precompiled keyword-word regex is the primary extractor because canonical spelling is a textual token policy.

## Examples

### Invalid Examples

1. `процедура Тест()`
2. `Для Каждого Строка ИЗ Таблица Цикл`
3. `#область СлужебныеПроцедуры`

### Valid Negative Twins

1. `Процедура Тест()`
2. `Для Каждого Строка Из Таблица Цикл`
3. `"процедура"` inside a string literal.

### Edge Examples

- Comments: comment-only keywords are ignored.
- Strings: string literal text is masked before matching.
- Preprocessor: known preprocessor and directive keywords are part of the accepted table.
- Multiline: each physical line is checked independently.
- Nested constructs: nesting does not change spelling semantics.
- BSL/SDBL variants, if relevant: SDBL query text is outside this rule.
