# BSL183 ExecuteExternalCode Contract

## Rule Identity

- Code: BSL183
- BSLLS compatible name: ExecuteExternalCode
- Public name/i18n key: BSL183 / ExecuteExternalCode
- Default message/i18n key: RULE_MESSAGES_RU["BSL183"]
- Description/i18n key: RULE_METADATA["BSL183"].description
- Severity: ERROR
- Parameters/defaults: none; BSLLS config can disable `ExecuteExternalCode`.
- Rule status: verified

## Standard And Product Decision

- Standard or product policy: server-side BSL must not execute arbitrary enterprise-mode code through `Выполнить` or `Вычислить`.
- Why this diagnostic exists: executing dynamic code on the server is a critical security risk.
- Non-goals: client-only methods, common modules handled by BSL184, split-module fragments duplicated from aggregate modules, ordinary form `Ext/module.bsl` client modules, comments, strings without a call, and member calls.
- Keep/drop decision: keep as a BSLLS-compatible security diagnostic.

## Semantic Oracle

- Checked language fact: non-client, non-common-module source calls global `Выполнить/Execute` or `Вычислить/Eval`.
- Must diagnose when: a global dynamic-code call appears in object modules, managed form modules, command modules, or other non-client module contexts.
- Must not diagnose when: the containing method is client-only, the file is a common module, the file is a split fragment, or the file is an ordinary form `Ext/module.bsl`.
- Diagnostic anchor token/range: full dangerous call from method name through the outer closing parenthesis, including multiline string arguments.
- Quick-fix target, if any: remove dynamic execution or replace it with explicit API calls/dispatch.

## CST Or Domain Fact Model

- Parser/tree source: file-level line scan with procedure/client directive ranges.
- CST/domain object types: procedure ranges from snapshot/fallback parser, client-only method ranges, dynamic-code global call facts.
- Extracted attributes: path module kind, split-fragment status, ordinary-form path, call method name, call start, multiline call end, and client-only procedure range.
- Parse-error behavior: clear call spelling can still report; BSL001 owns malformed syntax.
- Textual/regex behavior, only if genuinely textual: exact method-name matching is used after string/comment masking; the diagnostic span is allowed to include string arguments.

## Examples

### Invalid Examples

1. `Выполнить(Строка);` in `&НаСервере` method.
2. `Возврат Вычислить(Строка);` in a method without a client-only directive.
3. `Eval("...")` in an object module.

### Valid Negative Twins

1. `&НаКлиенте` method containing `Выполнить(Строка);`.
2. Common module code, which is owned by BSL184.
3. Ordinary form `Forms/.../Ext/module.bsl`, matching BSLLS BSL183 scope.

### Edge Examples

- Comments: ignored by masking.
- Strings: full diagnostic spans may include string arguments and are explicitly allowed through the string-overlap filter.
- Preprocessor: not a separate semantic target.
- Multiline: call range can span multiple physical lines.
- Nested constructs: nested assignments/conditions do not change the rule.
- BSL/SDBL variants, if relevant: query text is outside this rule.
