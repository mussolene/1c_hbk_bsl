## Standard And Product Decision

- Standard or product policy: assigning a variable to itself is meaningless and usually indicates a mistake.
- Why this diagnostic exists: self-assignment hides a likely typo, missing right-hand expression, or unfinished refactor.
- Non-goals: property-to-local assignments, normal assignments between different identifiers, comments, strings, or broader identical-expression analysis.
- Keep/drop decision: keep as a BSLLS-compatible suspicious-code diagnostic.

## Semantic Oracle

- Checked language fact: a simple assignment statement has the same variable reference on both sides.
- Must diagnose when: parsed executable code contains `Имя = Имя;` with the same identifier as assignment target and right-hand expression.
- Must not diagnose when: the left side is a member/property access and the right side is a same-named local identifier, or either side is not the same simple variable.
- Diagnostic anchor token/range: assignment statement span up to the right-hand expression boundary used by BSLLS-compatible ranges.
- Quick-fix target, if any: delete the self-assignment line or replace the right-hand side with the intended expression.

- Parser/tree source: tree-sitter BSL CST through `_diagnostics_bsl009_from_tree`.
