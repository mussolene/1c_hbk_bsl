## Standard And Product Decision

- Standard or product policy: a collection must not be inserted into itself because this creates cyclic references.
- Why this diagnostic exists: cyclic collection references can produce unpredictable behavior and performance problems.
- Non-goals: proving aliases, dataflow identity, or detecting insertion of a child object into a parent collection.
- Keep/drop decision: keep as a correctness/performance diagnostic.

## Semantic Oracle

- Checked language fact: a global-looking collection method call inserts the exact same collection expression as an argument into itself.
- Must diagnose when: the full receiver expression before `.Вставить` / `.Insert` / `.Добавить` / `.Add` exactly matches one of the relevant argument expressions.
- Must not diagnose when: only the last receiver segment matches the argument, the argument is a child/parent expression, or the match appears inside comments/strings.
- Diagnostic anchor token/range: the full receiver expression.
- Quick-fix target, if any: insert a copy, child item, or distinct collection instead of the collection itself.

## CST Or Domain Fact Model

- Parser/tree source: light call pool over masked code lines.
- CST/domain object types: receiver expression, method name, argument list, and top-level argument splitter.
- Extracted attributes: full receiver text, method name, relevant argument expressions, and receiver range.
- Parse-error behavior: textual call scan can run without a valid CST; broader syntax errors are owned by BSL001.
- Textual/regex behavior, only if genuinely textual: current implementation is a bounded lexical scan for simple receiver/method/argument facts.

## Examples

### Invalid Examples

1. `Массив.Добавить(Массив);`
2. `Коллекция.Вставить(Коллекция);`
3. `Объект.Коллекция.Add(Объект.Коллекция);`

### Valid Negative Twins

1. `Объект.Коллекция.Добавить(Коллекция);`
2. `Массив.Добавить(ДругойМассив);`
3. `Массив.Добавить(Массив[0]);`

### Edge Examples

- Comments: ignored through masked/clean lines.
- Strings: ignored through masked/clean lines.
- Preprocessor: not a separate semantic target.
- Multiline: not currently targeted by the bounded line scanner.
- Nested constructs: arguments are split at top level before comparison.
- BSL/SDBL variants, if relevant: query text is outside this rule.
