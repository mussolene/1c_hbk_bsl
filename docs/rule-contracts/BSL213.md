# BSL213 Contract

## Rule Identity

- Code: BSL213
- BSLLS compatible name: MissingCommonModuleMethod
- Public name/i18n key: BSL213 / MissingCommonModuleMethod
- Default message/i18n key: RULE_MESSAGES_RU["BSL213"]
- Description/i18n key: RULE_METADATA["BSL213"].description
- Severity: ERROR
- Parameters/defaults: no user parameters
- Rule status: verified

## Standard And Product Decision

- Standard or product policy: external calls to common modules must target existing exported methods of the referenced common module.
- Why this diagnostic exists: calling a missing or non-exported common-module method is a runtime correctness error.
- Non-goals: checking local procedure calls, non-common-module object calls, dynamic calls through strings, reflection-like invocation, or parameter arity.
- Keep/drop decision: keep as a BSLLS-compatible correctness diagnostic.

## Semantic Oracle

- Checked language fact: a qualified call `CommonModule.Method()` references a known common module but the method is not externally callable from the current module.
- Must diagnose when: the target common module exists and the called method is absent from its exported procedure/function set.
- Must diagnose when: the target method exists only as a non-exported method and the call is from another module.
- Must not diagnose when: the target method is exported, the call is to a private method from inside the same common module, the qualifier is not a known common module, or the file is outside a configuration common-module context.
- Diagnostic anchor token/range: the full `CommonModule.Method` text span in the call expression line.
- Quick-fix target, if any: create/export the target method or change the call to an exported API.

## CST Or Domain Fact Model

- Parser/tree source: current BSL module lines and shared common-module metadata index.
- CST/domain object types: current common module path context, common module XML entries, parsed target common module procedure/function definitions.
- Extracted attributes: current common module name, qualified call qualifier, method name, target module existence, exported target method names.
- Parse-error behavior: malformed target modules with no parsed exported methods are treated as having no externally callable methods; malformed caller syntax is limited to visible qualified-call text.
- Textual/regex behavior, only if genuinely textual: qualified-call discovery currently uses the existing metadata-pool line scanner after comments/strings are cleaned by the diagnostic runtime.

## Examples

### Invalid Examples

1. `Caller` calls `Target.Absent()` and `Target` is a known common module without exported `Absent`.
2. `Caller` calls `Target.PrivateMethod()` and `PrivateMethod` exists in `Target` without `Export`.
3. A common module calls an existing target common module method name with different spelling that is not exported in the target.

### Valid Negative Twins

1. `Caller` calls `Target.Exists()` and `Exists` is exported in `Target`.
2. `Target` calls `Target.PrivateMethod()` inside its own module.
3. A line contains `UnknownModule.Absent()` where `UnknownModule` is not a known common module in the configuration.

### Edge Examples

- Comments: comments do not produce calls after runtime line cleaning.
- Strings: strings do not produce calls after runtime line cleaning.
- Preprocessor: preprocessor directives are not special-cased; only visible qualified calls are scanned.
- Multiline: only same-line `Module.Method(` calls are currently in scope.
- Nested constructs: calls inside procedures, functions, conditionals, and loops are all checked the same way.
- BSL/SDBL variants, if relevant: SDBL is not relevant.

## Related-Rule Cluster

- Shared semantic object: common module metadata index and common module method calls.
- Rules that may report on the same object/range: BSL231 checks calls to privileged common modules, BSL214 checks event subscription handlers, and BSL242 checks scheduled job handlers.
- Intended duplicate policy: keep BSL213 independent; a call may be both privileged-sensitive and missing/non-exported, but each diagnostic explains a different defect.
- Cluster fixture or probe: common module cross-reference tests in `tests/test_diagnostics_query_metadata.py`.

## Performance Contract

- Traversal/fact source: current-file line scan plus lazy loading of exported method sets only for called common modules.
- Expected complexity: O(current module lines + called common modules), with cached target-module exported-method sets.
- Shared-pass reuse: shares the common module metadata index with BSL214 and BSL242 but does not load the privileged index used by BSL231.
- Before/after measurement, if changed: targeted pytest runtime 0.57s; private preserved-source-root BSL213 parity over 31,797 files completed in 97.76s with `onec=0`, `bslls=0`.

## Implementation Decision

- Change target: common-module procedure-name cache and BSL213 self-module skip.
- Delta category fixed by this change: semantic mismatch for external calls to non-exported common-module methods.
- Why not another layer: BSL213 already owns common-module method resolution; the shared helper should expose externally callable method names for this rule.
- Rollback signal: external non-exported methods stop reporting, self private calls report, exported target calls report, or lazy-loading tests start loading unrelated modules.
