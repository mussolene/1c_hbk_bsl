## Standard And Product Decision

- Standard or product policy: a standalone `;` is a useless empty operator and should not stay in production code.
- Why this diagnostic exists: empty statements usually appear after refactoring, copy-paste, or accidental duplicate semicolon typing.
- Non-goals: reporting ordinary statement terminators, block-closing semicolons, semicolons inside strings/comments/query text, or parse errors owned by BSL001.
- Keep/drop decision: keep as a CST-backed bad-practice diagnostic.

## Semantic Oracle

- Checked language fact: a semicolon token is parsed as an empty standalone statement rather than as a valid terminator for a real statement.
- Must diagnose when: the CST contains a semicolon token whose surrounding line text and parent context indicate a standalone empty statement, including duplicate semicolons and header/footer stray semicolons.
- Must not diagnose when: the semicolon terminates a valid statement or block, appears inside string/comment/query text, or belongs to malformed syntax better handled by BSL001.
- Diagnostic anchor token/range: the offending `;` token only.
- Quick-fix target, if any: remove the standalone semicolon.

## CST Or Domain Fact Model

- Parser/tree source: tree-sitter BSL CST.
- CST/domain object types: semicolon token nodes and their parent statement/block context.
- Extracted attributes: token start/end point, physical source line, neighboring non-space characters, and parent node type.
- Parse-error behavior: avoid manufacturing facts from parse-error recovery; BSL001 owns syntax failures.
- Textual/regex behavior, only if genuinely textual: limited line-neighborhood checks are allowed only to distinguish standalone semicolons from ordinary terminators.

## Examples

### Invalid Examples

1. `;`
2. `А = 1;;`
3. `Процедура Тест();`

### Valid Negative Twins

1. `А = 1;`
2. `Пока Истина Цикл\nКонецЦикла;`
3. `Сообщение = "строка;";`

### Edge Examples

- Comments: `// ;` is a comment and is ignored.
- Strings: string-literal semicolons are ignored.
- Preprocessor: not a separate target.
- Multiline: each semicolon token is anchored by its real CST position.
- Nested constructs: standalone semicolons inside exception/loop/branch blocks are still diagnosed.
- BSL/SDBL variants, if relevant: SDBL/query text is outside this rule.
