## Описание диагностики

Запрещено хранить в коде:

* Сетевые адреса (ip6, ip4)

Есть как минимум несколько способов правильного хранения такой информации:

* Хранение в константе.
* Хранение в регистре сведений.
* Хранение в отдельном модулей, в котором отключена проверка правила (не рекомендуется).
* Хранение в справочнике, узле плана обмена и т.д..

## Примеры

Неправильно:
```bsl
СетевойАдрес = "192.168.0.1";
```

Правильно:
```bsl
СетевойАдрес = МойМодульПовтИсп.СетевойАдресСервера();
```

<div class="doc-lang doc-lang-en" markdown="1">

## Description

It's forbidden to store in code:

* Network addresses (ip6, ip4)

There are several ways to properly store such information:

* Store in Constants.
* Store in Information registers.
* Store in separate module, where this diagnostic is disabled (not recommended).
* Store in Catalog, Exchange plan node and etc.

## Examples

Incorrect:
```bsl
NetworkAddress = "192.168.0.1";
```

Correct:
```bsl
NetworkAddress = MyModuleReUse.ServerNetworkAddress();
```

## Standard And Product Decision

- Standard or product policy: network addresses are deployment data and must not be hardcoded in module code.
- Why this diagnostic exists: hardcoded IPv4/IPv6 addresses make code environment-specific and can expose infrastructure details.
- Non-goals: URL literals, file paths, credentials, configured popular platform-version exclusions, driver/namespace/run-app contexts, comments, dynamic values loaded from constants/registers/catalogs, and syntactically broken source ownership.
- Keep/drop decision: keep as a BSLLS-compatible security/hardware-related diagnostic.

## Semantic Oracle

- Checked language fact: executable BSL code contains a double-quoted string literal with a bare IPv4 or IPv6 network address that is not excluded by BSLLS-compatible context filters.
- Must diagnose when: a non-comment source line has a string literal whose content contains a bare IP-shaped IPv4/IPv6 address and the literal is not excluded by explicit configured filters. The rule does not infer that an IP-shaped dotted numeric literal is a version based on method names or nearby identifiers.
- Must not diagnose when: the apparent address is part of a URL, an explicitly configured popular platform-version exclusion, an excluded parameter/context, a comment-only line, a file path, a credential-only signal, or non-literal/dynamic code.
- Diagnostic anchor token/range: the full double-quoted string literal containing the network address.
- Quick-fix target, if any: move the address to configuration data such as a constant, information register, catalog, exchange-plan node, or dedicated suppressed module.

- Parser/tree source: line-domain scan over source lines with string/comment awareness.
- CST/domain object types: double-quoted BSL string literal spans, comment boundary state, and line-level expression context.
