## Описание диагностики

В ОС `Linux` недоступны механизмы `COM`, `OLE`, `ActiveDocument`. Для интеграции необходимо использовать другие средства, например файловый обмен в формате XML или web-сервисы.
Внешние компоненты, реализованные по COM-технологии, рекомендуется переработать с использованием технологии `NativeAPI`.

Отслеживаемые механизмы, недоступные в Linux:

* `COMОбъект`
* `Почта`

**Проверка значения выполнения условия пока не выполняется.**

### Дополнительно

При проверке использования недоступных объектов в Linux учитываются условия, в которых можно найти следующий ключевые слова:

* `Linux_x86`
* `Windows`
* `MacOs`

## Примеры

```bsl
Компонента = Новый COMОбъект("System.Text.UTF8Encoding");
```

или

```bsl
Почта = Новый Почта;
```
Вместо этого можно использовать `ЗапуститьПриложение()`.

```bsl
СистемнаяИнформация = Новый СистемнаяИнформация();
Если Не СистемнаяИнформация.ТипПлатформы = ТипПлатформы.Linux_x86 Или ТипПлатформы.Linux_x86_64 Тогда
	Почта = Новый Почта;
КонецЕсли
```

## Description

On `Linux` OS `COM`, `OLE`, `ActiveDocument` are not available. For integration use other options, for example XML file exchange or web-services. For COM AddIns, it is recommended to change them to `NativeAPI` AddIn.

Checked the use of unavailable in:

* `COMObject`
* `Mail`

**Checking the value of the condition is not satisfied.**

### Addition

When found unavailable in Linux objects, the method is checked to include condition flow for platform type:

* `Linux_x86`
* `Windows`
* `MacOs`

## Examples

```bsl
Component = New COMObject("System.Text.UTF8Encoding");
```

or

```bsl
Mail = New Mail;
```
Instead of this you can use `StartApplication()`.

```bsl
SystemInformation = New SystemInformation();
If Not SystemInformation.PlatformType = PlatformType.Linux_x86 OR PlatformType.Linux_x86_64 Then
    Mail = New Mail;
EndIf;
```

## Standard And Product Decision

- Standard or product policy: cross-platform code should not use objects that are unavailable on Unix/Linux clients without an explicit platform guard.
- Why this diagnostic exists: `COM`, `OLE`, `ActiveDocument`, and related legacy integrations do not work on Linux and can break cross-platform deployments.
- Non-goals: proving actual platform branch truth, replacing all Windows-only integrations, or checking arbitrary object names outside the documented unavailable set.
- Keep/drop decision: keep as a BSLLS-compatible standard/compatibility diagnostic.

## Semantic Oracle

- Checked language fact: a `new_expression` creates `COMОбъект` / `COMObject` or `Почта` / `Mail` outside a recognized platform guard.
- Must diagnose when: executable BSL contains `Новый` / `New` for one of the unavailable object types and no ancestor `if`/`elseif` guard mentions the known platform tokens.
- Must not diagnose when: the new expression is guarded by platform checks, appears in comments/strings, or creates a different type.
- Diagnostic anchor token/range: the full `new_expression`, matching BSLLS selection range.
- Quick-fix target, if any: guard the code by platform or replace the unavailable object with a cross-platform integration.
