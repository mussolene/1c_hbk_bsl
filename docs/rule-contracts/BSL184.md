## Standard And Product Decision

- Standard or product policy: server common modules must not execute arbitrary enterprise-mode code through `Выполнить` or `Вычислить`.
- Why this diagnostic exists: dynamic code execution on the server is a security risk and should be audited or replaced by explicit APIs.
- Non-goals: client-only common modules, non-common modules owned by BSL183, comments, strings without an actual call, or member calls such as `Запрос.Выполнить()`.
- Keep/drop decision: keep as the common-module counterpart of BSL183.

## Semantic Oracle

- Checked language fact: a server-capable common module calls global `Выполнить/Execute` or `Вычислить/Eval`.
- Must diagnose when: the file is a common module applicable on server and a global dynamic-code call appears in executable code.
- Must not diagnose when: the common module is not server-capable, the call text is in a comment/string only, or the name is part of another identifier/member call.
- Diagnostic anchor token/range: full dangerous call from method name through the outer closing parenthesis.
- Quick-fix target, if any: remove dynamic execution or move audited explicit logic into a safe common module API.

## CST Or Domain Fact Model

- Parser/tree source: common-module metadata scope plus source-line scan with string/comment masking.
- CST/domain object types: common module path/metadata applicability, physical source line, global dynamic-code call span.
- Extracted attributes: file path, server applicability, method name, call start, multiline call end.
- Parse-error behavior: clear call spelling can still report; BSL001 owns malformed syntax.
- Textual/regex behavior, only if genuinely textual: exact call-name scan is allowed after string/comment masking; the rule is a small security API usage detector.

## Examples

### Invalid Examples

1. Server common module: `Выполнить(Строка);`
2. Server common module: `Возврат Вычислить(Строка);`
3. Server common module: `Eval("...")`

### Valid Negative Twins

1. Non-server common module: `Выполнить(Строка);`
2. Non-common module: `Выполнить(Строка);`
3. Query object method call: `Результат = Запрос.Выполнить();`

### Edge Examples

- Comments: ignored by masking.
- Strings: call-looking text inside strings is ignored, but real call arguments may be strings.
- Preprocessor: not a separate semantic target.
- Multiline: call range may span multiple physical lines.
- Nested constructs: nesting does not change the security fact.
- BSL/SDBL variants, if relevant: query text is outside this rule.
