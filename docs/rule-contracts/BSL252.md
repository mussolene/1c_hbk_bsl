## Standard And Product Decision

- Standard or product policy: assigning a value directly to `ЭтотОбъект` / `ThisObject` in object/form/common-module contexts is suspicious and invalid as a property/object overwrite.
- Why this diagnostic exists: direct self-object assignment usually means the developer intended to assign a property or variable, not the module object itself.
- Non-goals: assignments to properties of `ЭтотОбъект`, unrelated identifiers, comments, strings, and unsupported module contexts.
- Keep/drop decision: keep as a BSLLS-compatible correctness diagnostic.

## Semantic Oracle

- Checked language fact: an `assignment_statement` has `ЭтотОбъект` / `ThisObject` as the left-hand identifier.
- Must diagnose when: supported form/common-module context contains `ЭтотОбъект = ...` or `ThisObject = ...`.
- Must not diagnose when: the left side is `ЭтотОбъект.Свойство`, another variable, a comment/string, or the file context is unsupported.
- Diagnostic anchor token/range: the `ЭтотОбъект` / `ThisObject` identifier on the assignment left side.
- Quick-fix target, if any: replace with the intended property or local variable.

## Examples

### Invalid Examples

1. `ЭтотОбъект = Значение;` in a form module.
2. `ThisObject = Value;` in a supported module.
3. `Если Условие Тогда ЭтотОбъект = Новый Структура; КонецЕсли;`.

### Valid Negative Twins

1. `ЭтотОбъект.Реквизит = Значение;`.
2. `ДругойОбъект = Значение;`.
3. `"ЭтотОбъект = Значение"` inside a string.

### Edge Examples

- Comments: ignored by CST.
- Strings: ignored by CST.
- Preprocessor: no separate semantic target.
- Multiline: assignment span may be multiline, but the diagnostic anchors the left identifier.
- Nested constructs: nested assignment statements are checked the same way.
- BSL/SDBL variants, if relevant: SDBL is not relevant.
