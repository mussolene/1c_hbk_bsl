## Описание диагностики

Весь код модуля должен быть структурирован и разделен по разделам (областям).
Набор разделов для каждого типа модуля (модуль формы, модуль объект, общий модуль и т.д.) однозначно определен, наличие посторонних разделов недопустимо.

## Description

All module code should be structured and divided into sections (regions).
The set of sections for each type of module (form module, object module, common module, etc.) is uniquely determined, the presence of extraneous sections is unacceptable.

## Standard And Product Decision

- Standard or product policy: Module top-level regions should follow the standard region names for the module kind.
- Why this diagnostic exists: It keeps module structure predictable and consistent across projects.
- Non-goals: Nested non-top-level regions and modules with no known standard region allowlist.
- Keep/drop decision: keep

## Semantic Oracle

- Checked language fact: A module-level region name is not allowed for the detected module kind.
- Must diagnose when: A top-level region name does not match the standard names for that file/module path.
- Must not diagnose when: The region name is allowed, the region is not module-level, or the file kind has no allowlist.
- Diagnostic anchor token/range: the region directive line.
- Quick-fix target, if any: rename or remove the region manually.

## Examples

### Invalid Examples

1. A form module contains a module-level custom region not in the form allowlist.
2. A common module contains a module-level custom region not in the common-module allowlist.
3. An object module contains a module-level region named for another module kind.

### Valid Negative Twins

1. A form module uses a standard form region.
2. A file kind without standard regions is not reported.
3. A nested region is not treated as a module-level standard-region violation.

### Edge Examples

- Comments: comments inside regions do not affect the region name.
- Strings: strings are not region directives.
- Preprocessor: preprocessor lines inside regions are not region names.
- Multiline: region directives are single-line facts.
- Nested constructs: only module-level regions are checked.
- BSL/SDBL variants, if relevant: SDBL is not relevant.
