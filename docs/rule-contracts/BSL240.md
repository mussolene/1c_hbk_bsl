- Rule status: verified

## Standard And Product Decision

- Standard or product policy: a parameter passed by value should not be overwritten before its original value is used.
- Why this diagnostic exists: rewriting a by-value parameter before reading it hides a local variable and makes the method contract harder to reason about.
- Non-goals: reporting non-`Знач` parameters, outgoing function parameters, unused parameters, or intentional normalization where the parameter is read on the right side first.
- Keep/drop decision: keep as a BSLLS-compatible suspicious-correctness diagnostic.

## Semantic Oracle

- Checked language fact: a procedure or function assigns to a `Знач`/`Val` parameter before that parameter has been read in the method body.
- Must diagnose when: the left side of an executable assignment is a by-value parameter and the parameter has not been used earlier or in the assignment right side.
- Must not diagnose when: the parameter is not by-value, the apparent assignment is a default value in the method signature, the parameter is read before assignment, or the syntax tree is invalid.
- Diagnostic anchor token/range: the assigned parameter identifier on the assignment left side.
- Quick-fix target, if any: introduce a local variable for the rewritten value or use the parameter value before reassignment.

## CST Or Domain Fact Model

- Parser/tree source: tree-sitter BSL CST and `ProcInfo`/procedure-node mapping from `DocumentSnapshot`.
- CST/domain object types: `procedure_definition`, `function_definition`, `parameter`, `VAL_KEYWORD`, `assignment_statement`, left-side `identifier`, and right-side `expression`.
- Extracted attributes: by-value parameter names, body start after the full method signature, assignment lvalue name/range, right-side identifier reads, non-assignment identifier reads, and already-used parameter names.
- Parse-error behavior: structural method-contract checks skip invalid trees; BSL001 owns syntax errors.
- Textual/regex behavior, only if genuinely textual: none for valid CST paths.

## Examples

### Invalid Examples

1. `Процедура Тест(Знач П)` with `П = 1;` before any read.
2. `Процедура Тест(Знач П = 1)` with `П = 2;` in the body.
3. Form/module event method with `Знач Отказ` and `Отказ = Истина;` before any read.

### Valid Negative Twins

1. `Процедура Тест(П)` with `П = 1;`.
2. `Процедура Тест(Знач П)` with `П = СокрЛП(П);`.
3. Multiline signature default `П = Неопределено` where the body never assigns to `П`.

### Edge Examples

- Comments: comments do not create assignment facts.
- Strings: strings are only considered inside an already selected assignment expression and do not create left-side writes.
- Preprocessor: parsed body assignment facts are checked the same way.
- Multiline: method body starts after the complete multiline signature.
- Nested constructs: assignments inside nested blocks of the same method body count.
- BSL/SDBL variants, if relevant: SDBL is not relevant.

## Implementation Decision

- Change target: BSL240 CST fact extraction, synthetic coverage, contract, and audit state.
- Delta category fixed by this change: onec-only semantic false positives caused by tracking parameter reads only in assignment right sides and ignoring earlier reads in conditions/calls/other expressions.
- Why not another layer: the defect is local to BSL240's existing method-body CST walk; `ProcInfo` and procedure-node mapping already provide the needed scope boundaries.
- Rollback signal: multiline parameter defaults report as rewrites, non-`Знач` parameters report, read-before-write in conditions/calls reports, actual first-statement overwrites stop reporting, or contract validation fails.
