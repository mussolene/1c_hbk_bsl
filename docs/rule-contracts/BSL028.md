# BSL028 MissingCodeTryCatchEx Contract

## Rule Identity

- Code: BSL028
- BSLLS compatible name: MissingCodeTryCatchEx
- Public name/i18n key: BSL028 / MissingCodeTryCatchEx
- Default message/i18n key: RULE_MESSAGES_RU["BSL028"]
- Description/i18n key: RULE_METADATA["BSL028"].description
- Severity: ERROR in current emitted diagnostics; RULE_METADATA keeps `INFORMATION`.
- Parameters/defaults: BSLLS `commentAsCode=false`; comments do not make an exception handler non-empty.
- Rule status: verified

## Standard And Product Decision

- Standard or product policy: caught exceptions must not disappear without executable handling or logging.
- Why this diagnostic exists: an empty `Исключение` block hides real failures from users and administrators.
- Non-goals: ordinary empty control-flow blocks, empty statement tokens, risky calls outside `Попытка`; those are owned by BSL004, BSL025, and security/runtime rules.
- Keep/drop decision: keep as a BSLLS-compatible robustness diagnostic.

## Semantic Oracle

- Checked language fact: a parsed `Попытка ... Исключение ... КонецПопытки` statement has no executable code after `Исключение`.
- Must diagnose when: the exception handler contains only whitespace/comments before `КонецПопытки`.
- Must not diagnose when: the exception handler contains executable code, or the code is not an exception handler.
- Diagnostic anchor token/range: `Исключение` / `Except` keyword span.
- Quick-fix target, if any: add logging/handling code or remove the empty catch block.

## CST Or Domain Fact Model

- Parser/tree source: tree-sitter BSL CST through `MissingCodeTryCatchRule`.
- CST/domain object types: `try_statement`, `EXCEPT_KEYWORD`, `ENDTRY_KEYWORD`, comments, and executable child nodes.
- Extracted attributes: except keyword range, child nodes after the except keyword, executable-child presence, and severity.
- Parse-error behavior: skip malformed or missing try-statement CST; BSL001 owns syntax errors.
- Textual/regex behavior, only if genuinely textual: none for the active CST path.

## Examples

### Invalid Examples

1. `Попытка Действие(); Исключение КонецПопытки;`
2. `Попытка Действие(); Исключение // пусто КонецПопытки;`
3. `Try Action(); Except EndTry;`

### Valid Negative Twins

1. `Попытка Действие(); Исключение ЗаписатьОшибку(ОписаниеОшибки()); КонецПопытки;`
2. `Процедура Тест() Выполнить("Сообщить(1)"); КонецПроцедуры`
3. `Если Условие Тогда КонецЕсли;`

### Edge Examples

- Comments: ignored as handler code because `commentAsCode=false`.
- Strings: executable statements containing strings count as code.
- Preprocessor: ordinary CST parse behavior applies.
- Multiline: handler body is checked across lines until `КонецПопытки`.
- Nested constructs: nested try statements are checked independently.
- BSL/SDBL variants, if relevant: query text is outside this rule.
