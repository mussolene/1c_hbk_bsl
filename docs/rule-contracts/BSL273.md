## Standard And Product Decision

- Standard or product policy: 1C query virtual tables should be called with parameters when parameters are expected for efficient filtering.
- Why this diagnostic exists: virtual-table calls without parameters can read excessive data and hurt performance.
- Non-goals: ordinary table sources, virtual tables with non-empty parameters, comments, strings outside query blocks.
- Keep/drop decision: keep as a BSLLS-compatible query performance diagnostic.

## Semantic Oracle

- Checked language fact: extracted query text contains a virtual table source/call without parameters.
- Must diagnose when: query source matches the supported virtual-table pattern and has no parameter list or an empty parameter list.
- Must not diagnose when: parameters are present, source is not a virtual table, or text is outside an extracted query block.
- Diagnostic anchor token/range: virtual table source name or call range.
- Quick-fix target, if any: add required virtual table parameters.

- Parser/tree source: extracted query text block lines.
- CST/domain object types: `QueryTextBlockInfo`, content lines, virtual-table source regex.

- Parse-error behavior: line-local query block facts may still be checked; syntax errors are not repaired here.
- Textual/regex behavior, only if genuinely textual: bounded query-source matcher inside extracted query blocks.
