## Описание диагностики

Цикломатическая сложность программного кода является одной из наиболее старых метрик, впервые она была упомянута в 1976 году Томасом МакКэбом.
Цикломатическая сложность показывает минимальное число необходимых тестов.
Наиболее эффективным способом снижения цикломатической сложности является декомпозиция кода, дробление методов на более простые, а также оптимизация логических выражений.

Цикломатическая сложность увеличивается на 1 за каждую конструкцию

- `Для ... По .. Цикл`
- `Для каждого ... Из ... Цикл`
- `Если ... Тогда`
- `ИначеЕсли ... Тогда`
- `Иначе`
- `Попытка ... Исключение ... КонецПопытки`
- `Перейти ~Метка`
- Бинарные операции `И ... ИЛИ`
- Тернарный оператор
- `Процедура`
- `Функция`

## Description

Cyclomatic complexity of the program code is one of the oldest metrics, it was first mentioned by Thomas McCab in 1976.
Cyclomatic complexity shows the minimum number of required tests. The most effective way to reduce cyclomatic complexity is to decompose the code, split the methods into simpler ones, and also optimize logical expressions.

Cyclomatic complexity increases by 1 for each of following constructions

- `For ... To .. Do`
- `For each ... Of ... Do`
- `If ... Then`
- `ElsIf ... Then`
- `Else`
- `Try ... Except ... EndTry`
- `GoTo ~Label`
- Binary operations `AND ... OR`
- Ternary operator
- `Procedure`
- `Function`

## Standard And Product Decision

- Standard or product policy: Methods should avoid excessive independent execution paths.
- Why this diagnostic exists: It flags methods whose cyclomatic complexity exceeds the configured threshold.
- Non-goals: Module-level code, comments, strings, and methods below or equal to the threshold.

## Semantic Oracle

- Checked language fact: A procedure or function has McCabe/cyclomatic complexity greater than `max_mccabe_complexity`.
- Must diagnose when: The computed cyclomatic metric for a method exceeds the configured threshold.
- Must not diagnose when: The method is at or below the threshold or branch-like tokens are only comments/strings.
- Diagnostic anchor token/range: the method declaration range from `ProcInfo.header_col` to the method header end.
- Quick-fix target, if any: none

- Parser/tree source: BSL `DocumentSnapshot.procedures` and cached `complexity_metrics_for_procs`.

## Examples

### Invalid Examples

1. A method with enough independent `Если` branches to exceed the threshold.
2. A method with loops and conditions exceeding the threshold.
3. A method with boolean branches and ternary operations exceeding the threshold.

### Valid Negative Twins

1. A simple method below the threshold.
2. A method where branch-like words appear only in comments.
3. A method where branch-like words appear only in strings.

### Edge Examples

- Comments: excluded from metric counting.
- Strings: masked before token counting.
- Preprocessor: not a separate target.
- Multiline: continued boolean expressions contribute to the same method metric.
- Nested constructs: counted as additional execution paths, not cognitive nesting.
- BSL/SDBL variants, if relevant: SDBL is not relevant.
