# BSL253 TimeoutsInExternalResources Contract

## Rule Identity

- Code: BSL253
- BSLLS compatible name: TimeoutsInExternalResources
- Public name/i18n key: TimeoutsInExternalResources / BSL253
- Default message/i18n key: RULE_MESSAGES_RU["BSL253"]
- Description/i18n key: RULE_METADATA["BSL253"].description
- Severity: WARNING
- Parameters/defaults: BSLLS supports `analyzeInternetMailProfileZeroTimeout=true`; compatibility-mode dependent constructor timeout positions are not exposed as public onec parameters.
- Rule status: parity-classified

## Standard And Product Decision

- Standard or product policy: external resource objects must have an explicit finite timeout, either through constructor parameters or a timeout property assignment.
- Why this diagnostic exists: external network/resource calls without timeout can hang execution unpredictably.
- Non-goals: do not diagnose unrelated internet objects such as `HTTPЗапрос`, strings/comments containing constructors, constructors with an explicit timeout parameter, or variables whose timeout property is assigned later in the same method.
- Keep/drop decision: keep as a BSLLS-compatible robustness/performance diagnostic.

## Semantic Oracle

- Checked language fact: a `new_expression` constructs an external resource object whose timeout argument/property remains unspecified.
- Must diagnose when: a supported constructor is used without a non-empty timeout argument and the assigned variable does not receive a numeric or variable timeout property assignment later in the same procedure/function.
- Must not diagnose when: the constructor type is unsupported, the timeout argument position is present, the constructor is inside a comment/string, the timeout property is assigned later to a number or variable, or the checked file has no usable CST facts.
- Diagnostic anchor token/range: constructor type name range for CST-backed diagnostics.
- Quick-fix target, if any: add the timeout constructor argument or assign `Объект.Таймаут` / `Object.Timeout` after construction.

## CST Or Domain Fact Model

- Parser/tree source: tree-sitter BSL CST from the current `DocumentSnapshot`.
- CST/domain object types: `new_expression`, `arguments`, `assignment_statement`, `property_access`, procedure/function `ProcInfo`.
- Extracted attributes: constructor type name, raw argument-position presence including empty arguments, assigned variable name, containing method, subsequent timeout property assignments, and diagnostic type-name range.
- Parse-error behavior: when CST facts are unavailable, the rule falls back only to the existing same-line constructor fact with BSLLS-compatible timeout indexes.
- Textual/regex behavior, only if genuinely textual: fallback line extraction is kept for non-CST parser mode; valid CST paths use `new_expression` and `assignment_statement` nodes.

## Examples

### Invalid Examples

1. `Новый HTTPСоединение(Сервер, Порт)` without timeout argument or later timeout assignment.
2. `Новый FTPСоединение(...)` with the timeout position absent.
3. `Новый WSОпределения(...)` without the WSDL timeout argument.

### Valid Negative Twins

1. `Новый HTTPСоединение(Сервер,,,,, 30)`.
2. `Соединение = Новый HTTPСоединение(Сервер); Соединение.Таймаут = 30`.
3. `Соединение = Новый HTTPСоединение(Сервер); Соединение.Timeout = Таймаут`.
4. `Новый HTTPЗапрос(...)`.

### Edge Examples

- Comments: comments must not produce constructor facts.
- Strings: string literals must not produce constructor facts.
- Preprocessor: no special handling beyond parsed CST statements.
- Multiline: constructor arguments may span lines; CST arguments are the source of truth.
- Nested constructs: supported constructor facts inside nested blocks are checked in the same containing method.
- BSL/SDBL variants, if relevant: SDBL is not relevant.

## Implementation Decision

- Change target: BSL253 branch in `query_metadata_rules.py` plus the runtime rule adapter that passes current CST facts into the existing pool.
- Delta category fixed by this change: semantic mismatch from wrong timeout argument positions; CST implementation also covers later timeout property assignments.
- Why not another layer: current runtime pool already owns BSL253; extending it to receive current tree/snapshot avoids reparsing and avoids a separate scanner.
- Rollback signal: HTTP timeout at the 6th constructor argument reports, later `Таймаут` property assignment reports, comments/strings report, or private parity no longer improves to exact/no-signal.
