## Standard And Product Decision

- Standard or product policy: platform 8.3.12 marks selected chart attributes/methods, chart-label enum names, child-form item grouping values, and `ОчиститьЖурналРегистрации/ClearEventLog` as deprecated.
- Why this diagnostic exists: deprecated platform objects remain available for compatibility but should be replaced with current API names to avoid future breakage and ambiguous behavior.
- Non-goals: full platform type inference, arbitrary metadata compatibility analysis, deprecated user-defined methods, or diagnostics for platform versions outside this 8.3.12 pool.
- Keep/drop decision: keep as a BSLLS-compatible deprecated platform API diagnostic with docs-listed method coverage.

## Semantic Oracle

- Checked language fact: source code references one of the known 8.3.12 deprecated platform API names.
- Must diagnose when: code uses a deprecated chart/plot-area attribute, deprecated chart palette method, deprecated child-form grouping enum value, deprecated chart-label enum name, or deprecated event-log clearing global method.
- Must not diagnose when: the same text appears inside comments or strings, the replacement/current API name is used, or the member name is not in the 8.3.12 deprecated allowlist.
- Diagnostic anchor token/range: the deprecated member, enum, or global method identifier.
- Quick-fix target, if any: replace the deprecated identifier with the documented current API name.

## CST Or Domain Fact Model

- Parser/tree source: shared deprecated-API pool over module source lines with string masking and comment stripping.
- CST/domain object types: property access, method-call-like member access, complex identifier/enum access, and global method call facts represented as exact allowlist matches.
- Extracted attributes: owner/object name, deprecated identifier, line/character range, replacement name, and selected rule code.
- Parse-error behavior: malformed code should not be aggressively diagnosed; BSL001 owns syntax errors.
- Textual/regex behavior, only if genuinely textual: exact allowlist regexes are used for this small platform API surface after strings/comments are masked; no broad free-text search is allowed.
