## Standard And Product Decision

- Standard or product policy: `ПрограммныйИнтерфейс` and `СлужебныйПрограммныйИнтерфейс` regions expose public module APIs and must contain exported methods.
- Why this diagnostic exists: non-export methods in API regions mislead callers and violate module structure conventions.
- Non-goals: enforcing method descriptions, region naming, or common-module metadata; those are owned by related rules.
- Keep/drop decision: keep as a BSLLS-compatible module-structure diagnostic.

## Semantic Oracle

- Checked language fact: a procedure/function declaration is inside an API region and lacks `Экспорт` / `Export`.
- Must diagnose when: a parsed method belongs to `ПрограммныйИнтерфейс` or `СлужебныйПрограммныйИнтерфейс` and is not exported.
- Must not diagnose when: the method is exported, the region is not an API region, or method/region facts are unavailable.
- Diagnostic anchor token/range: procedure/function name in the declaration line.
- Quick-fix target, if any: add `Экспорт` or move the method to a non-API region.

## CST Or Domain Fact Model

- Parser/tree source: parsed procedure/function facts and region facts from the document model.
- CST/domain object types: `ProcedureModel`/`ProcInfo` and region span/name facts.
- Extracted attributes: method name span, export flag, method start/end, containing region name/span, and severity.
- Parse-error behavior: use available procedure/region facts; BSL001 owns syntax errors.
- Textual/regex behavior, only if genuinely textual: API region name matching and method-name span lookup are textual over structured facts.
