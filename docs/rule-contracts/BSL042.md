## Описание диагностики

Программные модули не должны иметь неиспользуемых процедур и функций. Диагностика умеет пропускать `подключаемые методы`, имеющие префиксы, указанные в параметре диагностики.

## Источники

* [Стандарт: Тексты модулей](https://its.1c.ru/db/v8std#content:456:hdoc)

</div>

<div class="doc-lang doc-lang-en" markdown="1">

## Description

Modules should not have unused procedures and functions. Diagnostics can skip `attachable methods` that have prefixes specified in the diagnostic parameter.

## Standard And Product Decision

- Standard or product policy: modules should not contain unused local procedures/functions.
- Why this diagnostic exists: unused local methods add dead code and maintenance cost.
- Non-goals: exported methods, object/form modules under the default configuration, platform handlers, extension overrides, and attachable methods.
- Keep/drop decision: keep as a BSLLS-compatible unused-code diagnostic.

## Semantic Oracle

- Checked language fact: a non-export local method in a whole module is not called by any other method and is not an allowed special method.
- Must diagnose when: a non-export method is unused, not recursive-only used by another method, and is not excluded by module kind, prefix, platform handler, or extension annotation.
- Must not diagnose when: the method is exported, called by another method, belongs to skipped module kinds, has an attachable prefix, is an extension override, or is a known platform handler.
- Diagnostic anchor token/range: method name in the declaration line.
- Quick-fix target, if any: remove the method, call it intentionally, export it when it is part of API, or rename it to an approved attachable pattern when appropriate.

## CST Or Domain Fact Model

- Parser/tree source: document snapshot procedure facts and call facts.
- CST/domain object types: `ProcInfo`, call facts with caller/callee names, module path classification, and annotation lines.
- Extracted attributes: method name/export flag/start line, caller/callee relation, module kind, attachable prefix, platform handler name, extension annotation, and severity.
- Parse-error behavior: skip when procedure/call facts are unavailable; BSL001 owns syntax errors.
- Textual/regex behavior, only if genuinely textual: path/module-kind classification, attachable prefix matching, and annotation checks are textual policy over structured method facts.
