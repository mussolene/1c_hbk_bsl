## Standard And Product Decision

- Standard or product policy: exception handling should not be used as the normal mechanism for converting a value to number.
- Why this diagnostic exists: `Число(...)` / `Number(...)` inside `Попытка` / `Try` bodies commonly hides conversion validation errors and makes control flow expensive.
- Non-goals: number conversions outside try bodies, conversions in exception handlers, comments/strings, and unrelated methods.
- Keep/drop decision: keep as a BSLLS-compatible suspicious error-handling diagnostic.

## Semantic Oracle

- Checked language fact: a `method_call` named `Число` / `Number` appears in the try-body part before `Исключение` / `Except`.
- Must diagnose when: a number conversion call is structurally inside the protected try block.
- Must not diagnose when: the call is outside try, inside the exception handler, or appears only in comments/strings.
- Diagnostic anchor token/range: full `Число(...)` / `Number(...)` call expression.
- Quick-fix target, if any: use explicit validation/parsing before conversion instead of exception-driven control flow.

## CST Or Domain Fact Model

- Parser/tree source: tree-sitter BSL CST through `DiagnosticDocumentContext`.
- CST/domain object types: `try_statement`, child nodes before `EXCEPT_KEYWORD`, and nested `method_call`.
- Extracted attributes: try-body boundary, method call name, call range, and duplicate guard.
- Parse-error behavior: if tree facts are unavailable, a bounded legacy fallback scans try depth; valid CST paths use structured try/method nodes.
- Textual/regex behavior, only if genuinely textual: fallback exists only for missing CST and is not used as the primary path.

## Examples

### Invalid Examples

1. `Попытка Результат = Число(Текст); Исключение ... КонецПопытки;`.
2. `Try Result = Number(Text); Except EndTry;`.
3. Nested call `Значение = Окр(Число(Текст));` inside the try body.

### Valid Negative Twins

1. `Результат = Число(Текст);` outside try.
2. `Исключение Результат = Число(Текст);`.
3. `"Число(Текст)"` inside a string.

### Edge Examples

- Comments: ignored by CST.
- Strings: ignored by CST.
- Preprocessor: no separate semantic target.
- Multiline: method-call range may span lines and is anchored by CST.
- Nested constructs: nested blocks inside the try body are checked.
- BSL/SDBL variants, if relevant: SDBL is not relevant.
