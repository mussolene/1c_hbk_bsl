## Standard And Product Decision

- Standard or product policy: application code should use style elements instead of constructing style primitives directly.
- Why this diagnostic exists: direct `Рамка` / `Цвет` / `Шрифт` construction bypasses shared style policy and can break UI consistency.
- Non-goals: unrelated constructors, comments/strings, and variables or method names that merely contain these words.
- Keep/drop decision: keep as a BSLLS-compatible UI/style diagnostic.

## Semantic Oracle

- Checked language fact: a real `Новый` / `New` constructor expression creates a style primitive type.
- Must diagnose when: constructor type name is exactly `Рамка`, `Цвет`, `Шрифт`, `Border`, `Color`, or `Font`.
- Must not diagnose when: constructor type is another class, text appears in comments/strings, or the style name is not in a constructor type position.
- Diagnostic anchor token/range: full constructor expression from `Новый` / `New` through argument list when present.
- Quick-fix target, if any: replace direct construction with a style element reference.
