## Описание диагностики
Размещение в тернарном операторе булевых констант "Истина" или "Ложь" указывает на плохую продуманность кода.

## Примеры
Бессмысленные операторы

```Bsl
А = ?(Б = 1, Истина, Ложь);
```
```Bsl
А = ?(Б = 0, False, True);
```

Подозрительные операторы (обе ветки - одна и та же булева константа, результат не зависит от условия)

```Bsl
А = ?(Б = 1, True, Истина);
```
```Bsl
А = ?(Б = 0, Ложь, False);
```

</div>

<div class="doc-lang doc-lang-en" markdown="1">

## Description
The placement of Boolean constants "True" or "False" in the ternary operator indicates poor code thoughtfulness.

## Examples
Useless operators

```Bsl
A = ?(B = 1, True, False);
```
```Bsl
A = ?(B = 0, False, True);
```

Suspicious operators (both branches are the same boolean constant, the result does not depend on the condition)

```Bsl
A = ?(B = 1, True, True);
```
```Bsl
A = ?(B = 0, False, False);
```

## Standard And Product Decision

- Standard or product policy: ternary expressions should not encode boolean constants in a way that can be replaced by the condition or its negation.
- Why this diagnostic exists: useless ternaries make boolean logic harder to read and often hide a simpler expression.
- Non-goals: simplifying all ternary expressions, proving arbitrary expression equivalence, or rewriting non-boolean branches.
- Keep/drop decision: keep as a BSLLS-compatible badpractice/suspicious diagnostic.

## Semantic Oracle

- Checked language fact: a ternary operator `?(condition, then, else)` has boolean literals in positions that make the ternary redundant or suspicious.
- Must diagnose when: the condition itself is a boolean literal, both branches are boolean literals, or one branch is a boolean literal while the opposite branch is a recognized boolean expression under the BSLLS-compatible policy.
- Must not diagnose when: boolean literals are paired with non-boolean values, the expression is inside comments, the ternary is malformed, or a boolean-looking value is outside the configured simple patterns.
- Diagnostic anchor token/range: the full ternary expression span.
- Quick-fix target, if any: replace with the condition, negated condition, or a direct boolean expression.

## CST Or Domain Fact Model

- Parser/tree source: shared ternary span extractor over masked source content.
- CST/domain object types: ternary expression span, top-level ternary arguments, and boolean-literal/boolean-expression classifiers.
- Extracted attributes: ternary start/end range, condition/then/else text, boolean literal flags, boolean expression flag, and simple member-access flag.
- Parse-error behavior: malformed ternary syntax is skipped; BSL001 owns broken syntax.
- Textual/regex behavior, only if genuinely textual: boolean operand classification is textual after ternary spans are extracted.
