## Описание диагностики

При активной разработке и изменении модели метаданных могут появляться запросы, в которых идет обращение к переименованным или удаленным метаданным.
Также ошибочные имена таблиц могут возникать при ручном изменении запросов, без проверки с помощью конструктора запросов.

При выполнении запросов к несуществующим метаданным будет возникать ошибка исполнения.

## Примеры

Запрос к уже удаленному регистру:
```sdbl
ВЫБРАТЬ
	Таблица.РесурсЧисло КАК РесурсЧисло
ИЗ
	РегистрСведений.УстаревшееИмяРегистра КАК Таблица
```
Запрос с соединением к переименованному регистру:
```sdbl
ВЫБРАТЬ
	Таблица.РесурсЧисло КАК РесурсЧисло
ИЗ
	РегистрСведений.Регистр1 КАК Таблица
	ВНУТРЕННЕЕ СОЕДИНЕНИЕ РегистрСведений.УстаревшееИмяРегистра КАК ТаблицаФильтр
	ПО ТаблицаФильтр.Регистратор = Таблица.Регистратор
```

## Description

Due to frequent changes to the metadata model, queries may appear that refer to renamed or deleted metadata.
Also, errors can occur when you manually change queries, without checking with the query designer.

When accessing non-existent metadata in a query, a runtime error will occur.

## Examples

Query for an already deleted register:
```sdbl
SELECT
    Table.Field1 AS Field1
FROM
    InformationRegister.InfoRegOld AS Table
```
Query with a join to the renamed register:
```sdbl
SELECT
    Table.Field1 AS Field1
FROM
     InformationRegister.InfoReg AS Table
     INNER JOIN InformationRegister.InfoRegOld AS FilterTable
     ON FilterTable.Field2 = Table.Field2
```

## Rule Identity

- Code: BSL236
- BSLLS compatible name: QueryToMissingMetadata
- Public name/i18n key: QueryToMissingMetadata / BSL236
- Default message/i18n key: Обращение к несуществующим метаданным в запросе
- Description/i18n key: Using non-existent metadata in the query
- Severity: ERROR
- Parameters/defaults: none
- Rule status: parity-classified

## Standard And Product Decision

- Standard or product policy: query data sources and metadata type references must point to existing configuration metadata objects of the referenced metadata type.
- Why this diagnostic exists: queries against deleted, renamed, or mistyped metadata objects fail at runtime.
- Non-goals: do not validate query aliases, temporary tables, fields, tabular-section fields, arbitrary single-part sources, or query syntax errors handled by BSL235.
- Keep/drop decision: keep as a BSLLS-compatible blocking correctness diagnostic.

## Semantic Oracle

- Checked language fact: SDBL metadata object reference in query text, keyed by metadata type and object name.
- Must diagnose when: a query source or metadata type reference uses a known metadata root such as `Документ`/`Document` or `Справочник`/`Catalog`, and no metadata object exists for that exact root type and object name in the active configuration root.
- Must not diagnose when: the object exists in the exact referenced metadata type, the source is a temp table declared by `ПОМЕСТИТЬ`/`INTO`, the source is a single-part query source, the configuration metadata surface is unavailable, or a same-named object exists only in another metadata type.
- Diagnostic anchor token/range: the full typed metadata reference, for example `Документ.Имя`, mapped to the original BSL query text range.
- Quick-fix target, if any: none.

## CST Or Domain Fact Model

- Parser/tree source: `SemanticFactSnapshot.queries` and its
  `MetadataContextFact` entries, populated once from
  `DocumentSnapshot.query_text_blocks`, tree-sitter SDBL CST, and the existing
  active-configuration typed metadata index.
- CST/domain object types: SDBL `table_source`, `join_clause`, and nested `virtual_table_source` source identifiers from `query_source_uses`; textual type references for `ССЫЛКА <MDO>` and `ВЫРАЗИТЬ(... КАК <MDO>)` until the SDBL CST exposes a stable type-reference node for these forms.
- Extracted attributes: source text, source CST node, metadata root token, object name, temp-table names, and type-aware active-configuration metadata index entries `(kind, name)`.
- Parse-error behavior: structural BSL236 facts require a recovered SDBL root; malformed query text is primarily BSL235 territory.
- Textual/regex behavior, only if genuinely textual: regex fallback is limited to metadata type-reference syntax not currently exposed by the SDBL helper facts.

## Examples

### Invalid Examples

1. Query source `Документ.УдаленныйДокумент КАК Таблица` when no `Document` object with that name exists.
2. Join source `РегистрСведений.УдаленныйРегистр КАК Фильтр` when no matching information register exists.
3. Type reference `Данные.Ссылка ССЫЛКА Справочник.УдаленныйСправочник`.
4. Virtual table source `РегистрСведений.УдаленныйРегистр.СрезПоследних(...)`.

### Valid Negative Twins

1. `Документ.Заказ` when `Documents/Заказ.xml` exists.
2. `Справочник.Заказ` in the active configuration or in another sibling configuration does not make `Документ.Заказ` valid; metadata type and active configuration root are both part of the identity.
3. `ВременнаяТаблица КАК ВременнаяТаблица` after `ПОМЕСТИТЬ ВременнаяТаблица`.

### Edge Examples

- Comments: query-line comments are stripped by query-block extraction before SDBL facts.
- Strings: string literals inside query expressions are not metadata references.
- Preprocessor: no special handling; visible query text is checked.
- Multiline: multiline query literals map CST ranges back to original BSL lines.
- Nested constructs: query packages, joins, and unions are checked per recovered source use.
- BSL/SDBL variants, if relevant: Russian and English metadata roots are supported.

- Change target: normalize the existing type-aware metadata lookup into

- Rollback signal: same-name different-type synthetic case fails, targeted query metadata tests fail, or parity/performance regresses without explanation.
