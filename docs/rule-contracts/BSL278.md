# BSL278 WrongWebServiceHandler Contract

## Rule Identity

- Code: BSL278
- BSLLS compatible name: WrongWebServiceHandler
- Public name/i18n key: WrongWebServiceHandler / BSL278
- Default message/i18n key: RULE_MESSAGES_RU["BSL278"]
- Description/i18n key: RULE_METADATA["BSL278"].description
- Severity: ERROR
- Parameters/defaults: none.
- Rule status: parity-classified

## Standard And Product Decision

- Standard or product policy: web service operation handlers declared in metadata must exist in the service module.
- Why this diagnostic exists: wrong handler references break web service operations at runtime.
- Non-goals: non-web-service modules, HTTP service handlers, comments/strings.
- Keep/drop decision: keep as a BSLLS-compatible web-service metadata diagnostic.

## Semantic Oracle

- Checked language fact: web service XML `<ProcedureName>` references an empty or missing service module procedure.
- Must diagnose when: procedure name is empty or no procedure/function with that name exists.
- Must not diagnose when: handler procedure exists.
- Diagnostic anchor token/range: module line for missing handler.
- Quick-fix target, if any: create/fix handler method or metadata reference.

## CST Or Domain Fact Model

- Parser/tree source: local web service XML and module procedure model.
- CST/domain object types: XML operation entries, `ProcInfo` procedures.
- Extracted attributes: procedure name, existence in module, module path kind.
- Parse-error behavior: missing procedure facts mean unresolved handler as applicable.
- Textual/regex behavior, only if genuinely textual: XML tag extraction is bounded to metadata file text.

## Examples

### Invalid Examples

1. `<ProcedureName>` is empty.
2. `<ProcedureName>НеСуществует</ProcedureName>`.
3. Web service module lacks the referenced procedure.

### Valid Negative Twins

1. Referenced procedure exists.
2. HTTP service XML is handled by BSL275, not BSL278.
3. Procedure name appears only in a string.

### Edge Examples

- Comments: comments do not create procedures.
- Strings: strings do not create procedures.
- Preprocessor: no separate semantic target.
- Multiline: procedure model owns ranges.
- Nested constructs: handlers are top-level module procedures.
- BSL/SDBL variants, if relevant: SDBL is not relevant.
