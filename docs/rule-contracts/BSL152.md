# BSL152 CachedPublic Contract

## Rule Identity

- Code: BSL152
- BSLLS compatible name: CachedPublic
- Public name/i18n key: BSL152 / CachedPublic
- Default message/i18n key: RULE_MESSAGES_RU["BSL152"]
- Description/i18n key: RULE_METADATA["BSL152"].description
- Severity: WARNING
- Parameters/defaults: none.
- Rule status: verified

## Standard And Product Decision

- Standard or product policy: cached common modules should not expose reusable methods through the public program interface region.
- Why this diagnostic exists: cached common-module return values are reused by the platform, so public API methods should be moved to the service public interface when the common module uses return-values reuse.
- Non-goals: reporting non-common modules, standalone `.bsl` files, non-cached common modules, empty public regions, service public regions, or validating method export flags.
- Keep/drop decision: keep as a BSLLS-compatible common-module design/performance diagnostic.

## Semantic Oracle

- Checked language fact: a cached common module contains a non-empty root public program interface region.
- Must diagnose when: a common module `Module.bsl` has metadata `ReturnValuesReuse` set to `DuringSession` or `DuringRequest`, and a `ПрограммныйИнтерфейс`/`Public` region contains at least one procedure or function.
- Must not diagnose when: the file is not a common-module `Module.bsl`, metadata XML is absent, `ReturnValuesReuse` is missing or `DontUse`, the public region is empty, the region is not public, or the syntax tree is invalid.
- Diagnostic anchor token/range: the public region name token in the `#Область`/`#Region` directive.
- Quick-fix target, if any: move methods from the public program interface to the service public program interface or disable return-values reuse if the module must remain public.

## CST Or Domain Fact Model

- Parser/tree source: tree-sitter BSL CST converted into `RegionInfo` and `ProcInfo`, plus common-module metadata XML near `Module.bsl`.
- CST/domain object types: common-module `Module.bsl`, sibling or nested common-module XML, root `#Область`/`#Region` region, `procedure_definition`, and `function_definition`.
- Extracted attributes: common-module path shape, `ReturnValuesReuse` value, region name/range, procedure/function start lines, and whether a method starts inside the public region bounds.
- Parse-error behavior: region/procedure facts come from the parsed document snapshot; malformed syntax is owned by BSL001.
- Textual/regex behavior, only if genuinely textual: metadata XML is read with a bounded `ReturnValuesReuse` value extraction; the diagnostic itself uses structured region/procedure facts.

## Examples

### Invalid Examples

1. Cached common module with `#Область ПрограммныйИнтерфейс` containing `Процедура Публичная() Экспорт`.
2. Cached common module with `#Region Public` containing `Procedure PublicMethod() Export`.
3. Cached common module with `ReturnValuesReuse=DuringRequest` and a public region containing a function.

### Valid Negative Twins

1. Common module with `ReturnValuesReuse=DontUse` and public region methods.
2. Cached common module with an empty `ПрограммныйИнтерфейс`/`Public` region.
3. Standalone `.bsl` file with a public region.

### Edge Examples

- Comments: commented region-looking text does not create a region fact.
- Strings: string literals do not create region or method facts.
- Preprocessor: not a separate semantic target for this rule.
- Multiline: method bodies may be multiline; only the method start line is needed to prove region content.
- Nested constructs: nested statements inside methods do not affect the region-level fact.
- BSL/SDBL variants, if relevant: SDBL is not relevant.
