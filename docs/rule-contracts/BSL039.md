## Описание диагностики

Использование вложенных тернарных операторов затрудняет читаемость кода.

## Примеры

### Некорректное использование тернарных операторов

```bsl
Результат  =  ?(x % 15 <> 0, ?( x % 5 <> 0, ?( x % 3 <> 0, x, "Fizz"), "Buzz"), "FizzBuzz");
```

```bsl
Если ?(Стр.Emp_emptype = Null, 0, Стр.Emp_emptype) = 0 Тогда

      Статус = "Готово";

КонецЕсли;
```

### Возможные вариант реализации

```bsl
Если x % 15 = 0 Тогда
	Результат = "FizzBuzz";
ИначеЕсли x % 3 = 0 Тогда
	Результат = "Fizz";
ИначеЕсли x % 5 = 0 Тогда
	Результат = "Buzz";
Иначе
	Результат = x;
КонецЕсли;
```

```bsl
Если Стр.Emp_emptype = Null ИЛИ Стр.Emp_emptype = 0 Тогда

      Статус = "Готово";

КонецЕсли;
```

## Description

Use of nested ternary operators decrease code readability.

## Examples

### Incorrect use of ternary operators

```bsl
Result = ?(X%15 <> 0, ?(X%5 <> 0, ?(X%3 <> 0, x, "Fizz"), "Buzz"), "FizzBuzz");
```

```bsl
If ?(P.Emp_emptype = Null, 0, PageEmp_emptype) = 0 Then

      Status = "Done";

EndIf;
```

### Possible implementation

```bsl
If x % 15 = 0 Then
    Result = "FizzBuzz";
ElseIf x % 3 = 0 Then
    Result = "Fizz";
ElseIf x % 5 = 0 Then
    Result = "Buzz";
Else
    Result = x;
EndIf;
```

```bsl
If PageEmp_emptype = Null OR PageEmp_emptype = 0 Then

      Status = "Done";

End If;
```

## Standard And Product Decision

- Standard or product policy: nested ternary expressions make conditions and value selection hard to read and should be replaced with explicit `Если`/`ИначеЕсли` or simpler named expressions.
- Why this diagnostic exists: nested `?()` expressions create compact but high-cognitive-load branches.
- Non-goals: simple non-nested ternary expressions, question marks inside comments/strings/query text, syntax-error ownership, and boolean condition complexity owned by BSL036.
- Keep/drop decision: keep as a BSLLS-compatible brain-overload/readability diagnostic.

## Semantic Oracle

- Checked language fact: a ternary expression `?()` is nested inside another ternary expression, or a ternary expression is used directly in an `Если`/`ИначеЕсли` condition.
- Must diagnose when: a valid ternary expression is a child/descendant of another ternary expression, or appears in the condition span of an `Если`/`ИначеЕсли` statement.
- Must not diagnose when: the ternary expression is simple and not in an `Если` condition, appears only in strings/comments/query text, or the syntax is malformed enough for BSL001.
- Diagnostic anchor token/range: the offending ternary expression range from `?` through its matching `)`.
- Quick-fix target, if any: replace nested ternary logic with explicit `Если`/`ИначеЕсли` branches or an extracted helper.

## CST Or Domain Fact Model

- Parser/tree source: current implementation uses a document text span scanner that skips strings/comments and maps spans through the document context.
- CST/domain object types: ternary span facts equivalent to `ternary_expression`, plus line-span detection for `Если`/`ИначеЕсли` condition headers.
- Extracted attributes: `?(` start offset, matching closing parenthesis offset, line/column range, containment between ternary spans, and condition-header line range.
- Parse-error behavior: unmatched parentheses produce bounded spans; malformed syntax remains BSL001-owned and must not create broad false positives.
- Textual/regex behavior, only if genuinely textual: temporary accepted implementation detail; a future refactor may replace this with direct CST `ternary_expression` facts after parity tests.
