## Описание диагностики

При разработке не стоит использовать идентификаторы, состоящие из символов разных языков, т.к. это усложняет их дальнейшее использование, заставляя переключать раскладку.
Диагностика обнаруживает и ошибочное использование символов из другого языка, когда он был использован не преднамеренно, например использование символов с одинаковым начертанием `o`, `c`, `B`, `p` и т.д.

Для снижения "шума" на именах состоящих из нескольких слов, начинающихся либо заканчивающихся на слово на другом языке, в диагностику добавлен параметр, включенный по умолчанию.
Если параметр включен, то **НЕ** считаются ошибочными имена вида `ZebraДрайвер`, `КодHTTP`, `SMSШлюз` и подобные им.

## Description

Do not use identifiers consisting of characters from different languages, вecause it makes it difficult to use them further, forcing to switch the layout.
Also, the diagnostics detects the erroneous use of characters from another language, when it was used unintentionally. For exaple: `o`, `c`, `B`, `p` and etc.

To reduce "noise" in the names consisting of several words beginning or ending in the word in another language, in the diagnostics option has been added that is included by default.
If the parameter is enabled, then **NOT** are considered erroneous names like `ZebraДрайвер`, `КодHTTP`, `SMSШлюз` and the like.

## Standard And Product Decision

- Standard or product policy: identifiers should not accidentally mix Latin and Cyrillic letters because homoglyphs and layout switches make code harder to read and maintain.
- Why this diagnostic exists: mixed-script words often indicate a mistaken keyboard layout or a visually confusing homoglyph.
- Non-goals: reporting known technical names, configured excluded words, pure Latin identifiers, pure Cyrillic identifiers, strings/comments, or BSL256 typo duplicates for the same word.
- Keep/drop decision: keep as a text/identifier quality diagnostic with a deliberate duplicate-noise policy.

## Semantic Oracle

- Checked language fact: an identifier-like word in executable module text contains both Latin and Cyrillic letters.
- Must diagnose when: a word contains both scripts, is not an excluded standard technical name, is not allowed by the trailing-language policy, and is not suppressed as a duplicate/noise case.
- Must not diagnose when: the mixed text is inside comments/strings, is an excluded technical name, only starts/ends with an allowed technical acronym part, or is owned by BSL256 typo detection policy.
- Diagnostic anchor token/range: the mixed-script word span.
- Quick-fix target, if any: rename the identifier or replace the accidental homoglyph.
