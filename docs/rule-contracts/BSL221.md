# BSL221 MultilingualStringHasAllDeclaredLanguages Contract

## Rule Identity

- Code: BSL221
- BSLLS compatible name: MultilingualStringHasAllDeclaredLanguages
- Rule status: implemented

## Standard And Product Decision

- Standard or product policy: `НСтр`/`NStr` literals in multilingual configurations should contain fragments for every declared language.
- Non-goals: Do not report `НСтр` calls inside `СтрШаблон`/`StrTemplate`; BSL222 owns template-parent cases.

## Semantic Oracle

- Checked language fact: A global `НСтр`/`NStr` call literal omits at least one configured declared language.
- Must diagnose when: `declaredLanguages` contains a language code missing from the NStr body.
- Must diagnose when: the NStr is a direct multilingual string call.
- Must not diagnose when: all declared languages are present.
- Must not diagnose when: the NStr call is an argument of `СтрШаблон`/`StrTemplate`; use BSL222 instead.
- Diagnostic anchor token/range: The `НСтр(...)`/`NStr(...)` call.

## CST Or Domain Fact Model

- CST/domain object types: NStr global-call fact, string body language fragments, declared language set.
- Extracted attributes: declared languages, present languages, parent template-call state, call range.
- Parse-error behavior: Do not report if the NStr call/string body cannot be parsed.
- Shared semantic object: Multilingual string literal.

## Examples

### Invalid Examples

1. `НСтр("en = 'Done'")` with declared languages `ru,en`.
2. `NStr("ru = 'Готово'")` with declared languages `ru,en`.
3. `НСтр("ru = 'Готово'; fr = 'Pret'")` with declared languages `ru,en,fr`.

### Valid Negative Twins

1. `НСтр("ru = 'Готово'; en = 'Done'")` with declared languages `ru,en`.
2. `СтрШаблон("%1", НСтр("en = 'Done'"))` is BSL222, not BSL221.
3. `"НСтр(""en = 'Done'"")"` inside a string literal.
