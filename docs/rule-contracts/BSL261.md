## Standard And Product Decision

- Standard or product policy: `БезопасныйРежим()` / `SafeMode()` returns a nullable boolean-like value and must be compared explicitly when used in conditions or boolean expressions.
- Why this diagnostic exists: implicit truthiness in security-sensitive safe-mode checks can produce unsafe or unclear branching.
- Non-goals: do not diagnose explicit comparisons, assignments, standalone calls outside boolean context, comments, strings, or other safe-mode setter methods.
- Keep/drop decision: keep as a BSLLS-compatible security/correctness diagnostic.

## Semantic Oracle

- Checked language fact: a global `БезопасныйРежим()` / `SafeMode()` call is used as a boolean expression without explicit comparison.
- Must diagnose when: the call is the sole condition of `Если`/`ИначеЕсли`, is under unary `Не` / `Not`, or has a neighboring boolean operator `И` / `Или` / `And` / `Or` without the call being part of a comparison.
- Must not diagnose when: the call is compared explicitly with `Истина`, `Ложь`, `True`, `False`, or another expression, assigned to a variable, passed as an argument, appears in comments/strings, or is a different method such as `УстановитьБезопасныйРежим`.
- Diagnostic anchor token/range: `БезопасныйРежим` / `SafeMode` method name range.
- Quick-fix target, if any: add an explicit comparison, for example `БезопасныйРежим() = Истина` or `БезопасныйРежим() <> Ложь`, matching intended null semantics.

## Examples

### Invalid Examples

1. `Если БезопасныйРежим() Тогда`.
2. `Если Не БезопасныйРежим() Тогда`.
3. `Если БезопасныйРежим() И Флаг Тогда`.
4. `Если Флаг Или SafeMode() Тогда`.

### Valid Negative Twins

1. `Если БезопасныйРежим() = Истина Тогда`.
2. `Если БезопасныйРежим() <> Ложь И Флаг Тогда`.
3. `Значение = БезопасныйРежим()`.
4. `УстановитьБезопасныйРежим(Истина)`.

### Edge Examples

- Comments: comments must not produce SafeMode call facts.
- Strings: string literals must not produce SafeMode call facts.
- Preprocessor: no special handling beyond parsed CST statements.
- Multiline: boolean expressions may span lines; CST expression ancestry is the source of truth.
- Nested constructs: nested condition expressions are checked by the same method-call facts.
- BSL/SDBL variants, if relevant: SDBL is not relevant.
