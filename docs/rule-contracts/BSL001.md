# BSL001 ParseError Contract

## Rule Identity

- Code: BSL001
- BSLLS compatible name: ParseError
- Public name/i18n key: ParseError / BSL001
- Default message/i18n key: parser error text or file-read failure
- Description/i18n key: RULE_METADATA["BSL001"].description
- Severity: ERROR
- Parameters/defaults: none.
- Rule status: verified

## Standard And Product Decision

- Standard or product policy: source modules must be readable and syntactically valid BSL.
- Why this diagnostic exists: later semantic diagnostics cannot reliably interpret an unreadable or malformed module.
- Non-goals: style, deprecated API, semantic correctness, and parser-recovery artifacts in otherwise supported valid syntax.
- Keep/drop decision: keep as the syntax and source-readability boundary.

## Semantic Oracle

- Checked language fact: the source cannot be read or the BSL CST contains a real parser error.
- Must diagnose when: the file is unreadable, a required syntax token is missing, or malformed source produces a trusted CST error node.
- Must not diagnose when: valid BSL uses supported properties, literals, directives, long headers, or grammar recovery without a real syntax defect.
- Diagnostic anchor token/range: unreadable files anchor at the start; parser errors use the CST error or missing-token range.
- Quick-fix target, if any: none; the user must repair the malformed source or file access.

## CST Or Domain Fact Model

- Parser/tree source: tree-sitter BSL CST plus the source file read boundary.
- CST/domain object types: CST `ERROR` and missing nodes, parser root, and file-read exception.
- Extracted attributes: node type, start/end points, missing/error state, parser message, and file path.
- Parse-error behavior: emit BSL001 for trusted error facts while suppressing known valid grammar-recovery shapes.
- Textual/regex behavior, only if genuinely textual: none; file-read failures are handled before parsing.

## Examples

### Invalid Examples

1. A procedure declaration with a missing closing parenthesis.
2. An unterminated string or block whose CST contains a trusted error node.
3. A requested source path that cannot be read.

### Valid Negative Twins

1. A valid call to `Окр()` with a precision argument.
2. A valid long function header and platform date literal.
3. A top-level region directive in a readable valid module.

### Edge Examples

- Comments: comment text that resembles broken code is ignored by the CST.
- Strings: complete string contents are not parsed as BSL statements.
- Preprocessor: valid region and conditional directives must not report.
- Multiline: valid multiline expressions and declarations must not report.
- Nested constructs: errors anchor to the innermost trusted CST error fact.
- BSL/SDBL variants, if relevant: embedded SDBL diagnostics are owned by query rules; BSL001 covers the host BSL syntax.

## Related-Rule Cluster

- Shared semantic object: parsed source document and CST error state.
- Rules that may report on the same object/range: all structural rules consume the same CST, but none owns syntax failures.
- Intended duplicate policy: emit one stable syntax diagnostic per trusted parser error and suppress dependent semantic noise where facts are unavailable.
- Cluster fixture or probe: `tests/test_diagnostics.py::TestBsl001SyntaxErrors`.

## Performance Contract

- Traversal/fact source: parser error-node collection during the existing CST traversal.
- Expected complexity: O(CST nodes) with no additional parse.
- Shared-pass reuse: the same parsed tree is reused by the diagnostic engine.
- Before/after measurement, if changed: no runtime change in this contract iteration.
