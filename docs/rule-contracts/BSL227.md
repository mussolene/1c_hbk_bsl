## Описание диагностики

Тексты модулей оформляются по принципу "один оператор в одной строке". Наличие нескольких операторов допускается только для "однотипных" операторов присваивания, например:

`НачальныйИндекс = 0; Индекс = 0; Результат = 0;`

## Источники

## Description

Module texts are formatted according to the "one statement in one line" principle. Several statements are acceptable in case of same-type assignment operators. For example:

`StartIndex = 0; Index = 0; Result = 0;`

## Standard And Product Decision

- Standard or product policy: module text should normally contain one statement per physical line; same-type compact assignment chains are a documented exception.
- Why this diagnostic exists: multiple unrelated statements on one line reduce readability and make diffs/debugging harder.
- Non-goals: formatting complete expressions, line wrapping, or flagging comments/strings containing semicolons.
- Keep/drop decision: keep as a BSLLS-compatible style/standard diagnostic.

## Semantic Oracle

- Checked language fact: a physical source line contains more than one top-level executable statement separated by semicolons.
- Must diagnose when: a line has multiple top-level statements, including compact statement after `Тогда` / `Then`.
- Must not diagnose when: semicolons appear inside strings/comments, nested parentheses, or the only extra token is `КонецЕсли` / `EndIf` closure.
- Diagnostic anchor token/range: each statement after the first statement on the same line.
- Quick-fix target, if any: split statements onto separate lines.

## CST Or Domain Fact Model

- Parser/tree source: physical source lines with string/comment masking.
- CST/domain object types: masked code line, top-level semicolon-delimited statement spans, and inline `Тогда` statement tail.
- Extracted attributes: statement start/end columns and parenthesis depth.
- Parse-error behavior: textual style scan can run without valid CST.
- Textual/regex behavior, only if genuinely textual: this rule is intentionally line-textual because the standard is about physical lines.

## Examples

### Invalid Examples

1. `А = 1; Сообщить(А);`
2. `Если Условие Тогда Сообщить("Да"); КонецЕсли;`
3. `Вызов1(); Вызов2();`

### Valid Negative Twins

1. `А = 1;\nСообщить(А);`
2. `НачальныйИндекс = 0; Индекс = 0; Результат = 0;`
3. `Сообщить("А; Б");`

### Edge Examples

- Comments: semicolons in comments are ignored.
- Strings: semicolons in strings are ignored.
- Preprocessor: preprocessor lines are skipped.
- Multiline: checked per physical line.
- Nested constructs: semicolons inside parenthesized expressions are ignored.
- BSL/SDBL variants, if relevant: query text is outside this rule.
