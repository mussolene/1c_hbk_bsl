## Описание диагностики

Запрещено хранить в коде:

* Пути к файлам и папкам (Windows, Unix)

Есть как минимум несколько способов правильного хранения такой информации:

* Хранение в константе.
* Хранение в регистре сведений.
* Хранение в отдельном модулей, в котором отключена проверка правила (не рекомендуется).
* Хранение в справочнике, узле плана обмена и т.д..

### Особенности

При поиске путей Windows / Unix происходит проверка и на URL в строке. Ключевые слова поиска URL:
* ``http``
* ``https``
* ``ftp``

## Примеры

Неправильно:

```bsl
КаталогОбмена = "c:/обмен/обменданными";
```

Правильно:

```bsl
КаталогОбмена = Константы.КаталогОбмена.Получить();
```

или

```bsl
КаталогОбмена = ОбменДаннымиПовтИсп.КаталогОбмена();
```

## Description

It's forbidden to store in code:

* Paths to files and folders (Windows, Unix)

There are several ways to correctly store this information:

* Store in Constants.
* Store in Information registers.
* Store in separate module, where this diagnostic is disabled (not recommended).
* Store in Catalog, Exchange plan node and etc.

### Nuances

When search for Windows / Unix  paths, also check for URL in a string. URL search keywords:
* ``http``
* ``https``
* ``ftp``

## Examples

Incorrect:

```bsl
EchangeFolder = "c:/exchange/dataexchange";
```

Correct:

```bsl
ExchangeFolder = Constants.ExchangeFolder.Get();
```

or

```bsl
ExchangeFolder = DataExchangeReuse.ExchangeFolder();
```

## Standard And Product Decision

- Standard or product policy: absolute file and directory paths are deployment data and must not be hardcoded in module code.
- Why this diagnostic exists: hardcoded paths make code environment-specific and can expose host layout assumptions.
- Non-goals: URLs, relative paths, dynamic path construction from configuration, network addresses, secrets, or arbitrary string literals.
- Keep/drop decision: keep as a BSLLS-compatible security/hardware-related diagnostic.

## Semantic Oracle

- Checked language fact: executable BSL code contains a double-quoted string literal whose content is an absolute Windows, Unix, UNC, home, or environment-variable file path.
- Must diagnose when: a non-comment source line contains a string literal matching one of the supported absolute path forms.
- Must not diagnose when: the literal is a URL, a relative path, a comment-only occurrence, or a dynamic value loaded from configuration.
- Diagnostic anchor token/range: the full double-quoted string literal containing the path.
- Quick-fix target, if any: move the path to configuration data such as a constant, information register, catalog, exchange-plan node, or reviewed suppressed module.

- Parser/tree source: line-domain scan over source lines with string/comment awareness.
- CST/domain object types: double-quoted BSL string literal spans and comment boundary state.
