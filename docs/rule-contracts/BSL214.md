## Rule Identity

- Code: BSL214
- BSLLS compatible name: MissingEventSubscriptionHandler
- Public name/i18n key: BSL214 / MissingEventSubscriptionHandler
- Default message/i18n key: RULE_MESSAGES_RU["BSL214"]

## Standard And Product Decision

- Standard or product policy: every event subscription must reference an existing exported handler method in a server common module.
- Why this diagnostic exists: broken event-subscription handlers fail at runtime and are configuration correctness defects.
- Non-goals: checking arbitrary common-module calls, scheduled job handlers, form event handlers, or handler parameter signatures.
- Keep/drop decision: keep as a BSLLS-compatible correctness diagnostic anchored on the session module.

## Semantic Oracle

- Checked language fact: an event subscription handler is empty, malformed, references a missing common module, references a non-server common module, references a missing method, or references a non-exported method.
- Must diagnose when: any event subscription in the configuration violates one of those handler requirements.
- Must not diagnose when: the handler points to an existing exported method of a server common module, or the current checked file is not the configuration session module.
- Diagnostic anchor token/range: metadata owner range at line 1, character 0 through character 9 of `Ext/SessionModule.bsl` when the first line is long enough; shorter first lines use their visible length with minimum 1.
- Quick-fix target, if any: fill or correct the event subscription handler, make the common module server-side, create the method, or export the method.

## CST Or Domain Fact Model

- Parser/tree source: Designer/EDT event subscription XML, common module XML, and common module BSL procedure/function definitions.
- CST/domain object types: `EventSubscriptions/*.xml`, `CommonModules/*.xml`, target common module `Ext/Module.bsl`.
- Extracted attributes: subscription name, handler path, module name, method name, common module server flag, all target method names, exported target method names.
- Parse-error behavior: unreadable/malformed XML without a valid handler is treated as invalid; malformed target module BSL with no exported method produces a missing/non-exported handler diagnostic.
- Textual/regex behavior, only if genuinely textual: XML tag extraction is textual because the existing metadata helper layer uses compact regex-based XML helpers for these rules.

## Examples

### Invalid Examples

1. An event subscription has an empty handler.
2. An event subscription references a missing common module.
3. An event subscription references an existing method that is not exported.

### Valid Negative Twins

1. An event subscription references `CommonModule.Target.Exists` where `Target` is server and `Exists` is exported.
2. A common module contains a private method that is not referenced by an event subscription.
3. A non-session module is checked while event subscriptions exist.

### Edge Examples

- Comments: BSL comments do not matter.
- Strings: BSL strings do not matter.
- Preprocessor: preprocessor directives do not matter.
- Multiline: XML formatting may span lines.
- Nested constructs: all event subscriptions in the configuration are checked from the session module.
- BSL/SDBL variants, if relevant: SDBL is not relevant.
