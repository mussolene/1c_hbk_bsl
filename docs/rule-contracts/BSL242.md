# BSL242 ScheduledJobHandler Contract

## Rule Identity

- Code: BSL242
- BSLLS compatible name: ScheduledJobHandler
- Public name/i18n key: ScheduledJobHandler / BSL242
- Default message/i18n key: RULE_MESSAGES_RU["BSL242"]
- Description/i18n key: RULE_METADATA["BSL242"].description
- Severity: ERROR
- Parameters/defaults: none
- Rule status: parity-classified

## Standard And Product Decision

- Standard or product policy: a scheduled job handler must reference an existing exported procedure or function of a non-global server common module.
- Why this diagnostic exists: invalid scheduled job handlers fail at runtime or silently do not execute the intended background work.
- Non-goals: do not validate arbitrary common modules that are not referenced by scheduled jobs, event subscription handlers, form handlers, local calls, or parameter value types for non-predefined jobs.
- Keep/drop decision: keep as a BSLLS-compatible metadata correctness diagnostic.

## Semantic Oracle

- Checked language fact: a scheduled job metadata object references a common-module handler path and that referenced handler satisfies scheduled-job requirements.
- Must diagnose when: the handler is empty or malformed, the referenced common module is missing, the referenced common module is not server-side, the referenced method is missing, the method is not exported, a predefined job handler has parameters, the handler body is empty, or more than one scheduled job references the same handler.
- Must not diagnose when: a common module is not referenced by any scheduled job, a non-predefined job handler has parameters, the referenced exported handler exists in a server common module and has a non-empty body, or a checked file is a split common-module fragment rather than the owner `Ext/Module.bsl`.
- Diagnostic anchor token/range: owner range on the referenced common module for metadata-level defects, or the handler method name range for method-level defects.
- Quick-fix target, if any: correct the scheduled job handler path, make the common module server-side, create/export the method, remove invalid predefined parameters, add a method body, or split duplicated handlers.

## CST Or Domain Fact Model

- Parser/tree source: Designer/EDT `ScheduledJobs/*.xml`, `CommonModules/*.xml`, and target common module BSL procedure/function definitions.
- CST/domain object types: scheduled job XML handler records, common module index entries, current common module `Ext/Module.bsl`, parsed `ProcInfo`.
- Extracted attributes: scheduled job name, handler path, module name, method name, predefined flag, common module server flag, procedure export flag, parameter count, optional parameter count, body emptiness, and duplicate handler key.
- Parse-error behavior: malformed target module BSL with no parsed matching method is treated as missing/non-exported handler; unreadable scheduled job XML produces no valid handler facts unless the handler tag can be extracted.
- Textual/regex behavior, only if genuinely textual: XML tag extraction uses existing compact XML helpers; BSL procedure facts come from the existing parser/snapshot path.

## Examples

### Invalid Examples

1. Scheduled job handler points to a missing common module.
2. Scheduled job handler points to an existing non-server common module.
3. Scheduled job handler points to an existing method that is not exported.
4. Predefined scheduled job handler has parameters.
5. Two scheduled jobs point to the same handler method.

### Valid Negative Twins

1. A client common module exists but no scheduled job references it.
2. A non-predefined scheduled job handler has parameters.
3. A scheduled job points to an exported non-empty method of a server common module.
4. A split common-module fragment is checked while the owner `Ext/Module.bsl` contains the handler.

### Edge Examples

- Comments: BSL comments do not make an empty handler body non-empty.
- Strings: BSL strings count as method body statements only through normal parsed procedure facts.
- Preprocessor: no special handling.
- Multiline: XML formatting may span lines; procedure signatures may be multiline through existing `ProcInfo`.
- Nested constructs: any non-comment/non-preprocessor statement inside the handler body makes it non-empty.
- BSL/SDBL variants, if relevant: SDBL is not relevant.

## Implementation Decision

- Change target: BSL242 branch in `query_metadata_rules.py`.
- Delta category fixed by this change: semantic mismatch where unreferenced non-server common modules were diagnosed even though BSL242 only applies to common modules referenced by scheduled jobs.
- Why not another layer: scheduled job handler mapping already exists; the missing guard is local to BSL242 emission.
- Rollback signal: unreferenced client modules report BSL242, referenced non-server modules stop reporting, or private parity returns ours-only client-module owner diagnostics.
