# BSL180 DisableSafeMode Contract

## Rule Identity

- Code: BSL180
- BSLLS compatible name: DisableSafeMode
- Public name/i18n key: BSL180 / DisableSafeMode
- Default message/i18n key: RULE_MESSAGES_RU["BSL180"]
- Description/i18n key: RULE_METADATA["BSL180"].description
- Severity: ERROR
- Parameters/defaults: none; BSLLS config can disable `DisableSafeMode`.
- Rule status: verified

## Standard And Product Decision

- Standard or product policy: application code must not disable safe mode for external code unless the dangerous operation is explicitly reviewed outside this generic diagnostic.
- Why this diagnostic exists: disabling safe mode can allow untrusted external code to execute destructive actions.
- Non-goals: safe literal calls, object/member calls, comments, strings, and proving that a variable value is safe.
- Keep/drop decision: keep as a BSLLS-compatible security diagnostic.

## Semantic Oracle

- Checked language fact: executable BSL code calls a global safe-mode setter in a mode that disables safe-mode control.
- Must diagnose when: `УстановитьБезопасныйРежим` / `SetSafeMode` is called with anything except literal `Истина`/`True`, or `УстановитьОтключениеБезопасногоРежима` / `SetSafeModeDisabled` is called with anything except literal `Ложь`/`False`.
- Must not diagnose when: safe literal values are used, the call is a member call, or the text is inside a string/comment.
- Diagnostic anchor token/range: unsafe setter method name.
- Quick-fix target, if any: remove the unsafe mode change or replace with the safe literal when semantically correct.

## CST Or Domain Fact Model

- Parser/tree source: masked source lines.
- CST/domain object types: textual global setter-call facts with `(?<!\\.)` member-call guard.
- Extracted attributes: method name, first argument text, and method-name range.
- Parse-error behavior: a clear global call spelling can still report; BSL001 owns malformed syntax.
- Textual/regex behavior, only if genuinely textual: regex is acceptable because the rule checks two exact global setter names and the first argument literal policy.
