# BSL218 MissingTemporaryFileDeletion Contract

## Rule Identity

- Code: BSL218
- BSLLS compatible name: MissingTemporaryFileDeletion
- Public name/i18n key: BSL218 / MissingTemporaryFileDeletion
- Default message/i18n key: RULE_MESSAGES_RU["BSL218"]
- Description/i18n key: RULE_METADATA["BSL218"].description
- Severity: ERROR
- Parameters/defaults: `searchDeleteFileMethod` default is represented by built-in delete/move method names.
- Rule status: verified

## Standard And Product Decision

- Standard or product policy: temporary files created by `ПолучитьИмяВременногоФайла` / `GetTempFileName` must be explicitly deleted or moved after use.
- Why this diagnostic exists: relying on platform cleanup can exhaust temporary storage and leave stale files.
- Non-goals: whole-program dataflow, custom deletion helper configuration beyond the built-in default set, or proving cleanup in unrelated branches.
- Keep/drop decision: keep as a resource-management diagnostic.

## Semantic Oracle

- Checked language fact: a temporary file name acquired in a code block is not passed later in the same block to a configured delete/move method.
- Must diagnose when: a bare temp-file-name call appears, or an assigned temp-file variable has no later `УдалитьФайлы` / `DeleteFiles` / async delete / `ПереместитьФайл` / `MoveFile` call with that same variable in the same code-block root.
- Must not diagnose when: the assigned variable is deleted or moved later in the same block, the call is not global, or the deletion exists only in another branch/scope.
- Diagnostic anchor token/range: the `ПолучитьИмяВременногоФайла` / `GetTempFileName` method call.
- Quick-fix target, if any: add deletion/move in the same cleanup scope, preferably with error handling.

## CST Or Domain Fact Model

- Parser/tree source: BSL CST `method_call`, assignment, routine, branch, loop, try, and source-file nodes.
- CST/domain object types: global method call facts, assignment ancestor, lvalue text, code-block roots, and delete/move call arguments.
- Extracted attributes: call name/range, assigned variable, containing code block, call order by line, delete/move method name, and argument expression text.
- Parse-error behavior: requires CST global call extraction; malformed files are not forced through textual fallback.
- Textual/regex behavior, only if genuinely textual: none for valid CST paths.

## Examples

### Invalid Examples

1. `ПолучитьИмяВременногоФайла(".xml");`
2. `Имя = ПолучитьИмяВременногоФайла(".xml");\nСообщить(Имя);`
3. `Если Условие Тогда\n    Имя = ПолучитьИмяВременногоФайла(".xml");\nКонецЕсли;\nУдалитьФайлы(Имя);`

### Valid Negative Twins

1. `Имя = ПолучитьИмяВременногоФайла(".xml");\nУдалитьФайлы(Имя);`
2. `Имя = GetTempFileName(".xml");\nDeleteFiles(Имя);`
3. `Имя = ПолучитьИмяВременногоФайла(".xml");\nПереместитьФайл(Имя, НовоеИмя);`

### Edge Examples

- Comments: ignored by CST call extraction.
- Strings: ignored by CST call extraction.
- Preprocessor: module-level source-file roots skip preprocessor nodes.
- Multiline: CST call/assignment ranges own multiline calls.
- Nested constructs: cleanup must be in the same branch/loop/try/routine code-block root after acquisition.
- BSL/SDBL variants, if relevant: query text is outside this rule.
