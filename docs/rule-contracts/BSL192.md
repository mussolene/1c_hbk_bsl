## Описание диагностики

В имени функции слово получить лишнее т.к. функция по определению возвращает значение.

## Примеры
```bsl
// Не правильно:
Функция ПолучитьИмяПоКоду()

// Правильно:
Функция ИмяПоКоду()
```

## Источники
* Источник: [Стандарт: Имена процедур и функций п 6.1](https://its.1c.ru/db/v8std#content:647:hdoc)

</div>

<div class="doc-lang doc-lang-en" markdown="1">

## Description

In the name of the function, the word get superfluous since function by definition returns a value.

## Examples
```bsl
// Incorrect:
Function GetNameByCode()

// Correct:
Function NameByCode()
```

## Sources
* Source: [Standard: Names of procedures and functions c 6.1 (RU)](https://its.1c.ru/db/v8std#content:647:hdoc)

## Standard And Product Decision

- Standard or product policy: function names should describe returned values without the redundant Russian verb prefix `Получить`.
- Why this diagnostic exists: `Получить*` function names add noise and duplicate the fact that functions return values.
- Non-goals: do not diagnose procedures; do not diagnose English `Get*` names because BSLLS only checks Russian `Получить.*`.
- Keep/drop decision: keep as a BSLLS-compatible naming diagnostic.

## Semantic Oracle

- Checked language fact: a function declaration name starts with `Получить`, case-insensitively.
- Must diagnose when: `proc.kind == "function"` and the function name matches `^Получить.*$`.
- Must not diagnose when: the routine is a procedure, the function name starts with English `Get`, the function name contains `Получить` after the first character, or the method declaration is not parsed.
- Diagnostic anchor token/range: function identifier token.
- Quick-fix target, if any: rename the function and update callers manually.

## CST Or Domain Fact Model

- Parser/tree source: `DocumentSnapshot.procedures` / `ProcInfo`, created from tree-sitter where available.
- CST/domain object types: function/procedure declaration and identifier span.
- Extracted attributes: routine kind, routine name, start line, identifier range.
- Parse-error behavior: only parsed procedure/function facts are checked; BSL001 owns syntax errors.
- Textual/regex behavior, only if genuinely textual: regex applies only to the already extracted function name, not to source text.
