# BSL172 DataExchangeLoading Contract

## Rule Identity

- Code: BSL172
- BSLLS compatible name: DataExchangeLoading
- Public name/i18n key: BSL172 / DataExchangeLoading
- Default message/i18n key: RULE_MESSAGES_RU["BSL172"] and RULE_MESSAGES_RU_FMT["BSL172"]
- Description/i18n key: RULE_METADATA["BSL172"].description
- Severity: ERROR
- Parameters/defaults: none.
- Rule status: verified

## Standard And Product Decision

- Standard or product policy: object write/delete handlers should guard data-exchange loading scenarios.
- Why this diagnostic exists: object event handlers can run during data exchange; missing `ОбменДанными.Загрузка` / `DataExchange.Load` checks may execute ordinary business logic during import/loading.
- Non-goals: unsupported module types, non-object event procedures, handlers that already return under an exchange-loading check, and syntax-error ownership.
- Keep/drop decision: keep as a BSLLS-compatible object-event safety diagnostic.

## Semantic Oracle

- Checked language fact: a supported object/record-set/value-manager module contains a write/delete event procedure that does not return under a data-exchange loading check.
- Must diagnose when: the file is `ObjectModule.bsl`, `RecordSetModule.bsl`, or `ValueManagerModule.bsl`; the procedure is `ПередЗаписью`/`BeforeWrite`, `ПриЗаписи`/`OnWrite`, `ПередУдалением`/`BeforeDelete`; and its body lacks an `Если ОбменДанными.Загрузка Тогда ... Возврат ... КонецЕсли` or English equivalent.
- Must not diagnose when: module type is unsupported, the procedure is not one of the supported handlers, or a data-exchange loading `if` branch contains a `Возврат`/`Return`.
- Diagnostic anchor token/range: handler procedure name.
- Quick-fix target, if any: add an early return under the data-exchange loading check.

## CST Or Domain Fact Model

- Parser/tree source: tree-sitter BSL procedure facts plus line-domain handler/body scan.
- CST/domain object types: `ProcInfo`, supported module path kind, handler procedure signature line, and handler body lines.
- Extracted attributes: procedure name/start/end, module path kind, data-exchange condition line, nested-if depth, and return presence in the checked branch.
- Parse-error behavior: use available procedure facts; malformed syntax is owned by BSL001.
- Textual/regex behavior, only if genuinely textual: current handler/body matching is line-based because the supported semantic surface is a narrow event-handler idiom.

## Examples

### Invalid Examples

1. `ПередЗаписью` in a record-set module with ordinary guard logic but no `ОбменДанными.Загрузка` check.
2. `BeforeWrite` in an object module without `DataExchange.Load` early return.
3. `ПередУдалением` in a supported module without the exchange-loading guard.

### Valid Negative Twins

1. `ПередЗаписью` begins with `Если ОбменДанными.Загрузка Тогда Возврат; КонецЕсли;`.
2. `BeforeWrite` begins with `If DataExchange.Load Then Return; EndIf;`.
3. A form module contains a same-named procedure; unsupported module type is skipped.

### Edge Examples

- Comments: commented exchange-loading text does not create a valid guard.
- Strings: string literals do not create a valid guard.
- Preprocessor: not a separate semantic target for this rule.
- Multiline: the exchange-loading guard may span multiple lines in the standard `if` block form.
- Nested constructs: nested `if` depth is tracked while looking for the return inside the exchange-loading branch.
- BSL/SDBL variants, if relevant: SDBL is not relevant.
