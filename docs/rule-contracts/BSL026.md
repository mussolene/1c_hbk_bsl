## Standard And Product Decision

- Standard or product policy: Module regions should group real code, not empty structural placeholders.
- Why this diagnostic exists: It removes empty structure that adds noise without behavior.
- Non-goals: Regions containing procedures/functions or meaningful code lines.
- Keep/drop decision: keep

## Semantic Oracle

- Checked language fact: A region contains no code between its opening and closing directives.
- Must diagnose when: A `RegionInfo` body has no code line matching the non-empty-region code predicate.
- Must not diagnose when: The region contains a procedure, function, assignment, statement, or other code.
- Diagnostic anchor token/range: the opening region directive line.
- Quick-fix target, if any: remove the empty region manually.

## CST Or Domain Fact Model

- Parser/tree source: `DocumentSnapshot.regions` and `empty_region_facts`.
- CST/domain object types: `RegionInfo`, body line range, non-empty code predicate.
- Extracted attributes: region start/end lines, region name, opening line range, code-presence flag.
- Parse-error behavior: skip missing region model facts; `BSL001` owns broken-document reporting.
- Textual/regex behavior, only if genuinely textual: region body emptiness uses textual code-line classification.

## Examples

### Invalid Examples

1. A region with only blank lines.
2. A region with only comments.
3. A region with only nested directives and no executable/declaration code.

### Valid Negative Twins

1. A region containing a procedure.
2. A region containing a function.
3. A region containing an executable statement.

### Edge Examples

- Comments: comments alone do not make a region non-empty.
- Strings: strings only matter when they are part of executable code.
- Preprocessor: preprocessor-only content does not stand in for code unless policy changes.
- Multiline: body lines are scanned across the whole region.
- Nested constructs: region body content is considered inside the region span.
- BSL/SDBL variants, if relevant: SDBL is not relevant.
