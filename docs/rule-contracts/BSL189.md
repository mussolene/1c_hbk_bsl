## Описание диагностики

Запрещено использовать имена объектов метаданных (и их реквизитов и табличных частей), которые применяются при именовании таблиц запросов (например Документ, Справочник).

Использование таких имен может приводить к ошибкам при исполнении запроса, а кроме того, затрудняют использование конструктора запросов и снижают наглядность текста запроса.

## Примеры

Плохое наименование
- `Справочник.Справочник`
- `Справочник.МойСправочник.Реквизит.Документ`
- `РегистрСведений.МойРегистрСведений.Измерение.Документы`

## Источники

* [Стандарт: Организация хранения данных. Имя, Синоним, Комментарий](https://its.1c.ru/db/v8std#content:474:hdoc:2.5)

## Description

It is forbidden to use the names of metadata objects (and their attributes and tabular sections), which are used when naming query tables (for example, Document, Catalog).

Using such names can lead to errors in the execution of the query, and also make it difficult to use the query designer and reduce the clarity of the query text.

## Examples

Wrong name
- `Catalog.Catalog`
- `Catalog.MyCatalog.Attribute.Document`
- `InformationRegister.MyRegister.Dimension.Documents`

## Sources

* [Standard: Organization of data storage (RU). Name, Synonym, Comment](https://its.1c.ru/db/v8std#content:474:hdoc:2.5)

## Standard And Product Decision

- Standard or product policy: metadata objects and storage fields must not use technical names reserved for query metadata namespaces such as `Справочник`, `Документ`, `РегистрСведений`, `Catalog`, or `Document`.
- Why this diagnostic exists: such names make query text ambiguous, interfere with query constructor readability, and may lead to query execution mistakes.
- Non-goals: checking synonyms, form controls, commands, local BSL variables, or arbitrary words outside metadata technical names.
- Keep/drop decision: keep, with BSLLS-compatible forbidden-name set.

## Semantic Oracle

- Checked language fact: a metadata object name or plain storage field name exactly matches a forbidden metadata namespace name, case-insensitively.
- Must diagnose when: the current metadata object name is forbidden, or one of its plain storage fields such as attribute, tabular section, tabular-section attribute, register dimension/resource/accounting flag, or enum value has a forbidden terminal name.
- Must not diagnose when: the name only contains a forbidden word as a substring, the member is not a storage field targeted by BSLLS, or no current metadata object context exists.
- Diagnostic anchor token/range: BSLLS anchors metadata diagnostics at line 1, character 0 through character 9 of the selected owner document; onec mirrors that owner-module range.
- Quick-fix target, if any: rename the metadata object or storage field.

## CST Or Domain Fact Model

- Parser/tree source: Designer/EDT metadata XML parsed through `crawl_config`.
- CST/domain object types: `MetaObject`, `MetaMember`, current module path context, metadata object XML.
- Extracted attributes: object name, object kind, member kind, terminal member name, parent kind, forbidden-name membership.
- Parse-error behavior: unreadable or missing XML produces no BSL189 diagnostics.
