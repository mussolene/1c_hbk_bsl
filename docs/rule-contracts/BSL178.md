## Настройка и подавление

Код `BSL###` - основной стабильный идентификатор. Совместимый псевдоним
принимается в `select`, `ignore` и совместимых блоковых комментариях.

```toml
[tool.onec-hbk-bsl]
select = ["BSL178"]
ignore = ["DeprecatedMethods8317"]
```

Все три семейства подавлений работают для текущей строки и диапазона.
Если открывающий комментарий стоит после кода, он действует только на
эту строку. Используйте любой один вариант:

- `noqa`:

```bsl
Значение = "пример";  // noqa: BSL178
```

- `bsl-disable` (совместимый вариант):

```bsl
Значение = "пример";  // bsl-disable: BSL178
```

- совместимый `BSLLS`-вариант:

```bsl
Значение = "пример";  // BSLLS:DeprecatedMethods8317-off
```

Если тот же открывающий комментарий стоит на отдельной строке, он
начинает диапазон. Закройте его парным маркером того же семейства:

```bsl
// noqa: BSL178
// код без этой диагностики
// noqa-enable: BSL178

// bsl-disable: BSL178
// код без этой диагностики
// bsl-enable: BSL178

// BSLLS:DeprecatedMethods8317-off
// код без этой диагностики
// BSLLS:DeprecatedMethods8317-on
```

Чтобы отключить правило до конца файла, не добавляйте закрывающий
`noqa-enable`, `bsl-enable` или `BSLLS:…-on`.

Открывающий и закрывающий маркеры должны принадлежать одному семейству.

## Configuration and suppression

`BSL###` is the primary stable identifier. The compatible alias is accepted
in `select`, `ignore`, and compatible block suppression comments.

```toml
[tool.onec-hbk-bsl]
select = ["BSL178"]
ignore = ["DeprecatedMethods8317"]
```

All three suppression families support both a current line and a range.
When an opening comment follows code, it affects only that line. Use any
one form:

- `noqa`:

```bsl
Value = "example";  // noqa: BSL178
```

- `bsl-disable`:

```bsl
Value = "example";  // bsl-disable: BSL178
```

- compatible `BSLLS` form:

```bsl
Value = "example";  // BSLLS:DeprecatedMethods8317-off
```

When the same opening comment is on a line by itself, it starts a range.
Close it with the matching marker from the same family:

```bsl
// noqa: BSL178
// code without this diagnostic
// noqa-enable: BSL178

// bsl-disable: BSL178
// code without this diagnostic
// bsl-enable: BSL178

// BSLLS:DeprecatedMethods8317-off
// code without this diagnostic
// BSLLS:DeprecatedMethods8317-on
```

To disable the rule until the end of the file, omit the closing
`noqa-enable`, `bsl-enable`, or `BSLLS:…-on` marker.

Opening and closing markers must belong to the same family.

## Описание диагностики

Проверяются глобальные вызовы `КраткоеПредставлениеОшибки`
(`BriefErrorDescription`), `ПодробноеПредставлениеОшибки` (`DetailErrorDescription`)
и `ПоказатьИнформациюОбОшибке` (`ShowErrorInfo`). Диагностика выделяет имя метода.
Вызовы через объект, строки и комментарии пропускаются.

Если в `Configuration.xml` найден `CompatibilityMode` или
`ConfigurationExtensionCompatibilityMode` ниже `Version8_3_17`, проверка
пропускается. При версии 8.3.17 и выше, а также при отсутствии найденного режима
совместимости проверка выполняется.

Например, `ПодробноеПредставлениеОшибки(ИнформацияОбОшибке())` вызывает диагностику
при применимом режиме совместимости; вызов через `ОбработкаОшибок` пропускается.

## Diagnostic description

The rule checks global calls to `BriefErrorDescription`, `DetailErrorDescription`,
and `ShowErrorInfo`, including their Russian aliases `КраткоеПредставлениеОшибки`,
`ПодробноеПредставлениеОшибки`, and `ПоказатьИнформациюОбОшибке`. It highlights
the method name. Object-qualified calls, strings, and comments are skipped.

If `Configuration.xml` contains `CompatibilityMode` or
`ConfigurationExtensionCompatibilityMode` below `Version8_3_17`, the check is
skipped. It runs for version 8.3.17 or later, and when no compatibility mode is
found.

For example, `DetailErrorDescription(ErrorInfo())` is reported when the
compatibility mode allows the check; an object-qualified call is skipped.
