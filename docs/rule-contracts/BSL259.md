## Rule Identity

- BSLLS compatible name: UnknownPreprocessorSymbol

- Default message/i18n key: RULE_MESSAGES_RU["BSL259"]

- Severity: WARNING
- Parameters/defaults: built-in allowed preprocessor symbols and logical keywords.
- Rule status: parity-classified

## Standard And Product Decision

- Standard or product policy: preprocessor conditions should use known platform preprocessor symbols and logical operators.
- Why this diagnostic exists: unknown symbols in `#Если` / `#If` conditions are usually typos or dead conditional code.
- Non-goals: normal identifiers in BSL code, known preprocessor symbols, logical keywords, comments, strings, and preprocessor directives without conditions.
- Keep/drop decision: keep as a BSLLS-compatible preprocessor correctness diagnostic.

## Semantic Oracle

- Checked language fact: a preprocessor `#Если` / `#If` expression contains an identifier that is neither an allowed platform symbol nor a logical keyword.
- Must diagnose when: a preprocessor condition references an unknown identifier.
- Must not diagnose when: the identifier is a known platform preprocessor symbol, a logical operator/boolean literal, or appears outside a preprocessor condition.
- Diagnostic anchor token/range: the unknown identifier token.
- Quick-fix target, if any: correct the symbol spelling or replace the condition.

## CST Or Domain Fact Model

- Parser/tree source: tree-sitter BSL CST through the light pool, with a fallback only when CST is unavailable.
- CST/domain object types: `preprocessor`, child `expression`, and identifier tokens.
- Extracted attributes: identifier text, allowed-symbol set membership, keyword set membership, and token range.
- Parse-error behavior: if CST is unavailable, a bounded line fallback scans `#Если` / `#If` condition text.
- Textual/regex behavior, only if genuinely textual: fallback is limited to preprocessor condition lines when no CST exists.
