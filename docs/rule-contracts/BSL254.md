# BSL254 TransferringParametersBetweenClientAndServer Contract

- Severity: WARNING
- Parameters/defaults: none.
- Rule status: verified

## Standard And Product Decision

- Standard or product policy: parameters transferred from client to server should avoid unnecessary copying and serialization cost.
- Why this diagnostic exists: server methods called from client context should mark incoming parameters as `Знач`/`Val` unless the parameter is intentionally rewritten inside the server method.
- Non-goals: reporting methods that are not called from client context, methods that are not server-context methods, already-by-value parameters, or parameters that are immediately reassigned locally.
- Keep/drop decision: keep as a BSLLS-compatible client/server performance and design diagnostic.

## Semantic Oracle

- Checked language fact: a server-context procedure or function has a parameter not declared `Знач`/`Val`, is called by a client-context method, and does not locally overwrite that parameter.
- Must diagnose when: a `&НаСервере` or `&НаСервереБезКонтекста` method with non-by-value parameters has at least one client-context caller in the symbol index and the parameter is not assigned in the method body.
- Must not diagnose when: no symbol index is available, no client caller exists, the method is not server-context, the parameter is already `Знач`/`Val`, the parameter is reassigned locally, or the syntax tree is invalid.
- Diagnostic anchor token/range: the parameter identifier in the server method declaration.
- Quick-fix target, if any: add `Знач`/`Val` to the parameter declaration when it is semantically safe.

## CST Or Domain Fact Model

- Parser/tree source: tree-sitter BSL CST, `ProcInfo`, procedure-node mapping from `DocumentSnapshot`, and `SymbolIndex` caller facts.
- CST/domain object types: `procedure_definition`, `function_definition`, compiler directives, `parameter`, `VAL_KEYWORD`, `assignment_statement`, and symbol-index caller rows.
- Extracted attributes: method execution context, parameter order/ranges, by-value parameter set, assigned parameter names, caller file/name/line, and caller execution context.
- Parse-error behavior: invalid trees are skipped; BSL001 owns syntax errors.
- Textual/regex behavior, only if genuinely textual: none for method and assignment facts; caller context is resolved from indexed source snapshots.

## Examples

### Invalid Examples

1. Client method calls `&НаСервере Процедура Сервер(Документ)` and `Документ` is not reassigned.
2. Client method calls `&НаСервереБезКонтекста Процедура Сервер(Документ)` and `Документ` is not `Знач`.
3. Multiline server signature has several non-by-value parameters called from client context.

### Valid Negative Twins

1. Server method has no client-context caller.
2. Parameter is already declared `Знач`.
3. Non-by-value parameter is locally reassigned before use.

### Edge Examples

- Comments: comments do not create caller, parameter, or assignment facts.
- Strings: call-looking text in strings does not create symbol-index caller facts.
- Preprocessor: compiler directives define the client/server context used by the rule.
- Multiline: parameter locations are reported on each parameter line.
- Nested constructs: assignments inside nested blocks of the same server method count as local reassignment.
- BSL/SDBL variants, if relevant: SDBL is not relevant.

## Implementation Decision

- Change target: BSL254 contract, audit state, and the shared parity harness for indexed diagnostics.
- Delta category fixed by this change: invalid zero onec-side parity caused by running BSL254 without a `SymbolIndex`.
- Why not another layer: current rule implementation already uses structured `ProcInfo`, compiler-context helpers, `SymbolIndex`, and CST assignment facts; the remaining high-volume delta is source-file identity/deduplication for EDT aggregate and split method files, which belongs in shared parity/source normalization rather than in BSL254 semantics.
- Rollback signal: BSL254 parity returns zero onec-side diagnostics with a populated indexed corpus, reports without a client caller, misses external indexed callers, reports reassigned parameters, loses multiline parameter locations, or contract validation fails.
