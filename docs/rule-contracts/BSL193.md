## Описание диагностики

Функция не должна иметь выходных параметров. Весь вывод должен быть в возвращаемом значении. Если нужно возвращать несколько значений следует использовать такие типы как Структура, Массив и т.д.

## Примеры

```bsl
// Не правильно:
URLСервиса = "";
ИмяПользователя = "";
ПарольПользователя = "";

ЗаполнитьПараметрыПодключения(URLСервиса, ИмяПользователя, Пароль);

// Правильно:
ПараметрыПодключения = НовыеПараметрыПодключения();
// Возвращаемое значение - Структура:
//     URLСервиса         - Строка
//     ИмяПользователя    - Строка
//     ПарольПользователя - Строка
```

## Description

The function must have no output parameters. All output must be in the return value. If you need to return multiple values, you should use such types as Structure, Array, etc.

## Examples

```bsl
// Incorrect:
ServiceURL = "";
UserName = "";
UserPassword = "";

FillConnectionParameters(ServiceURL, UserName, UserPassword);

// Correct:
ConnectionParameters = NewConnectionParameters();
// Returned value - Structure:
//     Service URL  - String
//     UserName     - String
//     UserPassword - String
```

## Standard And Product Decision

- Standard or product policy: function parameters should not be used as outgoing mutable values; functions should return values explicitly.
- Why this diagnostic exists: writing to a by-reference function parameter hides an extra output channel and makes call contracts harder to reason about.
- Non-goals: do not diagnose procedures; do not diagnose function parameters declared with `Знач` / `Val`; do not diagnose default values in a multiline function signature.
- Keep/drop decision: keep as a BSLLS-compatible function out-parameter diagnostic.

## Semantic Oracle

- Checked language fact: a function has a parameter not declared by value and that parameter is assigned as an lvalue in the function body.
- Must diagnose when: a non-`Знач` function parameter appears as the left side of an assignment in the executable body.
- Must not diagnose when: the routine is a procedure, the parameter is declared `Знач`, the apparent assignment is a default value in the signature, or the name appears only as a read.
- Diagnostic anchor token/range: the written lvalue occurrence in the function body.
- Quick-fix target, if any: replace the outgoing parameter with an explicit return value or refactor the procedure/function contract.

## CST Or Domain Fact Model

- Parser/tree source: `DocumentSnapshot.procedures` / `ProcInfo`, with body start derived after the full parameter list.
- CST/domain object types: function declaration, parameter list, by-value parameter modifier, body assignment lvalue.
- Extracted attributes: routine kind, params, val params, method body start/end, lvalue name/range.
- Parse-error behavior: only parsed procedure/function facts are checked; BSL001 owns syntax errors.
- Textual/regex behavior, only if genuinely textual: current implementation uses a line-level lvalue assignment regex inside the already delimited function body; it must not scan signature lines.

## Examples

### Invalid Examples

1. `Функция Тест(Параметр)` with `Параметр = 1;` in the body.
2. A multiline function whose non-value parameter is assigned after the signature.
3. A function where the first assignment to a non-value parameter is inside a branch.

### Valid Negative Twins

1. `Функция Тест(Знач Параметр)` with `Параметр = 1;`.
2. `Процедура Тест(Параметр)` with `Параметр = 1;`.
3. `Функция Тест(Параметр = Неопределено)` where the only `=` is the default value in the signature.

### Edge Examples

- Comments: ignored by line comment stripping.
- Strings: not lvalue positions.
- Preprocessor: active parsed body lines are checked by the same body range.
- Multiline: body scanning starts after the complete multiline signature.
- Nested constructs: assignments inside nested blocks of the same function count.
- BSL/SDBL variants, if relevant: query text is irrelevant.
