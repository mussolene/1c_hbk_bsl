# BSL275 WrongHttpServiceHandler Contract

## Rule Identity

- Code: BSL275
- BSLLS compatible name: WrongHttpServiceHandler
- Public name/i18n key: WrongHttpServiceHandler / BSL275
- Default message/i18n key: RULE_MESSAGES_RU["BSL275"]
- Description/i18n key: RULE_METADATA["BSL275"].description
- Severity: ERROR
- Parameters/defaults: none.
- Rule status: parity-classified

## Standard And Product Decision

- Standard or product policy: HTTP service method handlers declared in metadata must exist and have the required signature.
- Why this diagnostic exists: wrong handlers break HTTP service execution at runtime.
- Non-goals: non-HTTP-service modules, handlers not referenced by HTTP service XML, comments/strings.
- Keep/drop decision: keep as a BSLLS-compatible HTTP metadata correctness diagnostic.

## Semantic Oracle

- Checked language fact: HTTP service XML `<Handler>` references a missing handler or a handler with wrong parameter count.
- Must diagnose when: referenced handler is empty, missing, or exists with incompatible parameters.
- Must not diagnose when: handler exists with the expected single request parameter.
- Diagnostic anchor token/range: module line for missing handlers or handler method name for wrong signature.
- Quick-fix target, if any: create/fix the handler method or metadata reference.

## CST Or Domain Fact Model

- Parser/tree source: local HTTP service XML and module procedure model.
- CST/domain object types: XML handler entries, `ProcInfo` procedures.
- Extracted attributes: handler name, procedure existence, parameter count, module path kind, range.
- Parse-error behavior: missing procedure facts means missing/wrong handler as applicable.
- Textual/regex behavior, only if genuinely textual: XML tag extraction is bounded to metadata file text.

## Examples

### Invalid Examples

1. `<Handler>` is empty.
2. `<Handler>НеСуществует</Handler>`.
3. Handler exists but has two parameters.

### Valid Negative Twins

1. Handler exists with one parameter.
2. Same XML in non-HTTP-service module path.
3. Handler name appears only in a comment.

### Edge Examples

- Comments: module comments do not create procedures.
- Strings: strings do not create handlers.
- Preprocessor: no separate semantic target.
- Multiline: procedure signature model handles module lines.
- Nested constructs: handlers are top-level procedures.
- BSL/SDBL variants, if relevant: SDBL is not relevant.
