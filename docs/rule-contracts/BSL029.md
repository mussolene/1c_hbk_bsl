# BSL029 MagicNumber Contract

## Rule Identity

- Code: BSL029
- BSLLS compatible name: MagicNumber
- Public name/i18n key: BSL029 / MagicNumber
- Default message/i18n key: RULE_MESSAGES_RU["BSL029"]
- Description/i18n key: RULE_METADATA["BSL029"].description
- Severity: INFORMATION
- Parameters/defaults: `authorizedNumbers`, default `-1,0,1`; `allowMagicIndexes`, default `true` in BSLLS-compatible policy.
- Rule status: verified

## Standard And Product Decision

- Standard or product policy: unexplained numeric literals reduce readability; symbolic constants or named variables should explain their domain meaning.
- Why this diagnostic exists: arithmetic thresholds, limits, offsets, and call arguments should be named unless their meaning is conventional or structurally obvious.
- Non-goals: authorized numbers, simple index literals when magic indexes are allowed, comments, strings, query text, syntax-error ownership, and simple container data literals whose context is the structure/map data itself.
- Keep/drop decision: keep as a BSLLS-compatible readability diagnostic.

## Semantic Oracle

- Checked language fact: executable BSL code contains a numeric literal outside an allowed/exempt context.
- Must diagnose when: a parsed `number` token is not in the authorized set and participates in an expression where its business meaning is not structurally obvious, such as return expressions, binary expressions, call arguments, loop bound expressions, or nested constructor/call arguments.
- Must not diagnose when: the value is `0`, `1`, or `-1`; the token is inside a string/query literal; the number is a simple array/index access and magic indexes are allowed; the number is a default parameter value; the number is a simple structure/fixed-structure/map constructor or insert value/key allowed by the BSLLS exception; or the tree is invalid enough that BSL001 owns the syntax problem.
- Diagnostic anchor token/range: the numeric literal token itself, without the unary minus sign for binary-minus compatibility.
- Quick-fix target, if any: extract the literal to a named variable/constant or replace the expression with a named domain value.

## CST Or Domain Fact Model

- Parser/tree source: tree-sitter BSL CST.
- CST/domain object types: `number`, `expression`, `unary_expression`, `binary_expression`, `index`, `parameter`, `assignment_statement`, `property_access`, `call_expression`, `arguments`, and `new_expression`.
- Extracted attributes: literal text, signed literal value for authorization, numeric token range, expression ancestor, argument index, index/simple-number state, parameter-default ancestry, known local assignments to `Структура`/`ФиксированнаяСтруктура`/`Соответствие`, call receiver/method, and string ancestry.
- Parse-error behavior: invalid trees should not manufacture BSL029 semantic facts from recovery text; BSL001 owns malformed syntax.
- Textual/regex behavior, only if genuinely textual: none for valid CST paths.

## Examples

### Invalid Examples

1. `Возврат 42;`
2. `Возврат Длительность < 10 * 60 * 60;`
3. `Возврат Окр((Сумма - НДС) / Количество, 2);`

### Valid Negative Twins

1. `Если А = 0 Тогда Возврат 1; КонецЕсли;`
2. `Возврат Массив[2];`
3. `Структура.Вставить("Код", 42);`

### Edge Examples

- Comments: numeric text in comments is ignored.
- Strings: numeric text and format placeholders inside strings are ignored.
- Preprocessor: not a separate semantic target for this rule.
- Multiline: multiline string/query content is ignored, while real numeric call arguments after the string still use the numeric token range.
- Nested constructs: nested call/constructor arguments are diagnosed unless they are inside an allowed structure/map literal context.
- BSL/SDBL variants, if relevant: SDBL/query text is not a BSL029 target; query-specific rules own parsed query semantics.

## Implementation Decision

- Change target: shared BSLLS suppression parsing, BSL029 property-assignment exception, BSL029 contract, and audit state.
- Delta category fixed by this change: `config-or-suppression` for overlapping/whole-line BSLLS suppression comments and `semantic-mismatch` for over-broad property-assignment RHS suppression.
