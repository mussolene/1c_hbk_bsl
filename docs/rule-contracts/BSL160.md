## Описание диагностики

Общий модуль должен иметь хотя бы один экспортный метод, а также область "ПрограммныйИнтерфейс" или "СлужебныйПрограммныйИнтерфейс".

## Примеры

Неправильно

```Bsl
// начало модуля
Процедура Тест(А)
    А = А + 1;
КонецПроцедуры
// конец модуля
```

Правильно

```Bsl
// начало модуля
#Область СлужебныйПрограммныйИнтерфейс
Процедура Тест(А) Экспорт
    А = А + 1;
КонецПроцедуры
#КонецОбласти
// конец модуля
```

## Description

A common module must have at least one export method and region "Public" or "Internal".

## Examples

Incorrect

```bsl
// Start module
Procedure Test(A)
    A = A + 1;
EndProcedure
// End module
```

Correct

```bsl
// Start module
#Region Internal
Procedure Test(A) Export
    A = A + 1;
EndProcedure
#EndRegion
// End module
```

Source: [Standard: Module structure (RU)](https://its.1c.ru/db/v8std#content:455:hdoc)

## Standard And Product Decision

- Standard or product policy: a common module with procedures/functions should expose a clear public API region and exported methods when it is meant to be callable.
- Why this diagnostic exists: common modules without any exported methods or without an API/public-interface region are hard to consume and navigate consistently.
- Non-goals: non-common-module files, common modules without procedures/functions, missing XML metadata, common-module execution-context validity, and common-module naming.
- Keep/drop decision: keep as a BSLLS-compatible common-module structure diagnostic.

## Semantic Oracle

- Checked language fact: a common module has at least one procedure/function but either no exported procedure/function or no public API region.
- Must diagnose when: sibling common-module XML exists, procedure/function facts are present, and either no method is exported or no root region is named `ПрограммныйИнтерфейс`, `Public`, or `Internal`.
- Must not diagnose when: XML metadata is missing, there are no procedures/functions, at least one method is exported and an API region exists, or the file is not a common module.
- Diagnostic anchor token/range: the first non-empty/non-BOM line of the module file.
- Quick-fix target, if any: add an appropriate API/public region and export intended public methods.

## CST Or Domain Fact Model

- Parser/tree source: tree-sitter BSL CST for procedure/function facts, region extraction for module regions, and XML sibling lookup for common-module ownership.
- CST/domain object types: `ProcInfo`, `RegionInfo`, and common-module XML metadata path.
- Extracted attributes: common-module XML presence, region names, procedure/function export flags, and first non-empty module line range.
- Parse-error behavior: use available procedure/region facts; `BSL001` owns syntax errors.
- Textual/regex behavior, only if genuinely textual: API region name matching and XML sibling path lookup are textual conventions.

## Examples

### Invalid Examples

1. Common module with an exported procedure but only a non-API region.
2. Common module with a public API region but procedures/functions without `Экспорт`.
3. Common module with methods and no public/API region.

### Valid Negative Twins

1. Common module with `#Область ПрограммныйИнтерфейс` and an exported procedure.
2. Common module with `#Region Public` and an exported function.
3. File without common-module XML metadata.

### Edge Examples

- Comments: comments may be the diagnostic anchor when they are the first real module line; they do not create API regions by themselves.
- Strings: strings do not affect API-region or export detection.
- Preprocessor: not a separate semantic target for this rule.
- Multiline: procedure/function bodies may be multiline; only export flag and region membership matter.
- Nested constructs: root region names are used for API-region presence.
- BSL/SDBL variants, if relevant: SDBL is not relevant.
