## Описание диагностики

Использование ".Ссылка" к полю ссылочного типа приведет к неявному левому соединению с таблицей-источником данного поля,
при этом не несет никакой ценности, а только генерирует избыточную нагрузку на СУБД.
## Примеры

```bsl
Запрос.Текст = "ВЫБРАТЬ Файлы.Файл.Ссылка, // ошибка
   | Файлы.Файл
   | ИЗ
   | СлужебныеФайлы КАК Файлы";
```
## Источники

* Полезная информация: [Разыменование ссылочных полей составного типа в языке запросов](https://its.1c.ru/db/v8std/content/654/hdoc)

</div>

<div class="doc-lang doc-lang-en" markdown="1">

## Description

Using ".Ref" to a field of a reference type will result in an implicit left join with the source table of this field, and it has no value, but only generates excessive load on the DBMS.
## Examples

```bsl
Query.Text = "Select Files.File.Ref, // error
   | Files.File
   | From
   | InternalFiles AS Files";
```
## Sources

* Useful Information: [Dereferencing Complex Type Reference Fields in Query Language (RU)](https://its.1c.ru/db/v8std/content/654/hdoc)

## Rule Identity

- Code: BSL238
- BSLLS compatible name: RefOveruse
- Public name/i18n key: RefOveruse / BSL238
- Default message/i18n key: Избыточное использование "Ссылка" в запросе
- Description/i18n key: Overuse "Reference" in a query
- Severity: INFORMATION
- Parameters/defaults: none
- Rule status: parity-classified

## Standard And Product Decision

- Standard or product policy: in query text, dereferencing a reference-typed field through `.Ссылка` / `.Reference` is redundant and can force an implicit left join to the source table.
- Why this diagnostic exists: the extra dereference has no useful semantic value for the query result and can increase database workload.
- Non-goals: do not diagnose ordinary use of a table alias reference field such as `Таблица.Ссылка`, query source declarations, temp-table reference fields, tabular-section source reference fields, comments, string literals outside query text, or malformed query syntax handled by BSL235.
- Keep/drop decision: keep as a BSLLS-compatible performance/readability diagnostic.

## Semantic Oracle

- Checked language fact: SDBL query column expression containing a dotted access chain where a non-source reference-typed field is dereferenced through `Ссылка` / `Reference` / `Ref`.
- Must diagnose when: a selected query column or expression uses a dotted chain with at least three identifiers and a `Ссылка`/`Reference`/`Ref` part after the root alias, for example `Файлы.Файл.Ссылка` or `Таблица.Реквизит.Ссылка`.
- Must not diagnose when: the chain is a plain source reference field such as `Таблица.Ссылка`, the root alias is a simple temp/table source and the second part is `Ссылка`, the root alias points to a tabular-section source and the second part is `Ссылка`, the dotted name appears in a query source clause, or the query block has no recovered SDBL CST.
- Diagnostic anchor token/range: the whole redundant dotted column chain mapped back to the original BSL query text range.
- Quick-fix target, if any: remove the redundant `.Ссылка` part when it is the last dereference; no automatic fix is currently implemented.

## CST Or Domain Fact Model

- Parser/tree source: `SemanticFactSnapshot.queries`, populated once from
  `DocumentSnapshot.query_text_blocks` and tree-sitter SDBL CST.
- CST/domain object types: SDBL `dotted_identifier` candidates outside `from_clause`, source aliases from `query_source_uses`, and alias classification for simple sources and tabular-section sources.
- Extracted attributes: dotted identifier parts, candidate node range, nearest query scope, source alias, source name parts, temp/simple source alias marker, and tabular-section source alias marker.
- Parse-error behavior: structural BSL238 facts require a recovered SDBL root; malformed query text is primarily BSL235 territory.
- Textual/regex behavior, only if genuinely textual: none for valid SDBL CST.

## Examples

### Invalid Examples

1. `ВЫБРАТЬ Файлы.Файл.Ссылка ИЗ СлужебныеФайлы КАК Файлы`.
2. `ГДЕ Таблица.Реквизит.Ссылка ЕСТЬ НЕ NULL`.
3. `ВЫБРАТЬ Данные.Владелец.Reference.Code ИЗ Справочник.Тест КАК Данные`.

### Valid Negative Twins

1. `ВЫБРАТЬ Таблица.Ссылка ИЗ Справочник.Тест КАК Таблица`.
2. `ВЫБРАТЬ ВТ.Ссылка ИЗ ВТ КАК ВТ` where `ВТ` is a temporary/simple query source.
3. `ПО Документ.Ссылка = Товары.Ссылка.Дата` where `Товары` is a tabular-section source alias.

### Edge Examples

- Comments: query-line comments are ignored by query extraction and must not produce BSL238.
- Strings: ordinary BSL string literals that are not query text are out of scope.
- Preprocessor: no special handling; visible query text is checked.
- Multiline: multiline query literals map CST ranges back to original BSL lines.
- Nested constructs: query packages and nested query sources must keep source aliases scoped to the recovered SDBL query where possible.
- BSL/SDBL variants, if relevant: Russian and English reference spellings are supported; `Ref` is accepted as an implementation compatibility alias.

## Implementation Decision

- Change target: move the already-verified source-scope extraction to the
  shared SDBL helper and normalize its ranges as
  `QueryFact.redundant_reference_spans`; BSL238 consumes the immutable facts.
- Delta category fixed by this change: no semantic delta is intended; the
  classified scoped-alias behavior is preserved.
- Why not another layer: metadata lookup is not needed for BSL238, and
  `SemanticFactSnapshot` already owns shared immutable query facts.
- Rollback signal: targeted BSL238 tests fail, BSL236/BSL187 shared query metadata tests regress, or private parity grows beyond the classified final tail.
