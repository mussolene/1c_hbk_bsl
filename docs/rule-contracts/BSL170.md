## Standard And Product Decision

- Standard or product policy: compiler directives are intended for managed form modules and command modules; other modules should use preprocessor instructions when execution-side selection is needed.
- Why this diagnostic exists: a compiler directive in ordinary/global/object/manager/common code is redundant or misleading because the module execution context is already defined by the module kind.
- Non-goals: missing required directives in managed UI modules, validating the exact directive value, preprocessor instruction correctness, or parsing query text.
- Keep/drop decision: keep as a BSLLS-compatible redundant compiler directive diagnostic.

## Semantic Oracle

- Checked language fact: a method in a non-form/non-command module has a preceding compiler directive annotation.
- Must diagnose when: a procedure or function outside managed form and command modules has one or more immediately preceding `&...` compiler directive lines.
- Must not diagnose when: the method is in a managed form or command module, the file is a split module fragment, the file is a split form layout, or there is no method annotation.
- Diagnostic anchor token/range: the compiler directive line from `&` through the stripped directive text.
- Quick-fix target, if any: remove the compiler directive and, if needed, replace it with an appropriate preprocessor instruction.

## CST Or Domain Fact Model

- Parser/tree source: procedure facts and nearby source lines in the shared light-pool pass.

- Extracted attributes: method start line, immediately preceding annotation lines, module kind, form/command state, split-fragment state, directive column/range, and severity.
- Parse-error behavior: relies on extracted procedure facts; BSL001 owns malformed syntax.
- Textual/regex behavior, only if genuinely textual: path/module classification and annotation-line detection are textual/domain policy around structured method facts.

## Examples

### Invalid Examples

1. `&НаКлиенте` before a procedure in a manager module.
2. `&НаСервере` before a function in an object module.
3. `&НаСервереБезКонтекста` before a common-module method.

### Valid Negative Twins

1. `&НаКлиенте` before a managed form procedure.
2. `&НаСервере` before a command module handler.
3. A split module fragment containing a directive and method whose canonical sibling module owns the whole file.

### Edge Examples

- Comments: skipped while searching upward for annotations.
- Strings: ignored because method facts and annotation lines are used.
- Preprocessor: not a target for this rule.
- Multiline: directive diagnostics stay on the single annotation line.
- Nested constructs: not relevant; compiler directives attach to method declarations.
- BSL/SDBL variants, if relevant: query text is outside this rule.
