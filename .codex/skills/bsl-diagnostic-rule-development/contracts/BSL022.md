# BSL022 Contract

## Rule Identity

- Code: BSL022
- BSLLS compatible name: UsingModalWindows
- Public name/i18n key: BSL022 / UsingModalWindows
- Default message/i18n key: get_rule("BSL022").message
- Description/i18n key: RULE_METADATA["BSL022"].description
- Severity: WARNING
- Parameters/defaults: modal global method list
- Rule status: contracted

## Standard And Product Decision

- Standard or product policy: Managed UI code should avoid deprecated modal global methods and prefer asynchronous APIs.
- Why this diagnostic exists: It prevents modal UI behavior that blocks managed application workflows.
- Non-goals: Typical client command handlers explicitly exempted by product behavior and method names in comments or strings.
- Keep/drop decision: keep

## Semantic Oracle

- Checked language fact: A method call to a deprecated modal global method in executable code.
- Must diagnose when: The BSL CST contains a `method_call` to a modal global method outside exempted handler context.
- Must not diagnose when: The text is in comments/strings or the call is in an exempted typical client command handler.
- Diagnostic anchor token/range: the called method identifier.
- Quick-fix target, if any: replace with an asynchronous API manually.

## CST Or Domain Fact Model

- Parser/tree source: tree-sitter BSL CST through `_bsl022_modal_facts_from_tree`, with line fallback only when CST is unavailable.
- CST/domain object types: `method_call`, `identifier`, containing `ProcInfo`.
- Extracted attributes: method name, LSP range, containing procedure context, exempted-handler state.
- Parse-error behavior: use line fallback only when the tree is not usable; `BSL001` owns syntax errors.
- Textual/regex behavior, only if genuinely textual: fallback line scan is a degraded path for modal global method text.
