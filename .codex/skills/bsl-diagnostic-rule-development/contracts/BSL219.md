## Standard And Product Decision

- Standard or product policy: Module-level variables should have descriptions that explain their purpose.
- Why this diagnostic exists: It flags undocumented module-level `Перем` / `Var` declarations.
- Non-goals: Local procedure variables, variables with preceding descriptions, and variables with inline descriptions.
- Keep/drop decision: keep

## Semantic Oracle

- Checked language fact: A module-level variable declaration lacks an accepted description.
- Must diagnose when: A module-level `Перем` / `Var` declaration has no preceding, inline, or previous-inline variable description.
- Must not diagnose when: The declaration is inside a procedure/function or has an accepted description.
- Diagnostic anchor token/range: the declared variable names in the module-level declaration.
- Quick-fix target, if any: add a variable description comment manually.

## CST Or Domain Fact Model

- Parser/tree source: `DocumentSnapshot.module_variable_description_facts`.
- CST/domain object types: module-level clean code line, `ProcInfo` ranges, variable declaration match, description comment predicates.
- Extracted attributes: line index, names start, names end, procedure containment, description presence.
- Parse-error behavior: skip uncertain procedure containment when the procedure model is unavailable; `BSL001` owns syntax errors.
- Textual/regex behavior, only if genuinely textual: variable declaration and description comments are textual documentation conventions.

## Examples

### Invalid Examples

1. A module-level `Перем Имя;` declaration without description.
2. A module-level `Var Name;` declaration without description.
3. A module-level exported variable declaration without description.

### Valid Negative Twins

1. A module-level variable with a preceding description comment.
2. A module-level variable with an inline description.
3. A local variable declaration inside a procedure.

### Edge Examples

- Comments: description comments can satisfy the rule.
- Strings: strings are not variable declarations.
- Preprocessor: not a separate target.
- Multiline: declaration facts are anchored on the declaration line.
- Nested constructs: procedure/function ranges exclude local declarations.
- BSL/SDBL variants, if relevant: SDBL is not relevant.
