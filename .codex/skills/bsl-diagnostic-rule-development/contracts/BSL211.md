# BSL211 Contract

## Rule Identity

- Code: BSL211
- BSLLS compatible name: MetadataObjectNameLength
- Public name/i18n key: BSL211 / MetadataObjectNameLength
- Default message/i18n key: RULE_MESSAGES_RU["BSL211"]
- Description/i18n key: RULE_METADATA["BSL211"].description
- Severity: WARNING
- Parameters/defaults: `maxMetadataObjectNameLength=80` in BSLLS; onec currently uses the same fixed default threshold.
- Rule status: verified

## Standard And Product Decision

- Standard or product policy: metadata object names should not exceed the platform-compatible maximum name length of 80 characters.
- Why this diagnostic exists: overly long metadata object names reduce Designer/EDT compatibility and make exported configuration artifacts difficult to maintain.
- Non-goals: checking synonyms, BSL variable names, metadata child names, form item names, or query aliases.
- Keep/drop decision: keep as a BSLLS-compatible metadata diagnostic with the default 80-character threshold.

## Semantic Oracle

- Checked language fact: the current metadata object's technical name length is greater than 80 characters.
- Must diagnose when: the checked module belongs to a metadata object whose technical name contains 81 or more characters.
- Must not diagnose when: the name has exactly 80 characters or fewer, the current file has no metadata object context, or only a child/member name exceeds 80 characters.
- Diagnostic anchor token/range: metadata owner range at line 1, character 0 through character 9 of the checked module when the first line is long enough; shorter first lines use their visible length with minimum 1.
- Quick-fix target, if any: rename the metadata object to 80 characters or fewer.

## CST Or Domain Fact Model

- Parser/tree source: Designer/EDT metadata path context plus current `.bsl` module path.
- CST/domain object types: current module metadata context from `current_module_xml_context`, current object XML path from `current_object_xml_path`.
- Extracted attributes: metadata folder, object name, first module line for owner diagnostic range.
- Parse-error behavior: BSL parse errors do not affect this metadata rule; missing metadata context produces no diagnostic.
- Textual/regex behavior, only if genuinely textual: object-name length is a direct string-length check, not a BSL text regex.

## Examples

### Invalid Examples

1. A catalog whose technical name has 81 characters and whose manager module is checked.
2. An information register whose technical name has 81 characters and whose form module is checked.
3. A common module whose technical name has 81 characters and whose module is checked.

### Valid Negative Twins

1. A metadata object whose technical name has exactly 80 characters.
2. A metadata object whose technical name is short but a child attribute name has 81 characters.
3. A standalone `.bsl` file outside a configuration metadata folder.

### Edge Examples

- Comments: BSL comments do not matter.
- Strings: BSL strings do not matter.
- Preprocessor: preprocessor directives do not matter.
- Multiline: the diagnostic is independent of multiline BSL constructs.
- Nested constructs: child/member names are not BSL211 targets.
- BSL/SDBL variants, if relevant: SDBL is not relevant.
