# BSL011 Contract

## Rule Identity

- Code: BSL011
- BSLLS compatible name: CognitiveComplexity
- Public name/i18n key: BSL011 / CognitiveComplexity
- Default message/i18n key: get_rule("BSL011").message
- Description/i18n key: RULE_METADATA["BSL011"].description
- Severity: WARNING
- Parameters/defaults: max_cognitive_complexity / BSLLS `complexityThreshold=15`, `checkModuleBody=true`
- Rule status: parity-classified

## Standard And Product Decision

- Standard or product policy: Procedures and functions should stay readable enough that nested control flow and boolean logic can be reviewed safely. BSLLS public diagnostic catalog defines CognitiveComplexity as enabled by default, critical, defect-code diagnostic with `complexityThreshold=15` and `checkModuleBody=true`.
- Why this diagnostic exists: It flags methods whose cognitive complexity exceeds the configured threshold.
- Non-goals: Comments, strings, query text, and methods or module-body blocks below or equal to the threshold.
- Keep/drop decision: keep

## Semantic Oracle

- Checked language fact: A procedure, function, or module-body code block has cognitive complexity greater than `max_cognitive_complexity`.
- Must diagnose when: The computed cognitive metric for a method or module-body block exceeds the configured threshold.
- Must not diagnose when: The method or module-body block is at or below the threshold, or the apparent control-flow tokens appear only in comments, strings, or query text.
- Diagnostic anchor token/range: method name range for methods; first token of the module-body code block for module-level code.
- Quick-fix target, if any: none

## CST Or Domain Fact Model

- Parser/tree source: BSL `DocumentSnapshot.procedures`, cached `complexity_metrics_for_procs`, and `module_body_cognitive_complexity_facts`.
- CST/domain object types: `ProcInfo`, method body lines, module-body line ranges, control-flow and boolean operator tokens.
- Extracted attributes: method start line, header column, end line, module-body anchor token range, nesting level, boolean operators, ternary operations, and branch tokens.
- Parse-error behavior: skip missing procedure model facts; `BSL001` owns broken-document reporting.
- Textual/regex behavior, only if genuinely textual: lexical counting is used inside method body lines after comments and strings are masked.

## Examples

### Invalid Examples

1. A method with nested `Если` branches above the threshold.
2. A method with multiple loop and conditional branches above the threshold.
3. A method combining nested branches and boolean chains above the threshold.
4. A module-body code block with nested branches above the threshold.

### Valid Negative Twins

1. A flat method with one simple condition below the threshold.
2. A method whose branch-like words appear only in a string.
3. A method whose branch-like words appear only in comments.
4. A module-body comment whose branch-like words appear only in comments.

### Edge Examples

- Comments: excluded from metric counting.
- Strings: masked before token counting.
- Preprocessor: not a separate target; visible method and module-body lines are counted.
- Multiline: continued boolean expressions contribute to the same method or module-body metric.
- Nested constructs: nesting increases cognitive complexity.
- BSL/SDBL variants, if relevant: SDBL is not relevant.

## Implementation Decision

- Change target: `parse_suppressions`, BSLLS parity runner jar discovery, BSL011 suppression coverage, contract, and audit.
- Delta category fixed by this change: config/suppression false negatives caused by treating BSLLS `off` comments as open-ended line state after their matching `on`.
- Why not another layer: BSLLS applies suppression after diagnostics through `DiagnosticIgnoranceComputer`, so the shared suppression layer is the correct compatibility point for BSL011 and all other diagnostics.
- Rollback signal: contract validator fails, inline `noqa` behavior changes, trailing BSLLS `off` stops suppressing same-line diagnostics, or closed BSLLS `off/on` ranges suppress later diagnostics.
