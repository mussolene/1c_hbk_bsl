## Standard And Product Decision

- Standard or product policy: client-server common modules should be named so their mixed execution context is visible from the module name.
- Why this diagnostic exists: client-server common modules are callable from both sides; names without a client-server marker obscure the intended context.
- Non-goals: client-only modules covered by BSL162, global-client modules covered by BSL166, non-client-server modules, missing/unreadable XML, and other naming predicates.
- Keep/drop decision: keep as a BSLLS-compatible common-module naming diagnostic.

## Semantic Oracle

- Checked language fact: a common module is client-server and its metadata name does not contain a client-server marker.
- Must diagnose when: sibling common-module XML exists, execution-context predicates classify the module as client-server, and the module name does not contain `КлиентСервер` or `ClientServer`.
- Must not diagnose when: XML is missing/unreadable, the module is not client-server, or the name already contains an accepted client-server marker.
- Diagnostic anchor token/range: the first non-empty/non-BOM line of the module file.
- Quick-fix target, if any: rename the common module to include an accepted client-server marker.

## CST Or Domain Fact Model

- Parser/tree source: XML metadata for common-module flags/name; BSL text is used for the diagnostic anchor.
- CST/domain object types: common-module XML snapshot and first non-empty module line.
- Extracted attributes: module name, execution-context flags, computed client-server predicate, and anchor line range.
- Parse-error behavior: BSL parse errors do not affect this XML-driven naming rule.
- Textual/regex behavior, only if genuinely textual: XML tags and module-name token matching are textual metadata conventions.

## Examples

### Invalid Examples

1. Client-server common module named `ОбменДанными`.
2. Client-server common module named `Utilities`.
3. Client-server common module whose name contains `Клиент` but not `КлиентСервер`.

### Valid Negative Twins

1. Client-server common module named `ОбменДаннымиКлиентСервер`.
2. Client-server common module named `ClientServerUtilities`.
3. Client-only common module without `КлиентСервер`, because BSL162 owns client-only naming.

### Edge Examples

- Comments: comments may be the diagnostic anchor when they are the first real module line.
- Strings: BSL strings do not affect XML naming.
- Preprocessor: not a separate semantic target for this rule.
- Multiline: XML formatting may be multiline; tag extraction is fixed-tag based.
- Nested constructs: BSL procedures/functions do not affect this rule.
- BSL/SDBL variants, if relevant: SDBL is not relevant.
