## Standard And Product Decision

- Standard or product policy: source-code identifiers should avoid the Russian letter `ё` and use `е` for portability and consistency.
- Why this diagnostic exists: visually similar `е`/`ё` identifiers are hard to type/search consistently and can create avoidable naming friction.
- Non-goals: reporting natural-language comments, string literal contents, documentation text, or query text inside strings.
- Keep/drop decision: keep as a BSLLS-compatible style/convention diagnostic.

## Semantic Oracle

- Checked language fact: executable code contains an identifier-like token with `ё` / `Ё`.
- Must diagnose when: a code token outside comments and strings contains `ё` or `Ё`.
- Must not diagnose when: `ё` appears only in comments, string literals, or non-code text.
- Diagnostic anchor token/range: the full identifier-like token containing `ё` / `Ё`.
- Quick-fix target, if any: replace `ё` / `Ё` with `е` / `Е` in the identifier and all references.

## CST Or Domain Fact Model

- Parser/tree source: masked executable source lines.
- CST/domain object types: identifier-like text tokens after comment/string masking.

- Parse-error behavior: malformed syntax is not the target; BSL001 owns syntax errors.
