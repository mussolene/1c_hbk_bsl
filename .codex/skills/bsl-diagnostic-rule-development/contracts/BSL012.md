# BSL012 Contract

## Rule Identity

- Code: BSL012
- BSLLS compatible name: UsingHardcodeSecretInformation
- Public name/i18n key: BSL012 / UsingHardcodeSecretInformation
- Default message/i18n key: get_rule("BSL012").message
- Description/i18n key: RULE_METADATA["BSL012"].description
- Severity: ERROR
- Parameters/defaults: `searchWords=Пароль|Password` compatibility default.
- Rule status: implemented

## Standard And Product Decision

- Standard or product policy: Source code must not contain hardcoded credentials; BSLLS maps this rule to the configurable secret-name words used in variables, structures, and mappings.
- Why this diagnostic exists: It prevents accidental credential exposure and unsafe deployment practices.
- Non-goals: Comments, suppression-disabled lines, ordinary non-secret string literals, and non-default key names such as `token` unless configuration later extends `searchWords`.
- Keep/drop decision: keep

## Semantic Oracle

- Checked language fact: A structural assignment, property/index assignment, `Вставить`/`Insert` call, or container/connection constructor stores a non-empty string literal under a key/name matching default `searchWords`.
- Must diagnose when: The key/name exactly matches `Пароль` or `Password` and the assigned/stored value is a single non-empty string literal that is not all `*`.
- Must not diagnose when: The same text is in a comment, is suppressed, uses a non-default key/name, assigns a non-string expression, assigns an empty string, or assigns an all-asterisk masked value.
- Diagnostic anchor token/range: the enclosing assignment or statement range, matching the BSLLS visitor object.
- Quick-fix target, if any: none

## CST Or Domain Fact Model

- Parser/tree source: `DocumentSnapshot.hardcoded_credential_facts`.
- CST/domain object types: `assignment_statement`, `property_access`, `method_call`, `new_expression`, `arguments`, `expression`, `string`, and `identifier`.
- Extracted attributes: structural key/name text, single-string value text, assignment/statement range.
- Parse-error behavior: structural security scan skips invalid CST; `BSL001` owns syntax errors.
- Textual/regex behavior, only if genuinely textual: regex is limited to the configured key/name predicate and masked-value predicate after CST facts are extracted.

## Examples

### Invalid Examples

1. `Пароль = "12345";`.
2. `Структура.Вставить("Пароль", "12345");`.
3. `Структура = Новый Структура("Пароль", "12345");`.

### Valid Negative Twins

1. A full-line comment mentions a password word.
2. `token = "12345";` does not match default `searchWords`.
3. `Пароль = "**********";` is a masked placeholder.

### Edge Examples

- Comments: comments are ignored by CST structural extraction.
- Strings: only a single string literal value is reported; ordinary string content is not scanned.
- Preprocessor: not a separate target.
- Multiline: each line is scanned independently.
- Nested constructs: not relevant.
- BSL/SDBL variants, if relevant: SDBL is not relevant.
