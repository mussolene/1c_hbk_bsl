## Standard And Product Decision

- Standard or product policy: `ОтменитьТранзакцию()` / `RollbackTransaction()` should be used inside an exception block and be the first call in that block.
- Why this diagnostic exists: rollback outside the correct exception flow can corrupt transaction handling.
- Non-goals: commit/begin transaction checks owned by other rules, comments, strings.
- Keep/drop decision: keep as a BSLLS-compatible transaction correctness diagnostic.

## Semantic Oracle

- Checked language fact: a rollback transaction call is outside an exception block or not the first call in the exception block.
- Must diagnose when: rollback is not in `Исключение` / `Except`, or another call precedes it in the exception block.
- Must not diagnose when: rollback is the first call in the exception block.
- Diagnostic anchor token/range: rollback call expression.
- Quick-fix target, if any: move rollback to the first operation in the exception block.

## Examples

### Invalid Examples

1. `ОтменитьТранзакцию();` outside try/exception.
2. Exception block calls `Сообщить()` before rollback.
3. `RollbackTransaction()` outside `Except`.

### Valid Negative Twins

1. Exception block starts with `ОтменитьТранзакцию();`.
2. Exception block starts with `RollbackTransaction();`.
3. `"ОтменитьТранзакцию()"` inside a string.

### Edge Examples

- Comments: ignored by CST.
- Strings: ignored by CST.
- Preprocessor: no separate semantic target.
- Multiline: call range from runtime call facts.
- Nested constructs: call ordering is evaluated inside exception block roots.
- BSL/SDBL variants, if relevant: SDBL is not relevant.
