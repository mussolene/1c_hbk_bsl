# BSL031 NumberOfParams Contract

## Rule Identity

- Code: BSL031
- BSLLS compatible name: NumberOfParams
- Public name/i18n key: NumberOfParams / BSL031
- Default message/i18n key: RULE_MESSAGES_RU["BSL031"]

- Severity: WARNING
- Parameters/defaults: max_params / default 7.
- Rule status: parity-classified

## Standard And Product Decision

- Standard or product policy: methods should not expose parameter lists so large that call sites and documentation become hard to audit.
- Why this diagnostic exists: too many parameters usually indicates a method doing too much or a missing parameter object/structure.
- Non-goals: do not diagnose optional-parameter count; BSL015 owns that. Do not diagnose parameter order; BSL228 owns ordering. Do not diagnose methods at or below the configured total-parameter threshold.
- Keep/drop decision: keep as a BSLLS-compatible method contract diagnostic.

## Semantic Oracle

- Checked language fact: one procedure or function has more parameters than `max_params`.
- Must diagnose when: total method parameter count is greater than the configured threshold.
- Must not diagnose when: total parameter count is less than or equal to the threshold, or parameter-like text is not part of a method signature.
- Diagnostic anchor token/range: the method parameter-list context, matching BSLLS `ParamListContext` range semantics.
- Quick-fix target, if any: none.

## CST Or Domain Fact Model

- Parser/tree source: `DocumentSnapshot.procedures` / `ProcInfo` extracted from tree-sitter method definitions.
- CST/domain object types: `parameters` node, child `parameter` nodes, `ProcInfo.params`, and `ProcedureModel`.
- Extracted attributes: method start/end line, first and last parameter ranges, total parameter count, configured threshold.
- Parse-error behavior: skip uncertain procedure containment when the procedure model is unavailable; BSL001 owns syntax errors.
- Textual/regex behavior, only if genuinely textual: fallback range logic is used only when CST parameter ranges are unavailable.

## Examples

### Invalid Examples

1. A method with eight parameters when `max_params=7`.
2. A multiline method signature with more than seven parameters.
3. A method with mixed required and optional parameters whose total parameter count exceeds the threshold.

### Valid Negative Twins

1. A method with exactly seven parameters when `max_params=7`.
2. A method with many optional-looking values in its body but a short signature.
3. Parameter-like text inside comments or strings rather than a method signature.

### Edge Examples

- Comments: ignored; comments are not parameters.
- Strings: ignored; strings are not parameters.
- Preprocessor: visible parsed method signatures are checked; inactive preprocessor branch handling is not owned by this rule.
- Multiline: diagnostic range spans from the first parameter token to the last parameter token, excluding standalone opening or closing parenthesis lines.
- Nested constructs: not relevant; only the method signature is checked.
- BSL/SDBL variants, if relevant: SDBL query text is not a target.
