## Standard And Product Decision

- Standard or product policy: service tags and generated-code placeholders should not remain in production comments.
- Why this diagnostic exists: tags such as TODO/FIXME/DEBUG or constructor placeholders indicate unfinished or temporary code.
- Non-goals: reporting arbitrary comments, service-tag-like text inside string literals, or tags outside the configured BSLLS-compatible list.
- Keep/drop decision: keep as a BSLLS-compatible convention/bad-practice diagnostic.

## Semantic Oracle

- Checked language fact: a source comment contains a configured service tag.
- Must diagnose when: a real line comment outside string literals contains one of the configured service-tag patterns.
- Must not diagnose when: the tag text is inside a string literal, the comment contains an unconfigured tag such as HACK, or the comment is ordinary text.
- Diagnostic anchor token/range: the full comment from `//` to the end of the physical line, matching BSLLS selection range.
- Quick-fix target, if any: remove the service tag by completing or deleting the temporary comment.

## CST Or Domain Fact Model

- Parser/tree source: line-domain scan using string-aware comment-start detection.
- CST/domain object types: physical source line, comment start outside strings, configured service-tag regex match.
- Extracted attributes: line number, comment start column, line end column, and matched service-tag pattern.
- Parse-error behavior: textual comment scan may run even with malformed code; BSL001 owns syntax-error diagnostics.
- Textual/regex behavior, only if genuinely textual: allowed. The diagnostic target is comment text and a configurable regex-like tag list.

## Examples

### Invalid Examples

1. A line comment with a fix marker: `// FIXME: баг с кодировкой`
2. A line comment with a debug marker: `// Отладка`
3. A generated handler placeholder: `// Вставить содержимое обработчика`

### Valid Negative Twins

1. `// HACK: временный обходной путь`
2. `// Обычный комментарий без тегов`
3. `Сообщение = "строка // FIXME: не комментарий";`

### Edge Examples

- Comments: real line comments are the only target.
- Strings: comment-looking text inside strings is ignored.
- Preprocessor: not a separate semantic target.
- Multiline: each physical comment line is checked independently.
- Nested constructs: irrelevant; comment text controls the rule.
- BSL/SDBL variants, if relevant: query text inside strings is outside this rule.
