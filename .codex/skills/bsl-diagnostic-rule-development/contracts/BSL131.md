# BSL131 Contract

## Rule Identity

- Code: BSL131
- BSLLS compatible name: DuplicateRegion
- Public name/i18n key: BSL131 / DuplicateRegion
- Default message/i18n key: get_rule("BSL131").message
- Description/i18n key: RULE_METADATA["BSL131"].description
- Severity: INFORMATION
- Parameters/defaults: normalized module-level region name
- Rule status: contracted

## Standard And Product Decision

- Standard or product policy: A module should not contain duplicate module-level regions with the same normalized name.
- Why this diagnostic exists: It keeps module structure unambiguous and avoids scattering the same logical section.
- Non-goals: Unique region names and nested regions with separate scopes.
- Keep/drop decision: keep

## Semantic Oracle

- Checked language fact: A module-level region name repeats after normalization.
- Must diagnose when: A later module-level `RegionInfo` has the same normalized name as a previous module-level region.
- Must not diagnose when: Region names are unique after normalization or the region is not module-level.
- Diagnostic anchor token/range: the duplicate region opening directive line.
- Quick-fix target, if any: merge or rename duplicate regions manually.

## CST Or Domain Fact Model

- Parser/tree source: `DocumentSnapshot.regions` and `duplicate_region_facts`.
- CST/domain object types: `RegionInfo`, module-level region list, normalized region key.
- Extracted attributes: region name, normalized key, start line, opening line indentation/range.
- Parse-error behavior: skip missing region model facts; `BSL001` owns broken-document reporting.
- Textual/regex behavior, only if genuinely textual: region name normalization is textual.

## Examples

### Invalid Examples

1. Two module-level regions named the same.
2. Two module-level regions differing only by normalizable formatting.
3. A third repeated module-level region after an earlier duplicate.

### Valid Negative Twins

1. Two differently named module-level regions.
2. A nested region with the same name in a different scope.
3. Region names that normalize to distinct keys.

### Edge Examples

- Comments: comments inside regions do not affect names.
- Strings: strings are not region directives.
- Preprocessor: not a separate target.
- Multiline: region directives are single-line facts.
- Nested constructs: only module-level duplicate names are checked.
- BSL/SDBL variants, if relevant: SDBL is not relevant.
