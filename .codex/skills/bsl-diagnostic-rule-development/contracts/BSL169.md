# BSL169 CompilationDirectiveLost Contract

## Rule Identity

- Code: BSL169
- BSLLS compatible name: CompilationDirectiveLost
- Public name/i18n key: BSL169 / CompilationDirectiveLost
- Default message/i18n key: RULE_MESSAGES_RU["BSL169"]
- Description/i18n key: RULE_METADATA["BSL169"].description
- Severity: ERROR
- Parameters/defaults: none.
- Rule status: verified

## Standard And Product Decision

- Standard or product policy: methods of managed forms and commands must have explicit compiler directives.
- Why this diagnostic exists: without a directive, execution side is ambiguous and managed UI code can behave unpredictably.
- Non-goals: ordinary forms, non-form/non-command modules, split form layouts, or reporting needless directives in ordinary modules.
- Keep/drop decision: keep as a BSLLS-compatible managed UI compilation directive diagnostic.

## Semantic Oracle

- Checked language fact: a method declaration in a managed form or command module has no immediately preceding compiler directive annotation.
- Must diagnose when: a managed form/command method has no `&...` annotation above it, ignoring blank/comment lines.
- Must not diagnose when: the method has a compiler directive, the module is an ordinary form, the module is not a form/command module, or the file belongs to a split form layout.
- Diagnostic anchor token/range: method name in the declaration line.
- Quick-fix target, if any: add the correct compiler directive such as `&НаКлиенте`, `&НаСервере`, or another platform-appropriate annotation.

## CST Or Domain Fact Model

- Parser/tree source: procedure facts and nearby source lines in the shared light-pool pass.
- CST/domain object types: `ProcInfo`, form/command module path classification, form XML managed/ordinary state, split form layout marker, annotation lines, and method name range.
- Extracted attributes: method start line/name, immediately preceding annotation list, module kind, form managed state, split layout state, source range, and severity.
- Parse-error behavior: relies on extracted procedure facts; BSL001 owns syntax errors.
- Textual/regex behavior, only if genuinely textual: path/module classification, XML managed-state probing, and annotation line detection are textual/domain policy around structured method facts.

## Examples

### Invalid Examples

1. `Процедура ПриСозданииНаСервере() КонецПроцедуры` in a managed form module.
2. `Функция Команда() Возврат Истина; КонецФункции` in a command module without annotation.
3. `Процедура Обработчик() КонецПроцедуры` in a managed form with no preceding `&...` directive.

### Valid Negative Twins

1. `&НаСервере\nПроцедура ПриСозданииНаСервере() КонецПроцедуры`
2. Ordinary form method without a compiler directive.
3. Split form layout file with `Module.header` marker.

### Edge Examples

- Comments: skipped while searching upward for an annotation.
- Strings: ignored because method facts and annotation lines are used.
- Preprocessor: not a separate target.
- Multiline: method name range comes from method declaration facts.
- Nested constructs: not relevant; compiler directives attach to method declarations.
- BSL/SDBL variants, if relevant: query text is outside this rule.
