# BSL256 Typo Contract

## Rule Identity

- Code: BSL256
- BSLLS compatible name: Typo
- Public name/i18n key: BSL256 / Typo
- Default message/i18n key: RULE_MESSAGES_RU["BSL256"]
- Description/i18n key: RULE_METADATA["BSL256"].description
- Severity: INFORMATION
- Parameters/defaults: BSLLS exposes `minWordLength=3`, `userWordsToIgnore=""`, and `caseInsensitive=false`; the local engine loads the bundled BSLLS Russian diagnostic exceptions and keeps local domain-token ignores.
- Rule status: verified

## Standard And Product Decision

- Standard or product policy: user-facing strings and selected code identifiers should not contain spelling mistakes.
- Why this diagnostic exists: typos in messages and names reduce UX quality and make code harder to search and maintain.
- Non-goals: exact reproduction of the BSLLS LanguageTool/EhCache backend, checking every identifier occurrence, checking generated API names, or treating mixed-script homoglyphs as typo facts.
- Keep/drop decision: keep as a BSLLS-compatible convention diagnostic with an intentionally local spelling backend.

## Semantic Oracle

- Checked language fact: a spelling candidate extracted from BSL strings or selected code-name positions contains a Russian word fragment that the spell backend classifies as suspicious.
- Must diagnose when: an extracted candidate part is not ignored by the BSLLS exception list, local domain-token ignore list, or mixed-script rules, and the spell backend reports it as misspelled.
- Must not diagnose when: the text is below the minimum word length, belongs to comments, is a known platform/domain token, is a multiline string token intentionally skipped by the BSLLS-shaped policy, or is owned by BSL208 mixed-script detection.
- Diagnostic anchor token/range: the spelling candidate range used by the local extractor; string candidates anchor to the enclosing string token for BSLLS-style messaging.
- Quick-fix target, if any: correct the word or add a reviewed project dictionary exception.

## CST Or Domain Fact Model

- Parser/tree source: tree-sitter BSL CST through `collect_spell_candidates`.
- CST/domain object types: string literal candidates, selected assignment/name candidates, and method/string fragments that are explicitly forced by the BSLLS-compatible typo token list.
- Extracted attributes: candidate kind, text, line/range, exact ignore set, split word fragments, normalized fragment, forced-token flag, and backend misspelling result.
- Parse-error behavior: malformed syntax is not the target; BSL001 owns syntax errors.
- Textual/regex behavior, only if genuinely textual: word splitting is textual after CST candidate extraction because typo detection is lexical text analysis.

## Examples

### Invalid Examples

1. `Сообщить("Атмена");`
2. `НаиболееПоздниееПодтверждение = 1;`
3. `Сообщить("Кор Рег Деб Сис Дис");`

### Valid Negative Twins

1. `Сообщить("Маркетплейсы и маркетплейсы");`
2. `Сообщить("ТестЭДО Тов Нал Прокси Токен Маппинг Парсинг Прослеживаемости");`
3. `ИмяNameПользователь = 1;` when BSL208 owns the mixed-script diagnostic.

### Edge Examples

- Comments: ignored by CST candidate extraction.
- Strings: checked as string candidates except multiline string tokens intentionally skipped by the local BSLLS-shaped policy.
- Preprocessor: not a separate semantic target.
- Multiline: multiline string tokens are skipped to avoid backend/range noise.
- Nested constructs: nesting is irrelevant after candidate extraction.
- BSL/SDBL variants, if relevant: query text is ordinary string text only; query semantics are not inspected.

## Related-Rule Cluster

- Shared semantic object: source text fragments in strings and code names.
- Rules that may report on the same object/range: BSL208 owns mixed Latin/Cyrillic identifiers, BSL035 owns duplicated string literals, BSL014 may report long lines, and BSL012 owns hardcoded secrets.
- Intended duplicate policy: BSL208 suppresses typo ownership for mixed-script facts; BSL256 emits at most one public diagnostic per structural spelling candidate because its public message and anchor do not distinguish individual words. It may coexist with string-value rules when it reports a different text quality issue.
- Cluster fixture or probe: `tests/test_bsl_typo_engine.py` and `tests/test_diagnostics_extended.py -k "bsl256 or typo"`.

## Performance Contract

- Traversal/fact source: CST candidate extraction plus cached spelling/morphology checks over normalized word fragments. Production diagnostics preselect code-name candidates from structural CST containers (`var_statement`, `var_definition`, `assignment_statement`) and then apply the same context predicates as the legacy identifier/property walk.
- Expected complexity: O(structural code-name candidates + string candidates + unique spell fragments) with local `lru_cache` spell results.
- Shared-pass reuse: BSL256 has a dedicated process-parallel path for large files and should not be merged into simple regex worker groups.
- Before/after measurement, if changed: the largest-file full-rule probe emitted 14,269 diagnostics, including 871 exact repeated BSL256 rows. After candidate-level normalization, a dedicated BSL256 production-path probe over the same 130,533-line file emitted 5,085 BSL256 diagnostics with zero exact duplicate rows in 6.464 seconds; candidate ownership and ranges remain covered by the existing fixtures.

## Implementation Decision

- Change target: normalize `SpellIssue` rows by structural candidate before conversion to diagnostics.
- Delta category fixed by this change: ours-only exact duplicate diagnostics from repeated equal or distinct suspicious fragments inside one whole-candidate anchor.
- Why not another layer: output-level diagnostic deduplication would hide repeated issue creation. Fragment-level diagnostics are not representable by the current public model because BSL256 exposes one generic message and anchors the whole structural candidate.
- Rollback signal: candidate ownership or ranges change, BSL208 mixed-script facts start emitting BSL256 duplicates, comments start reporting, known domain tokens report, multiline string tokens report, or targeted typo fixtures fail.
