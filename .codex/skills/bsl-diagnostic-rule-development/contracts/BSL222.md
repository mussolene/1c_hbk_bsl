## Standard And Product Decision

- Standard or product policy: localized `НСтр` values used as `СтрШаблон` templates must include all declared languages.
- Why this diagnostic exists: if `НСтр` lacks the active session language, it can return an empty string and make `СтрШаблон` fail at runtime.
- Non-goals: validating placeholder counts owned by BSL202, validating all `НСтр` calls outside `СтрШаблон`, or resolving dynamically computed localized strings.
- Keep/drop decision: keep as a localization correctness diagnostic.

## Semantic Oracle

- Checked language fact: a `СтрШаблон`/`StrTemplate` call uses `НСтр`/`NStr` text that does not cover all declared languages.
- Must diagnose when: an `НСтр`/`NStr` literal inside a `СтрШаблон`/`StrTemplate` call lacks at least one declared language.
- Must not diagnose when: the localized string covers all declared languages, the `НСтр` is not used as a template argument, or the template is dynamically computed beyond this rule's scope.
- Diagnostic anchor token/range: the localized string/call range used as the template argument.
- Quick-fix target, if any: add missing language fragments to the `НСтр` literal.

## Examples

### Invalid Examples

1. With declared `ru,en`: `СтрШаблон(НСтр("ru='Готово'"), Значение)`
2. With declared `ru`: `СтрШаблон(НСтр("en='Done'"), Значение)`
3. `StrTemplate(NStr("ru='Value %1'"), Value)`

### Valid Negative Twins

1. With declared `ru`: `СтрШаблон(НСтр("ru='Готово'"), Значение)`
2. `НСтр("en='Done'")` outside `СтрШаблон`
3. `СтрШаблон("%1", Значение)`
