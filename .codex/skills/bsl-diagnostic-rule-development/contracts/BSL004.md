# BSL004 EmptyCodeBlock Contract

## Rule Identity

- Code: BSL004
- BSLLS compatible name: EmptyCodeBlock
- Public name/i18n key: BSL004 / EmptyCodeBlock
- Default message/i18n key: RULE_MESSAGES_RU["BSL004"]
- Description/i18n key: RULE_METADATA["BSL004"].description
- Severity: WARNING in current emitted diagnostics; RULE_METADATA keeps `ERROR`.
- Parameters/defaults: BSLLS `commentAsCode=false`; comments do not make a block non-empty.
- Rule status: verified

## Standard And Product Decision

- Standard or product policy: empty executable control-flow blocks are suspicious and should be filled or removed.
- Why this diagnostic exists: an empty branch or loop often means deleted, unfinished, or accidentally skipped logic.
- Non-goals: empty exception handlers, standalone empty statements, or parse errors; those are owned by BSL028, BSL025, and BSL001 respectively.
- Keep/drop decision: keep as a BSLLS-compatible suspicious-code diagnostic.

## Semantic Oracle

- Checked language fact: a parsed control-flow branch or loop body has no executable statements.
- Must diagnose when: an `Если`/`ИначеЕсли`/`Иначе` branch or loop body contains only whitespace/comments before its terminator or next branch.
- Must not diagnose when: the block contains executable code, the empty block is an exception handler owned by BSL028, or an empty statement token is owned by BSL025.
- Diagnostic anchor token/range: opening branch/loop keyword or `Тогда` token for multiline conditions, matching current BSLLS ranges.
- Quick-fix target, if any: remove the block, add the missing implementation, or add explicit exception handling where appropriate.

## CST Or Domain Fact Model

- Parser/tree source: tree-sitter BSL CST through `diagnostics_bsl004_from_tree`.
- CST/domain object types: conditional branches, loop statements, and branch terminators.
- Extracted attributes: opener token/range, body statement presence, comment-only body state, terminator line, and severity.
- Parse-error behavior: avoid manufacturing facts from parse-error recovery; BSL001 owns syntax failures.
- Textual/regex behavior, only if genuinely textual: line checks are used to skip blanks/comments and identify branch terminators around CST-derived blocks.

## Examples

### Invalid Examples

1. `Если Условие Тогда КонецЕсли;`
2. `Если А Тогда Сообщить("A"); Иначе // пусто КонецЕсли;`
3. `Пока Условие Цикл КонецЦикла;`

### Valid Negative Twins

1. `Если Условие Тогда Сообщить("OK"); КонецЕсли;`
2. `Исключение` containing only a comment; BSL028 owns this case.
3. A block containing only `;`; BSL025 owns the empty statement token.

### Edge Examples

- Comments: ignored as code because `commentAsCode=false`.
- Strings: do not affect block emptiness unless they are executable statements.
- Preprocessor: ordinary CST parse behavior applies.
- Multiline: multiline `Если ... Тогда` anchors on the `Тогда` token when needed.
- Nested constructs: inner and outer blocks are evaluated by their own executable body facts.
- BSL/SDBL variants, if relevant: query text is outside this rule.
