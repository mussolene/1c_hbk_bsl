## Standard And Product Decision

- Standard or product policy: direct role checks through `РольДоступна` / `IsInRole` should be avoided for access-control decisions; prefer `ПравоДоступа` / `AccessRight`, BSP helpers, or combine role checks with privileged-mode checks for role-only flags.
- Why this diagnostic exists: role checks can be an incorrect proxy for actual object permissions.
- Non-goals: proving metadata rights, modeling BSP configuration, or diagnosing non-conditional helper wrappers.
- Keep/drop decision: keep as an access-control correctness diagnostic.

## Semantic Oracle

- Checked language fact: an `Если` / `If` condition checks `РольДоступна` / `IsInRole` without an accompanying `ПривилегированныйРежим` / `PrivilegedMode` check.
- Must diagnose when: a conditional expression directly calls role-check method, or uses a variable assigned from role-check method, and no privileged-mode call/variable is present later in the same condition.
- Must not diagnose when: the condition also checks privileged mode, the call is not a global method call, the text is inside comments/strings, or the role-check result is not used in a condition.
- Diagnostic anchor token/range: direct method call range or the role-check variable use range.
- Quick-fix target, if any: replace with an access-right check or add the appropriate privileged-mode condition when role-only semantics are intended.

## CST Or Domain Fact Model

- Parser/tree source: line-level conditional scan with string/comment masking.
- CST/domain object types: physical source line, assignment facts for role-check/privileged-mode variables, and `Если` / `If` condition expression text.
- Extracted attributes: role-check variables, privileged-mode variables, conditional expression, call range, and variable-use range.
- Parse-error behavior: textual conditional scan can run without a complete CST.
- Textual/regex behavior, only if genuinely textual: accepted here because the rule tracks simple global calls and same-module boolean variables in conditions.

## Examples

### Invalid Examples

1. `Если РольДоступна("Администратор") Тогда`
2. `Если IsInRole("Treasury") Then`
3. `ЕстьРоль = РольДоступна("Право");\nЕсли ЕстьРоль Тогда`

### Valid Negative Twins

1. `Если ПравоДоступа("Просмотр", Метаданные.Справочники.Номенклатура) Тогда`
2. `Если РольДоступна("Право") ИЛИ ПривилегированныйРежим() Тогда`
3. `ЕстьРоль = РольДоступна("Право");\nЕстьПривилегия = ПривилегированныйРежим();\nЕсли ЕстьРоль ИЛИ ЕстьПривилегия Тогда`

- BSL/SDBL variants, if relevant: query text is outside this rule.
