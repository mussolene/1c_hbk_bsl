# BSL174 Contract

## Rule Identity

- Code: BSL174
- BSLLS compatible name: DenyIncompleteValues
- Public name/i18n key: BSL174 / DenyIncompleteValues
- Default message/i18n key: RULE_MESSAGES_RU["BSL174"]
- Description/i18n key: RULE_METADATA["BSL174"].description
- Severity: WARNING
- Parameters/defaults: no user parameters
- Rule status: contracted

## Standard And Product Decision

- Standard or product policy: register dimensions that must be meaningful in database records should deny incomplete values through the platform metadata flag.
- Why this diagnostic exists: the platform can enforce non-empty register dimensions uniformly; otherwise empty dimension values may appear from UI or code paths and make register records ambiguous.
- Non-goals: deciding whether a business-specific dimension is allowed to be empty, inspecting query text, or proving runtime record writes are safe.
- Keep/drop decision: keep, with BSLLS-compatible metadata ownership.

## Semantic Oracle

- Checked language fact: a dimension of an information, accumulation, accounting, or calculation register has `DenyIncompleteValues` set to `false`.
- Must diagnose when: the current module is the diagnostic owner module for such a register and the register metadata XML contains a dimension whose `DenyIncompleteValues` flag is false.
- Must not diagnose when: the object is not one of the register kinds above, all dimensions deny incomplete values, the current module is a form module, or another module already owns the metadata diagnostic for the same register.
- Diagnostic anchor token/range: BSLLS anchors metadata diagnostics at the first line of the selected owner document; onec anchors line 1 from character 0 through the first line text.
- Quick-fix target, if any: set the register dimension metadata flag to deny incomplete values.

## CST Or Domain Fact Model

- Parser/tree source: EDT/designer metadata XML plus current module path context.
- CST/domain object types: register object XML, `Dimension` XML blocks, module path owner context.
- Extracted attributes: metadata folder, object name, dimension name, `DenyIncompleteValues` boolean flag, manager-module existence.
- Parse-error behavior: BSL parser errors do not affect this metadata rule; missing or unreadable XML produces no BSL174 diagnostics.
- Textual/regex behavior, only if genuinely textual: XML dimension blocks are read from metadata text with the existing shared XML helper regex.

## Examples

### Invalid Examples

1. `InformationRegisters/<Name>.xml` has a dimension with `<DenyIncompleteValues>false</DenyIncompleteValues>` and the checked file is `<Name>/Ext/ManagerModule.bsl`.
2. `AccumulationRegisters/<Name>.xml` has such a dimension and the checked file is the register owner manager module.
3. `AccountingRegisters/<Name>.xml` or `CalculationRegisters/<Name>.xml` has such a dimension and the checked file is the register owner manager module.

### Valid Negative Twins

1. A catalog XML contains a dimension-shaped block with `DenyIncompleteValues=false`.
2. A register dimension has `<DenyIncompleteValues>true</DenyIncompleteValues>`.
3. The same register has a manager module, but the checked file is `RecordSetModule.bsl` or a form module.

### Edge Examples

- Comments: BSL comments do not matter.
- Strings: BSL strings and query text do not matter.
- Preprocessor: preprocessor directives do not matter.
- Multiline: XML dimension blocks may span lines.
- Nested constructs: only metadata child dimensions of supported register objects are relevant.
- BSL/SDBL variants, if relevant: SDBL is not relevant; this rule is in the query-metadata batch only because it shares metadata scheduling infrastructure with query metadata rules.

## Implementation Decision

- Change target: `query_metadata_rules.py` BSL174 owner-module gate and synthetic coverage.
- Delta category fixed by this change: ours-only duplicate diagnostics on non-owner modules.
- Why not another layer: the rule already owns metadata eligibility in the query metadata pool; adding ownership there prevents unnecessary XML reads and preserves other metadata helpers.
- Rollback signal: manager modules stop reporting BSL174, non-register metadata reports BSL174, or preserved-source-root parity gains BSLLS-only ownership misses.
