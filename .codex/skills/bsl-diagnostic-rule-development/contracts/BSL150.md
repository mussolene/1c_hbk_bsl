## Standard And Product Decision

- Standard or product policy: teams may configure a regular expression for words that must not appear in module text.
- Why this diagnostic exists: configured prohibited words usually mark unacceptable vocabulary, temporary markers, or project-specific forbidden terminology.
- Non-goals: reporting anything when the configured pattern is empty, inventing a default forbidden-word list, or interpreting identifiers semantically.
- Keep/drop decision: keep as an optional BSLLS-compatible textual diagnostic.

- Must diagnose when: `badWords` is non-empty and matches a line segment that is eligible under `findInComments`.
- Must not diagnose when: `badWords` is empty, the match is inside a comment while `findInComments=false`, or no configured regex match exists.
- Diagnostic anchor token/range: the exact regex match span.
- Quick-fix target, if any: none.

- Nested constructs: irrelevant.
- BSL/SDBL variants, if relevant: query text inside strings is physical text for this rule.
