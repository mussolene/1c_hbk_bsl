# BSL014 Contract

## Rule Identity

- Code: BSL014
- BSLLS compatible name: LineLength
- Public name/i18n key: BSL014 / LineLength
- Default message/i18n key: get_rule("BSL014").message
- Description/i18n key: RULE_METADATA["BSL014"].description
- Severity: INFORMATION
- Parameters/defaults: max_line_length
- Rule status: contracted

## Standard And Product Decision

- Standard or product policy: Source lines should stay within the configured readable line length.
- Why this diagnostic exists: It improves readability and review ergonomics.
- Non-goals: Lines at or below the configured limit and multiline string/query content lines that start with `|`.
- Keep/drop decision: keep

## Semantic Oracle

- Checked language fact: A visible source line exceeds `max_line_length`.
- Must diagnose when: The reported visible line length is greater than the configured threshold.
- Must not diagnose when: The visible length is at or below the threshold or the line is multiline string/query content starting with `|`.
- Diagnostic anchor token/range: the full overlong line range from column 0 to reported visible length.
- Quick-fix target, if any: manual line wrap.

## CST Or Domain Fact Model

- Parser/tree source: `DocumentSnapshot.line_too_long_facts`.
- CST/domain object types: source line, reported visible length, multiline string/query content line.
- Extracted attributes: line index, reported visible length, configured maximum.
- Parse-error behavior: line-length rule can run without valid CST.
- Textual/regex behavior, only if genuinely textual: this is a textual formatting rule.

## Examples

### Invalid Examples

1. A BSL assignment line longer than `max_line_length`.
2. A method call line longer than `max_line_length`.
3. A comment or code line that is not covered by a multiline string/query exception and exceeds the limit.
4. A long single-line string literal source line.

### Valid Negative Twins

1. A line exactly at `max_line_length`.
2. A line shorter than `max_line_length`.
3. A query text line starting with `|`.
4. A non-keyword multiline string content line starting with `|`, even above the normal threshold.

### Edge Examples

- Comments: comments are checked unless excluded by a specific exception.
- Strings: long string lines are measured as visible source lines.
- Preprocessor: checked as text.
- Multiline: each physical line is checked independently.
- Nested constructs: not relevant.
- BSL/SDBL variants, if relevant: multiline query/string content lines starting with `|` are excluded from BSL014 and left to query/formatting rules.

## Implementation Decision

- Change target: `DocumentSnapshot.line_too_long_facts`, BSL014 contract, and synthetic coverage.
- Delta category fixed by this change: semantic-mismatch / onec-only multiline string/query content lines starting with `|`.
- Why not another layer: BSLLS `LineLength` is token-line based and does not report multiline string content lines; query/string content formatting belongs to query/formatting rules.
- Rollback signal: configured threshold is ignored, `|` multiline content lines report as BSL014, or contract validation fails.
