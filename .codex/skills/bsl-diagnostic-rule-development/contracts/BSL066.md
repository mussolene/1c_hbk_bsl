# BSL066 DeprecatedFind Contract

## Rule Identity

- Code: BSL066
- BSLLS compatible name: DeprecatedFind
- Public name/i18n key: BSL066 / DeprecatedFind
- Default message/i18n key: RULE_MESSAGES_RU["BSL066"]
- Description/i18n key: RULE_METADATA["BSL066"].description
- Severity: WARNING
- Parameters/defaults: none.
- Rule status: verified

## Standard And Product Decision

- Standard or product policy: the global string function `Найти` / `Find` is deprecated; use `СтрНайти` / `StrFind`.
- Why this diagnostic exists: deprecated platform APIs should be replaced with current equivalents for compatibility and clarity.
- Non-goals: object methods named `Найти`, methods such as `НайтиПоКоду`, modern `СтрНайти`, comments, strings, and unrelated deprecated APIs owned by other rules.
- Keep/drop decision: keep as a BSLLS-compatible deprecated API diagnostic.

## Semantic Oracle

- Checked language fact: executable BSL code calls the global method `Найти` / `Find`.
- Must diagnose when: a clean CST contains a global `method_call` whose identifier is exactly `Найти` or `Find`.
- Must not diagnose when: `Найти` is an object method call, part of a longer identifier, a user-defined method declaration, a comment/string token, or syntax-error recovery text.
- Diagnostic anchor token/range: the global call identifier token.
- Quick-fix target, if any: replace `Найти` with `СтрНайти` when the call is the deprecated string-search function.

## CST Or Domain Fact Model

- Parser/tree source: tree-sitter BSL CST and existing global-method-call extractor.
- CST/domain object types: `method_call`, `identifier`, global-call fact produced by `global_method_calls_from_nodes`.
- Extracted attributes: method call node, identifier text, global-vs-member-call classification, identifier range, and source line text for extractor filtering.
- Parse-error behavior: invalid CST should not produce BSL066 facts; BSL001 owns malformed syntax.
- Textual/regex behavior, only if genuinely textual: none for valid CST paths.

## Examples

### Invalid Examples

1. `Поз = Найти(Строка, "текст");`
2. `Pos = Find(Text, "x");`
3. `Если Найти(Сотрудник.Имя, "Борис") > 0 Тогда`

### Valid Negative Twins

1. `Поз = СтрНайти(Строка, "текст");`
2. `Элемент = МойМассив.Найти(Значение);`
3. `// Найти("текст");`

### Edge Examples

- Comments: commented calls are ignored.
- Strings: string text is ignored.
- Preprocessor: not a separate semantic target for this rule.
- Multiline: multiline call arguments do not change the identifier anchor.
- Nested constructs: nesting inside conditions/assignments does not change the rule.
- BSL/SDBL variants, if relevant: SDBL query text is not relevant.
