## Standard And Product Decision

- Standard or product policy: a function must return a value; otherwise it should be a procedure.
- Why this diagnostic exists: functions without `Возврат`/`Return` create unpredictable call behavior and usually indicate a wrong method kind.
- Non-goals: proving all paths return, checking returned primitive values, or reporting procedures that return values; those are owned by related rules.
- Keep/drop decision: keep as a BSLLS-compatible function-contract diagnostic.

## Semantic Oracle

- Checked language fact: a parsed function body contains no return statement.
- Must diagnose when: a procedure/function fact is a function and no `Возврат`/`Return` statement exists in its body.
- Must not diagnose when: the method is a procedure, the function has at least one return statement, or method facts are unavailable.
- Diagnostic anchor token/range: function name in the declaration line.
- Quick-fix target, if any: add a return statement or convert the function to a procedure.

## CST Or Domain Fact Model

- Parser/tree source: parsed procedure/function facts from the document model.
- CST/domain object types: `ProcedureModel`/`ProcInfo` with kind, start/end indices, and body lines.
- Extracted attributes: method kind, body line span, return-statement presence, function name span, and severity.
- Parse-error behavior: skip uncertain procedure containment when procedure facts are unavailable; BSL001 owns syntax errors.
- Textual/regex behavior, only if genuinely textual: return detection uses the canonical return-statement regex over the recovered function body lines.

## Examples

### Invalid Examples

1. `Функция Тест() А = 1; КонецФункции`
2. `Function Build() Value = 1; EndFunction`
3. `Функция ПолучитьЗначение() // only comments КонецФункции`

### Valid Negative Twins

1. `Функция Тест() Возврат 1; КонецФункции`
2. `Процедура Тест() А = 1; КонецПроцедуры`
3. `Function Build() Return Value; EndFunction`

### Edge Examples

- Comments: ignored as return statements.
- Strings: ignored as return statements.
- Preprocessor: ordinary procedure fact extraction applies.
- Multiline: function body lines are scanned across the recovered method span.
- Nested constructs: any return statement in the function body suppresses BSL032; BSL148 owns all-path return analysis.
- BSL/SDBL variants, if relevant: query text is outside this rule.
