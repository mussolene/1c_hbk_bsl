# BSL015 NumberOfOptionalParams Contract

## Rule Identity

- Code: BSL015
- BSLLS compatible name: NumberOfOptionalParams
- Public name/i18n key: NumberOfOptionalParams / BSL015
- Default message/i18n key: RULE_MESSAGES_RU["BSL015"]
- Description/i18n key: RULE_METADATA["BSL015"].description
- Severity: WARNING
- Parameters/defaults: max_optional_params / default 3.
- Rule status: parity-classified

## Standard And Product Decision

- Standard or product policy: methods should not expose too many optional parameters because large defaulted signatures are hard to call, test, and document correctly.
- Why this diagnostic exists: a high count of optional parameters usually indicates a method with too many responsibilities or an argument object missing from the design.
- Non-goals: do not diagnose total parameter count; BSL031 owns that. Do not diagnose parameter order; BSL228 owns ordering. Do not diagnose methods at or below the configured optional-parameter threshold.
- Keep/drop decision: keep as a BSLLS-compatible method contract diagnostic.

## Semantic Oracle

- Checked language fact: one procedure or function has more optional/defaulted parameters than `max_optional_params`.
- Must diagnose when: a method parameter list contains more than the configured number of parameters with default values.
- Must not diagnose when: optional parameter count is less than or equal to the threshold, or optional-looking text is not part of a method parameter list.
- Diagnostic anchor token/range: the method parameter-list context, matching BSLLS `ParamListContext` range semantics.
- Quick-fix target, if any: none.

## CST Or Domain Fact Model

- Parser/tree source: `DocumentSnapshot.procedures` / `ProcInfo` extracted from tree-sitter method definitions.
- CST/domain object types: `parameters` node, child `parameter` nodes, `ProcInfo.optional_count`, and `ProcedureModel`.
- Extracted attributes: method start/end line, first and last parameter ranges, optional parameter count, configured threshold.
- Parse-error behavior: skip uncertain procedure containment when the procedure model is unavailable; BSL001 owns syntax errors.
- Textual/regex behavior, only if genuinely textual: fallback range logic is used only when CST parameter ranges are unavailable.

## Examples

### Invalid Examples

1. A method with four optional parameters when `max_optional_params=3`.
2. A multiline method signature with four defaulted parameters.
3. A method with mixed required and optional parameters where optional parameters exceed the threshold.

### Valid Negative Twins

1. A method with exactly three optional parameters when `max_optional_params=3`.
2. A method with many required parameters but optional parameters at or below the threshold.
3. Default-looking text inside comments or method body strings rather than a method signature.

### Edge Examples

- Comments: ignored; comments are not parameters.
- Strings: ignored; strings are not parameters.
- Preprocessor: visible parsed method signatures are checked; inactive preprocessor branch handling is not owned by this rule.
- Multiline: diagnostic range spans from the first parameter token to the last parameter token, excluding standalone opening or closing parenthesis lines.
- Nested constructs: not relevant; only the method signature is checked.
- BSL/SDBL variants, if relevant: SDBL query text is not a target.
