## Standard And Product Decision

- Standard or product policy: Query result truncation with `ПЕРВЫЕ` / `TOP` should be deterministic; use `УПОРЯДОЧИТЬ ПО` / `ORDER BY` when limiting result rows.
- Why this diagnostic exists: It prevents unstable query results and performance-sensitive logic that depends on an undefined row order.
- Non-goals: Queries without `ПЕРВЫЕ` / `TOP`, ordered limited queries, SDBL parse-error blocks, and BSLLS-compatible `TOP 0` / `TOP 1` exceptions are not reported.
- Keep/drop decision: keep

## Semantic Oracle

- Checked language fact: An SDBL `top_clause` in a `select_section` whose owning `query` has no direct `order_by_clause` that makes the selected limited result deterministic.
- Must diagnose when: A query package contains `ВЫБРАТЬ ПЕРВЫЕ` / `SELECT TOP` without an applicable `УПОРЯДОЧИТЬ ПО` / `ORDER BY`.
- Must not diagnose when: The same query has an applicable direct order clause, the embedded SDBL block has parse errors, or the limited selection matches the documented small-limit compatibility exceptions.
- Diagnostic anchor token/range: the SDBL `top_clause` mapped back to the original BSL string-literal line and LSP character range.
- Quick-fix target, if any: none

## CST Or Domain Fact Model

- Parser/tree source: SDBL CST attached to `DocumentSnapshot.query_text_blocks`.
- CST/domain object types: SDBL `query`, `select_section`, `top_clause`, `order_by_clause`, `union_clause`, and `where_clause`.
- Extracted attributes: original BSL LSP position, top limit text, query-union flag, select-where flag, SDBL parse-error flag.
- Parse-error behavior: skip SDBL blocks with parser errors; broken query syntax is not repaired by this rule.
- Textual/regex behavior, only if genuinely textual: none for BSL077; query selection is derived from SDBL CST and original-position mapping.

## Examples

### Invalid Examples

1. `ВЫБРАТЬ ПЕРВЫЕ 1000` from a table without `УПОРЯДОЧИТЬ ПО`.
2. The first query in a query package uses `ПЕРВЫЕ`, while only a later package query is ordered.
3. A union query uses `ПЕРВЫЕ 1` without the compatible filtering exception.

### Valid Negative Twins

1. `ВЫБРАТЬ ПЕРВЫЕ 1000` followed by `УПОРЯДОЧИТЬ ПО` in the same query.
2. A query package where the limited query itself is ordered and later package queries are ordinary reads.
3. A BSLLS-compatible `ПЕРВЫЕ 1` union branch with a `ГДЕ` condition.

### Edge Examples

- Comments: query text extraction preserves SDBL content and ignores BSL comments outside query literals.
- Strings: only embedded query literal content is parsed as SDBL.
- Preprocessor: not a direct target; preprocessed BSL structure is outside BSL077.
- Multiline: original-position mapping anchors diagnostics back into multiline query literals.
- Nested constructs: nested SDBL sections are scoped to their owning `query`.
- BSL/SDBL variants, if relevant: Russian `ВЫБРАТЬ ПЕРВЫЕ` and English `SELECT TOP` are SDBL variants for the same fact.
