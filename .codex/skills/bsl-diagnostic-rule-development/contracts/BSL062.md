# BSL062 UnusedParameters Contract

## Rule Identity

- Code: BSL062
- BSLLS compatible name: UnusedParameters
- Public name/i18n key: UnusedParameters / BSL062
- Default message/i18n key: RULE_MESSAGES_RU["BSL062"]
- Description/i18n key: RULE_METADATA["BSL062"].description
- Severity: WARNING
- Parameters/defaults: none.
- Rule status: parity-classified

## Standard And Product Decision

- Standard or product policy: method signatures should not contain unused parameters unless the platform or framework requires the signature.
- Why this diagnostic exists: unused parameters make method contracts misleading and often show stale call patterns or incomplete refactoring.
- Non-goals: do not report local variables; BSL007 owns unused locals. Do not report parameters in empty/comment-only method bodies. Do not report `ПриСозданииОбъекта` / `OnObjectCreate` handler parameters.
- Keep/drop decision: keep as a BSLLS-compatible unused method-parameter diagnostic, with CST-based reference facts where available.

## Semantic Oracle

- Checked language fact: a procedure/function parameter has no identifier reference in its method body.
- Must diagnose when: a parsed method has a non-empty executable body and a parameter identifier does not appear as a body identifier.
- Must not diagnose when: the parameter is referenced in the method body, the method has no parameters, the method body is empty/comment-only, the method is `ПриСозданииОбъекта` / `OnObjectCreate`, or the file is an EDT split-method fragment skipped by this rule.
- Diagnostic anchor token/range: the unused parameter identifier token/range.
- Quick-fix target, if any: remove the unused parameter and update call sites manually.

## CST Or Domain Fact Model

- Parser/tree source: `DocumentSnapshot.procedures`, `ProcInfo.param_ranges`, `proc_node_map`, and tree-sitter identifier facts in the procedure body.
- CST/domain object types: `procedure_definition` / `function_definition`, `parameter` identifier nodes, body identifier nodes, and `ProcedureModel`.
- Extracted attributes: method name/kind/start/end, parameter names and ranges, method body identifier casefold set, split-fragment status.
- Parse-error behavior: if tree-sitter procedure body facts are unavailable, the rule falls back to textual body search through `ProcedureModel.validate_unused_parameters`; BSL001 owns syntax errors.
- Textual/regex behavior, only if genuinely textual: fallback body search is compatibility-only; clean tree-sitter files use CST identifier facts to avoid comments/strings false reads.

## Examples

### Invalid Examples

1. `Процедура Тест(НеИспользуемый)` with a non-empty body that does not reference `НеИспользуемый`.
2. A method with an unused optional parameter.
3. A client command handler whose standard-looking parameters are not referenced; BSLLS reports them.

### Valid Negative Twins

1. A parameter referenced in an expression inside the method body.
2. `ПриСозданииОбъекта(Параметр)`; BSLLS handler exception.
3. A method with only comments in the body.

### Edge Examples

- Comments: parameter mentions in comments do not count as usage on tree-sitter path.
- Strings: parameter mentions in strings do not count as usage on tree-sitter path.
- Preprocessor: visible parsed method bodies are checked; inactive preprocessor branch handling is not owned by this rule.
- Multiline: multiline signatures use `ProcInfo.param_ranges` for exact parameter anchors.
- Nested constructs: references inside nested blocks within the method body count as usage.
- BSL/SDBL variants, if relevant: query text is not a parameter-reference target unless the parameter is referenced by BSL code outside the query literal.

- Traversal/fact source: existing procedure model and cached tree-sitter procedure node map.
- Expected complexity: O(method parameters + body identifiers).
- Shared-pass reuse: shares `ProcInfo` parameter ranges with BSL015/BSL031; body identifier collection is lazy and limited to parameter-name candidates.
- Before/after measurement, if changed: compare the same full-rule `largest5` run and require an unchanged diagnostic count; report controlled old/new timings separately from noisy background-loaded runs.

## Implementation Decision

- Change target: BSL062 body-identifier fact construction only; semantic validation and ranges remain in `ProcedureModel`.
- Delta category fixed by this change: performance-only; skip body fact construction when the existing applicability gate rejects the method and stop traversal once all parameter candidates are found.
- Why not another layer: the waste is local to the BSL062 fact request; changing global CST indexing would retain the unnecessary per-method identifier decoding.
- Rollback signal: targeted BSL062 tests fail, contract validation fails, or a working BSLLS runtime later produces unclassified BSL062 semantic deltas.
