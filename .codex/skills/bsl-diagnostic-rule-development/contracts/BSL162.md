## Standard And Product Decision

- Standard or product policy: client common modules should be named so their client-side execution context is visible from the module name.
- Why this diagnostic exists: common-module availability is encoded in metadata; names without a client marker obscure where the module is intended to run.
- Non-goals: global client common modules covered by BSL166, client-server modules covered by BSL163, non-client modules, missing/unreadable XML, and other naming predicates.
- Keep/drop decision: keep as a BSLLS-compatible common-module naming diagnostic.

## Semantic Oracle

- Checked language fact: a non-global common module is client-only and its metadata name does not contain a client marker.
- Must diagnose when: sibling common-module XML exists, execution-context predicates classify the module as client, `Global` is false, and the module name does not contain `Клиент` or `Client`.
- Must not diagnose when: XML is missing/unreadable, the module is not client-only, the module is global, or the name already contains an accepted client marker.
- Diagnostic anchor token/range: the first non-empty/non-BOM line of the module file.
- Quick-fix target, if any: rename the common module to include an accepted client marker.

## CST Or Domain Fact Model

- Parser/tree source: XML metadata for common-module flags/name; BSL text is used for the diagnostic anchor.
- CST/domain object types: common-module XML snapshot and first non-empty module line.
- Extracted attributes: module name, `Global`, execution-context flags, computed client predicate, and anchor line range.
- Parse-error behavior: BSL parse errors do not affect this XML-driven naming rule.
- Textual/regex behavior, only if genuinely textual: XML tags and module-name token matching are textual metadata conventions.

## Examples

### Invalid Examples

1. Non-global client common module named `ОбменДанными`.
2. Non-global client common module named `Utilities`.
3. Client common module whose name contains neither `Клиент` nor `Client`.

### Valid Negative Twins

1. Non-global client common module named `ОбменДаннымиКлиент`.
2. Non-global client common module named `ClientUtilities`.
3. Global client common module without `Клиент`, because BSL166 owns the global-client naming case.

### Edge Examples

- Comments: comments may be the diagnostic anchor when they are the first real module line.
- Strings: BSL strings do not affect XML naming.
- Preprocessor: not a separate semantic target for this rule.
- Multiline: XML formatting may be multiline; tag extraction is fixed-tag based.
- Nested constructs: BSL procedures/functions do not affect this rule.
- BSL/SDBL variants, if relevant: SDBL is not relevant.
