- Rule status: verified

## Standard And Product Decision

- Standard or product policy: code must not assign to an identifier that names a common module metadata object.
- Why this diagnostic exists: common module names are globally visible identifiers; assignment to such a name is almost certainly a naming conflict or invalid intent.
- Non-goals: assignments to ordinary local/module variables, calls or property access without assignment, metadata kinds other than `CommonModule`, and runs without a metadata/symbol index.
- Keep/drop decision: keep as a metadata-indexed BSLLS-compatible name-conflict diagnostic.

## Semantic Oracle

- Checked language fact: the left side of a simple assignment is an identifier that resolves to a metadata object of kind `CommonModule`.
- Must diagnose when: metadata is available, `symbol_index.find_meta_object(name)` resolves the simple assignment left-hand identifier, and the resolved object kind is `CommonModule`.
- Must not diagnose when: metadata is unavailable, the left-hand side is not a simple identifier assignment, the identifier is not known metadata, or the resolved metadata kind is not `CommonModule`.
- Diagnostic anchor token/range: the assigned identifier on the left side of `=`.
- Quick-fix target, if any: rename the variable/local symbol.

## CST Or Domain Fact Model

- Parser/tree source: current line-domain simple assignment detection plus metadata symbol index lookup.
- CST/domain object types: assignment line, left-hand identifier, `SymbolIndex` metadata object.
- Extracted attributes: line, identifier range, identifier text, metadata availability, metadata kind.
- Parse-error behavior: malformed assignment lines do not match; `BSL001` owns syntax errors.
- Textual/regex behavior, only if genuinely textual: current simple-assignment extraction is line-regex based; semantic confirmation is metadata-index based.

## Examples

### Invalid Examples

1. `МойОбщийМодуль = 1;` when `МойОбщийМодуль` is a common module.
2. `CommonUtilities = Неопределено;` when `CommonUtilities` is a common module.
3. Assignment at module level or inside a method to a known common-module name.

### Valid Negative Twins

1. `МойОбщийМодуль.Выполнить();` because this is a call/property access, not assignment to the module name.
2. `ЛокальнаяПеременная = 1;` when the identifier is not metadata.
3. `МойОбщийМодуль = 1;` in a run without metadata index, because the rule cannot prove the metadata conflict.

### Edge Examples

- Comments: commented assignments are ignored.
- Strings: strings do not create assignment facts.
- Preprocessor: not a separate semantic target for this rule.
- Multiline: only simple same-line assignments are currently modeled.
- Nested constructs: method/module location does not affect the semantic decision.
- BSL/SDBL variants, if relevant: SDBL is not relevant.
