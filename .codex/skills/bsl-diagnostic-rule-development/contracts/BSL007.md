# BSL007 UnusedLocalVariable Contract

## Rule Identity

- Code: BSL007
- BSLLS compatible name: UnusedLocalVariable
- Public name/i18n key: UnusedLocalVariable / BSL007
- Default message/i18n key: RULE_MESSAGES_RU["BSL007"]
- Description/i18n key: RULE_METADATA["BSL007"].description
- Severity: WARNING
- Parameters/defaults: none.
- Rule status: parity-classified

## Standard And Product Decision

- Standard or product policy: program modules should not contain unused variables.
- Why this diagnostic exists: unused variables are dead code and make maintenance harder.
- Non-goals: do not report parameters; BSL062 owns unused parameters. Do not report exported variables.
- Keep/drop decision: keep as a BSLLS-compatible dead-code diagnostic.

## Semantic Oracle

- Checked language fact: a non-exported module, local, or dynamic variable symbol has no reference occurrence.
- Must diagnose when: a `Перем` module/local variable, loop variable, or dynamic local variable has no read/reference occurrence in its scope.
- Must not diagnose when: a symbol has at least one read/reference occurrence, is exported, is a parameter, or is a form/split-module state assignment that BSLLS does not model as a local variable symbol.
- Diagnostic anchor token/range: the variable symbol selection range, mapped to onec diagnostic coordinates.
- Quick-fix target, if any: remove the unused variable declaration or unused assignment.

## CST Or Domain Fact Model

- Parser/tree source: module procedure/domain model and masked source lines; longer-term target is CST/reference-symbol facts.
- CST/domain object types: `ProcInfo`, module-level `Перем` declarations, local `Перем` declarations, loop headers, implicit dynamic assignment sites, line read-name facts.
- Extracted attributes: variable name, variable kind, declaration/assignment line and character range, exported flag, containing procedure/module scope, and read/reference count.
- Parse-error behavior: skip uncertain procedure containment when the procedure model is unavailable; BSL001 owns syntax errors.
- Textual/regex behavior, only if genuinely textual: current implementation uses line/domain facts for declaration and reference approximation; valid CST/reference facts should replace regex when available.

## Examples

### Invalid Examples

1. `Перем НеИспользуется;` inside a procedure with no reads.
2. Module-level `Перем Кэш;` with no reads anywhere in the module.
3. `Для Индекс = 1 По 3 Цикл ...` where `Индекс` is never read.

### Valid Negative Twins

1. `Перем Значение; Значение = 1; Сообщить(Значение);`.
2. `Перем Экспортируемая Экспорт;`.
3. Assignment to a form/split-module state field used as external module state rather than a local variable symbol.

### Edge Examples

- Comments: mentions in comments do not count as reads.
- Strings: names in ordinary strings do not count as reads, except dynamic `Выполнить` receiver construction compatibility.
- Preprocessor: preprocessor directives do not create variable symbols.
- Multiline: multiline `Перем` declarations report each unused declared name.
- Nested constructs: loop variables and implicit locals are checked in their containing procedure scope.
- BSL/SDBL variants, if relevant: not relevant.

## Implementation Decision

- Change target: `validate_bsl007_unused_local_variable` in `module_model.py`, BSL007 contract, audit state, and targeted tests.
- Delta category fixed by this change: missing module-level declaration diagnostics and over-broad implicit assignment diagnostics in form/split handler modules.
- Why not another layer: BSL007 already owns the local/module variable approximation; this iteration should extend the existing domain pass instead of adding a new reference index.
- Rollback signal: module-level unused `Перем` declarations remain missed, used module variables report, form/split handler state assignments report as locals, or BSL062/BSL219 behavior regresses.
